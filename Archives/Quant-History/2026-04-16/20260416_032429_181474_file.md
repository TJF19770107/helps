# HERMES Dev Refactor Rule

## 1. 方法论

- `1`：明确目标与最终验收。
- `拆解`：把复杂需求拆成更小、可验证的模块。
- `0`：清空错误假设，只保留事实、输入、输出与约束。
- `重构`：按模块修复实现、接口、日志、回执与容错。
- `1`：重新收敛为单一可交付结果，并完成验证。

## 2. 执行规范

- 先证据，后结论。
- 先局部验证，后全量执行。
- 先落日志，后宣称完成。
- 先环境变量，后运行依赖。
- 失败时必须给出可复现原因与下一步修复入口。

## 3. 交付标准

- 本地知识库存在可检索规范文档。
- 至少形成规范、工作流、开发规则三类文档。
- 同步日志完整记录状态、时间、摘要与异常。
