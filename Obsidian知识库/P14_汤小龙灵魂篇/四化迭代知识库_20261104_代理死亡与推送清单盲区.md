### 1.2 git 校验的标准姿势（三个 `-c` 缺一不可）

```bash
git -c http.proxy= -c credential.helper=store push origin main
git -c http.proxy= -c credential.helper=store ls-remote origin refs/heads/main
```

- `-c http.proxy=` —— 关代理走直连（本机代理已死）
- `-c credential.helper=store` —— **ls-remote 和 push 都需要**，别以为只有 push 要
- 判据只认 **sha 逐字相等 + ahead=0**，不认退出码

### 1.3 推送器的「今日文件必须在清单里」前置检查

**「只追加」和「可重渲染」是两件事，共用一个 BODY 源即可。**

## 四 · 智能化（本轮的认知增量）

### 4.1 「返回空」有四种含义，我原来只知道一种

`git ls-remote` 输出空时可能是：
1. 远端真的没这个 ref（我以为的唯一解释）
2. **认证失败 rc=128**（本轮踩的）
3. 通道不通 rc=128
4. 命令被吞（管道 + 2>/dev/null 把 stderr 吃掉）

→ **先看 rc，再看输出。** `2>/dev/null` 这个「清爽」的习惯，正是把 2/3 两种情况伪装成 1 的元凶。

### 4.2 「脚本跑完没报错」是 L3，不是 L4

推送器第一次跑：24 条「跳过」、结论「0/0 篇」、退出码 0 —— 看着完美。
**L4 真相：节点数 203 → 203，今日日报压根没进队列。**
→ 判断「有没有漏推」要问：**「今日文件名出现在结果里了吗」**，而不是「脚本报错了吗」。

### 4.3 版本从 0 变 1，要说清是哪一侧的进化

同一轮里：
- 03:00:39 tick → 进化为 0（工作区干净、覆盖达标 = 巡检正常）
- 03:06:25 tick → 进化为 1，+0.0.1（`_tools` 新增 2 个脚本，命中白名单第 5 类）

**这是判据活着的最好证据**（同逻辑、输入变、结论变）。
但必须写清：**本轮进化的是工程侧脚手架，不是灵魂认知。** 混为一谈就是新一轮粉饰。
