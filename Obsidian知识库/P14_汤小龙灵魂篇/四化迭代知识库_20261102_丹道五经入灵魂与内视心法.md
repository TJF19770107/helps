## 一 · 标准化（把"读懂"变成可核验的口径）

### 1.1 三层分离：原文 / 解读 / 心法，不许混

| 层 | 内容 | 硬规矩 |
|---|---|---|
| **原文层** `01_原典/` | 只有原文 + 校勘异文 | 一字不改；异文单列附录；不做翻译 |
| **解读层** `02_义理解读/` | 逐本义理解读 | **凡引原文必标出处**；凡属推断必写"推论/我的判断"；历代分歧**全部列出或明标所采何说** |
| **心法层** `03_串联与心法/` | 串联逻辑 + 心法拆解 | 只给**判据**，不给**功法**；每条心法必须落到至少一本经的原句 |

→ 这三层分离的直接好处：**任何一句话都能被追问"这是原文还是你说的"。**

### 1.2 "读懂"的可核验判据（不是自我感觉）

| 判据 | 反例 |
|---|---|
| 能指出这句在哪本哪章 | "黄庭经说过……"（说不清哪章）= 没读 |
| 能说出历代有几种解法 | "黄庭就是中丹田"（只有一说）= 读了二手 |
| 能分清哪是原文、哪是后人附会 | 把"斩三尸"当黄庭经原文 = 混淆 |
| 能说出这本书**不能**回答什么 | 拿丹经回答"怎么治病" = 越界 |

### 1.3 风险口径前置

所有解读文件末尾必须有"争议与不确定"一节，且 `04_风险与边界/` 是**最高优先级**文件（在总索引里排"若只读一篇读这个"）。

## 三 · 自动化（一条命令跑完一段）

```bash
# 探测页面（改书单时先跑）
python _tools/probe_dandao_pages.py

# 抓取（已存在则跳过；--force 全量重抓；--check 只核验）
python _tools/fetch_dandao.py

# 复现校验
python _tools/fetch_dandao.py --check
```

**自动化内含的三重判据**（三条全过才算成功）：

| # | 判据 | 防什么 |
|---|---|---|
| A | pageid / revid 全部拿得到 | 防抓到缓存页/重定向页 |
| B | 清洗后汉字数 ≥ 阈值 | 防目录页/消歧义页冒充全文 |
| C | **结构断言**（36 章 / 24 章 / 3 卷） | 防"字数够了但缺一整章" |

→ 判据 C 是这轮补上的。**只靠字数（B）过不了"缺章"这种失败**——缺 24 章里的一章，字数照样过阈值。

## 五 · 踩到的真坑（五个，全部当场证伪过）

### 坑 1 · `{{參|正文|异文}}` 的第一参数就是正文，被通用清洗器整块删掉

- 现象：外景经 raw 3,025 汉字 → 清洗后 **1,177**。
- **最危险处：剩下的句子读起来通顺**（"黃庭中人衣朱衣，。幽闕之高巍巍"），不逐句比对发现不了。
- 真因：`clean_wikitext()` 的 `re.sub(r"\{\{[^{}]*\}\}", "", t)` 把带正文的校勘模板当元数据删了。
- 修法：新增 `expand_templates()`，清洗前展开，正文留、异文另存附录（123 条）。
- 判据：展开前后字数必须变（1,177 → 1,477）。
- **铁律级**：`{{...}}` 未必是元数据，**模板也可能是正文的容器**。任何"删模板"的清洗都必须先看模板是什么。

### 坑 2 · 标题被"列表项规则"二次吃掉

- 现象：`=== 第一章 ===` 先转成 `### 第一章`，再被 `^[ \t]*#[ \t]* → "1. "` 吃成 `1. ## 第一章`。
- 后果：按标题切分全部落空，**结构断言实得 0**（正是这条断言抓出来的）。
- 修法：`prep()` 里修回 `^\d+\.\s+(#{1,6})\s*`。
- **不动通用清洗器**：它已通过八部经典 8/8，改它 = 破坏历史可比性。
- 普适：**两条正则的顺序会互相破坏**。"先转标题、再处理行首#" 这个组合，必然二次误伤。

### 坑 3 · 字数阈值定错方向（把异文当正文）

- 现象：外景经报"字数不足 2,000（实得 1,477）"。
- 误判方向：以为数据缺。
- 真因：**我把 3,025（含 123 条异文的 1,300 字）当成了正文量**；正文本身只有 1,477。
- 修法：阈值按正文实量定 1,200 + 结构断言（24 章 / 3 卷 / 卷数）。
- 普适：**"数字不够"先问"我的阈值是从哪来的"，再问"数据是不是真缺"。**

### 坑 4 · 渲染通道与 wikitext 通道是两条分叉，噪声只在一侧清

- 现象：阴符经（走 `action=parse` 渲染）尾部拖着「此作品在全世界都属于公有领域」+ 行内 `[编辑]`；其他 4 本干净。
- 真因：`clean_noise()` 只接在 `prep()`（wikitext 分支）里，渲染分支直接 `strip_nav(clean_rendered(...))`，绕过了它。
- 修法：渲染分支改成 `clean_noise(strip_nav(...))`。
- 普适：**加了一层清洗，要把所有数据通道都过一遍**。只改主通道 = 留下分叉里的脏东西。

### 坑 5 · bash heredoc 里的 `\n` 被当真换行写进源码（一天内第二次）

- 现象：用 `python - <<'PY'` 改 `fetch_dandao.py`，写进去的 `"\n"` 变成字面换行 → `SyntaxError: unterminated string literal`。
- 这已是本机老铁律（2026-10-26 记过一次：改文件一律写独立 `.py`），**本轮又犯**。
- 修法：改用编辑工具（Read + Edit）直接改，不经 bash。
- **铁律（再次确认）**：**改代码文件不用 heredoc，不用 `python -c`，只用编辑器工具或独立脚本。**
- 附带观察：这坑不像别的坑——别的坑你不懂才踩，**这个坑你懂也会踩**，因为它是工具层的（shell 转义）。→ 所以对策不能是"记住"，必须是"换工具"。
