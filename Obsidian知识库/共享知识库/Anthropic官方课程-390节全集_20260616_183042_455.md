## Claude Code 子代理架构详解

### 子代理核心概念

子代理（Subagents）是 Claude Code 中处理特定任务类型的专用 AI 助手。每个子代理运行在独立的上下文窗口中，拥有自定义 system prompt、特定工具访问权限和独立权限模式。

**关键特性**：
- 独立上下文窗口：避免探索性结果污染主会话
- 自定义权限边界：限制子代理可使用的工具
- 跨项目复用：用户级子代理在所有项目中可用
- 模型路由：可将低成本任务路由到 Haiku 等快速模型

### 内置子代理

| 子代理 | 模型 | 工具 | 用途 |
|--------|------|------|------|
| **Explore** | Haiku | 只读 | 快速代码库搜索和分析，支持三种深度级别（quick/medium/very thorough） |
| **Plan** | 继承主会话 | 只读 | Plan Mode 下的代码库研究 |
| **General-purpose** | 继承主会话 | 全部工具 | 复杂多步骤任务，需要探索+修改 |
| **statusline-setup** | Sonnet | — | 状态栏配置 |
| **claude-code-guide** | Haiku | — | Claude Code 功能问答 |

### 子代理作用域与优先级

| 位置 | 作用域 | 优先级 |
|------|--------|--------|
| Managed Settings | 组织级 | 1（最高） |
| `--agents` CLI Flag | 当前会话 | 2 |
| `.claude/agents/` | 当前项目 | 3 |
| `~/.claude/agents/` | 所有项目 | 4 |
| Plugin `agents/` 目录 | Plugin 作用域 | 5（最低） |

### 子代理配置示例

```markdown
---
name: code-reviewer
description: Expert code reviewer. Use proactively after code changes.
model: sonnet
tools:
  - Read
  - Grep
  - Glob
permissionMode: acceptEdits
---

You are a senior code reviewer. Focus on:
1. Code quality and readability
2. Security vulnerabilities
3. Performance issues
4. Best practices compliance

For each issue found:
- Show the current code snippet
- Explain why it's problematic
- Provide an improved version
```

### 子代理与 Agent Teams / Background Agents 的区别

| 特性 | 子代理 | 后台代理 | Agent Teams |
|------|--------|----------|-------------|
| 会话关系 | 同一会话内 | 独立会话并行 | 多会话协作 |
| 通信方式 | 父会话委派 | 单向监控 | 对等通信 |
| 任务共享 | 无 | 无 | 共享任务列表 |
| 适用场景 | 旁路任务 | 长时间并行 | 跨层功能开发 |

## Agent SDK 编程接口参考

### Python SDK 安装

```bash
pip install claude-agent-sdk
```

### query() vs ClaudeSDKClient 选型

| 特性 | `query()` | `ClaudeSDKClient` |
|------|-----------|-------------------|
| 会话 | 默认每次新建 | 复用同一会话 |
| 对话 | 单次交换 | 同一上下文多次交换 |
| 连接 | 自动管理 | 手动控制 |
| Streaming Input | ✅ | ✅ |
| 中断 | ❌ | ✅ |
| Hooks | ✅ | ✅ |
| Custom Tools | ✅ | ✅ |
| 继续对话 | `continue_conversation=True` 或 `resume` | 自动 |
| 场景 | 一次性任务 | 持续对话 |

### query() 基础用法

```python
import asyncio
from claude_agent_sdk import query, ClaudeAgentOptions

async def main():
    options = ClaudeAgentOptions(
        system_prompt="You are an expert Python developer",
        permission_mode="acceptEdits",
        cwd="/home/user/project",
    )
    async for message in query(prompt="Create a Python web server", options=options):
        print(message)

asyncio.run(main())
```

### ClaudeSDKClient 持续对话

```python
from claude_agent_sdk import ClaudeSDKClient, ClaudeAgentOptions

async def main():
    async with ClaudeSDKClient(options=ClaudeAgentOptions(
        system_prompt="You are a helpful assistant",
        permission_mode="acceptEdits",
        cwd="/path/to/project",
    )) as client:
        # 第一轮
        async for msg in client.query("Create a hello.py script"):
            print(msg)
        
        # 第二轮：继承上下文
        async for msg in client.query("Now add a command-line argument for the name"):
            print(msg)
```

### 自定义 MCP Tool

```python
from claude_agent_sdk import tool, ToolAnnotations

@tool("greet", "Greet a user", {"name": str})
async def greet(args):
    return {"content": [{"type": "text", "text": f"Hello, {args['name']}!"}]}
```

### Tool Annotations 元数据

| 字段 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `title` | str\|None | None | 工具标题 |
| `readOnlyHint` | bool\|None | False | 是否只读 |
| `destructiveHint` | bool\|None | True | 是否可能有破坏性 |
| `idempotentHint` | bool\|None | False | 是否幂等 |
| `openWorldHint` | bool\|None | True | 是否与外部实体交互 |

### 会话管理

```python
from claude_agent_sdk import list_sessions, get_session_messages, get_session_info

# 列出最近10个会话
for session in list_sessions(directory="/path/to/project", limit=10):
    print(f"{session.summary} ({session.session_id})")

# 获取会话消息
messages = get_session_messages(session_id="xxx", directory="/path/to/project")
for msg in messages:
    print(f"[{msg.type}] {msg.uuid}")
```

## Dynamic Workflows 大规模编排

> **版本要求**: Claude Code v2.1.154+ | 状态：Research Preview（2026年5月28日发布）
> **可用范围**: 所有付费计划、Anthropic API、Amazon Bedrock、Google Cloud Vertex AI、Microsoft Foundry

### 什么是 Dynamic Workflows

Dynamic Workflows 是 Claude Code 的多 Agent 编排能力。Claude 将任务描述转化为 JavaScript 脚本，runtime 在后台执行——脚本负责拆阶段、派 agents、收集中间结果、做验证和汇总。

**核心边界**：workflow 脚本本身**不直接访问文件系统或执行 Shell**。真正读文件、改文件、执行命令、调用 MCP 的都是 subagents。脚本是调度器，agent 是 worker。

### 与 Subagents / Skills / Agent Teams 的对比

| 维度 | Subagents | Skills | Agent Teams | Workflows |
|------|-----------|--------|-------------|-----------|
| 本质 | Claude 派生的 Worker | Claude 遵循的指令 | 主导会话监督对等会话 | Runtime 执行的脚本 |
| 决策者 | Claude 逐轮决定 | Claude 遵循 prompt | Lead Agent 逐轮决定 | 脚本决定 |
| 中间结果存储 | Claude 上下文窗口 | Claude 上下文窗口 | 共享任务列表 | 脚本变量 |
| 可复用性 | Worker 定义 | 指令 | 团队定义 | 编排本身 |
| 规模 | 每轮几个委派任务 | 同 subagents | 少数长期对等会话 | 数十到上百 agents |
| 可恢复性 | 重启该轮 | 重启该轮 | 队友继续运行 | 同一会话内可恢复 |

### 触发方式

#### 方式一：Prompt 中显式请求

```
Run a workflow to audit every API endpoint under src/routes/ for missing auth checks.
Map endpoints first, assign independent reviewers by route group, then verify each finding
with a second agent before reporting. Do not edit files; return file paths and evidence.
```

#### 方式二：开启 Ultracode

```bash
/effort ultracode
```

Ultracode = xhigh reasoning effort + 自动 workflow 编排。Claude 会自己判断哪些任务值得跑 workflow，一个请求可能拆成几个连续 workflow。

#### 方式三：内置 /deep-research

```bash
/deep-research What changed in the Node.js permission model between v20 and v22?
```

从多个角度搜索资料、交叉验证、生成带引用的报告。

### 运行时管理

```bash
# 列出运行中和已完成的 workflow
/workflows
```

进度视图按键：
- `↑/↓`：选择 phase 或 agent
- `Enter/→`：深入查看详情
- `Esc`：退回上一级
- `p`：暂停/恢复
- `x`：停止选中 agent 或整个 workflow
- `r`：重启选中 agent
- `s`：保存为可复用命令

### 行为限制

| 限制 | 说明 |
|------|------|
| 无中间用户输入 | 只有 agent 权限提示能暂停运行 |
| 脚本不访问文件系统/Shell | 真实操作由 agents 执行 |
| 最大并发 16 个 agents | 低 CPU 机器可能更少 |
| 单次最多 1000 个 agents | 防止无限循环 |

### 权限注意事项

- Workflow 派出的 subagents 总是 **acceptEdits** 模式
- 继承用户 tool allowlist
- 文件编辑自动批准
- Shell/web fetch/MCP 若不在 allowlist 仍需权限

### 实用 Prompt 模板

**审计类**：
```
Run a workflow to audit [scope] for [risk].
Phase 1: map all relevant files and entry points.
Phase 2: assign independent agents by module; each agent must cite exact files and lines.
Phase 3: run verifier agents that try to disprove each finding.
Return only findings that pass verification, with severity, evidence, and recommended fix.
Do not edit files.
```

**迁移类**：
```
Create a workflow to migrate [old API/framework] to [new API/framework] in [scope].
Start with an inventory and risk map. Split implementation by ownership boundary.
Use isolated agents per module. After each batch, run the relevant tests.
Stop and report if the same blocker appears in three modules.
Keep behavior unchanged unless the migration requires otherwise.
```

### 保存复用

保存后 workflows 作为 slash command 使用：

```
.claude/workflows/    # 项目级（进仓库，团队共用）
~/.claude/workflows/  # 个人级（跨项目复用）
```

## 多Agent协作团队实战

### 多Agent核心价值

单 Agent 局限：上下文窗口填满、长项目丢失早期决策、并行任务互相阻塞。

多Agent 解决：**编排 Agent** 负责规划和委派、**编码 Agent** 负责实现和测试、**研究 Agent** 负责网络搜索和总结、**写作 Agent** 负责文档产出。

### CLAUDE.md 编排模板

```markdown
# CLAUDE.md — Orchestrator

## Team structure
- Orchestrator (me): planning, delegation, memory management
- Coder sub-agent: implementation, tests (uses: tdd-guide, code-review)
- Researcher sub-agent: web search, summarization (uses: web-search)
- Writer sub-agent: documentation, blog posts (uses: content-writer)

## Rules
- Read MEMORY.md at start of every session
- Update MEMORY.md before ending every session
- Never implement directly — always delegate to Coder sub-agent
- Parallelise independent tasks with simultaneous Task calls
```

### 推荐的 Skill 组合

| Skill | 角色 | 功能 |
|-------|------|------|
| sequential-thinking | 编排 Agent | 采取行动前强制结构化推理 |
| web-search | 研究 Agent | Brave/Tavily 搜索与结果总结 |
| code-review | 编码 Agent | 结构化 review：安全/性能/可读性 |
| memory-manager | 全部 Agent | 会话边界自动读写 MEMORY.md |
| tdd-guide | 编码 Agent | 红-绿-重构循环执行 |

### 模型选择策略

| 角色 | 推荐模型 | 原因 |
|------|----------|------|
| 编排 Agent | Sonnet 4.5 | 平衡速度和质量 |
| 研究 Agent | Haiku 4.5 | ~10× 更便宜，检索任务足够快 |
| 写作 Agent | Sonnet 4.5 | 需要高质量输出 |
| 架构决策 | Opus 4.5 | 最强推理能力 |

### 实测数据（23次工作流，6个项目）

- 单 Agent 基线：18-25K tokens/任务
- 3 子代理变体：55-80K tokens（约 3× 成本）
- 时间：并行可分解任务约 40% 的墙钟时间完成

### 安全护栏

1. **禁止在 MEMORY.md 或 CLAUDE.md 中存储 API Key**（CLAUDE.md 默认进入 Git）
2. **文件系统访问白名单**：工作目录设为项目根目录而非 `~`
3. **破坏性操作确认**：rm、DROP TABLE、force-push 前必须暂停确认
4. **Token 预算上限**：每次 Task 调用设置 `--max-tokens`
5. **全量日志**：监控 Skill 检测异常行为

## Skills / Hooks / MCP 四件套组合

### Skills 核心设计

Skills 是存储在 `~/.claude/skills/` 的 Markdown 文件（SKILL.md），Claude Code 在适当时机自动套用。

**SKILL.md 结构**：
```markdown
---
name: my-skill
description: When to trigger this skill
---

# Skill instructions
...
```

### Skills 与 CLAUDE.md / Hooks / Subagents 的区别

| 机制 | 用途 | 触发方式 |
|------|------|----------|
| CLAUDE.md | 全局会话指令 | 每次会话加载 |
| Skills | 任务特定指令 | 按描述匹配自动触发 |
| Hooks | 事件驱动动作 | 事件触发（如 pre-edit） |
| Subagents | 独立 Worker | 按描述匹配委派 |

### MCP 三大核心 Primitive

| Primitive | 类型 | 说明 |
|-----------|------|------|
| **Tools** | 模型控制的动作 | 查数据库、发 API 请求 |
| **Resources** | 应用控制的唯读数据 | 配置文件 |
| **Prompts** | 预定义指令组合 | 「review 这段 code」 |

### MCP Transport 选型

| Transport | 适用场景 |
|-----------|----------|
| stdio | 本机通信 |
| Streamable HTTP | 远程部署 |

## Agent Teams 协作模式

### 与 Subagents 的核心差异

Agent Teams 支持**多个 Claude Code session 协作**，拥有共享任务列表，队友之间能互相发消息。适合：

- 跨层功能开发（前后端并行）
- 不同假设并行调试
- 需要队友间持续通信的复杂任务

### 架构对比总结

```
Subagents     → 旁路任务（单会话内委派）
Skills        → 固定流程+能力注入
Agent Teams   → 多会话协作+共享任务列表
Workflows     → 大规模编排（fan-out/复核/聚合/恢复/复用）
```

## 最佳实践与设计原则

### AI Agent 设计原则

1. **上下文隔离优先**：探索性任务（搜索、日志扫描）应委派给子代理，防止污染主会话上下文
2. **模型分层路由**：编排用 Sonnet，搜索用 Haiku，架构用 Opus
3. **权限最小化**：子代理只授予完成任务所需的最小工具集
4. **结果导向委派**：每个子代理返回摘要而非全量数据
5. **并行化独立任务**：无数据依赖的任务同时派发
6. **工作流脚本化**：重复性复杂流程沉淀为 workflow 脚本
7. **记忆外置**：跨会话状态存入 MEMORY.md，不在 system prompt 中硬编码
8. **逐阶段确认**：破坏性操作分阶段执行，每阶段确认后再继续

### 子代理管理最佳实践

- **命名规范**：使用动词描述子代理职责（code-reviewer、dependency-scanner、test-generator）
- **描述精准**：清晰描述触发条件，Claude 据此决定何时委派
- **工具白名单**：明确列出允许的工具，禁止使用通配符
- **模型指定**：根据任务复杂度选择合适的模型
- **持久记忆**：为高频使用的子代理启用在 `~/.claude/agent-memory/` 的持久记忆

### 成本优化策略

1. 缓存重复上下文（项目栈、编码规范）在 CLAUDE.md
2. 研究/搜索任务用 Haiku
3. 设置子代理上下文长度上限
4. 大任务先在小范围内试跑
5. 定期检查 `/model` 确认未意外使用贵模型

### 多Agent自动化协作流程

```
用户需求
  ↓
编排 Agent 分析并拆解任务
  ↓
并行派发 → 研究 Agent（搜索资料）
         → 编码 Agent（实现功能）
         → 审查 Agent（检查质量）
  ↓
编排 Agent 汇总结果并更新 MEMORY.md
  ↓
最终产出交付用户
```
