## 三、关键技术点提炼

### 3.1 MCP 协议（Model Context Protocol）

MCP 是 Codex 与飞书之间的标准化通信桥梁。飞书官方提供 MCP Server 实现，将飞书开放平台 API 封装为 MCP 工具接口，使 Codex Agent 可以直接调用。

**核心优势**：
- 零代码集成：安装即用，无需手动编写 API 调用代码
- 标准化接口：飞书 MCP Server 遵循 MCP 规范，与 Codex 原生兼容
- 工具发现：Codex Agent 可自动发现飞书 MCP Server 提供的工具列表

### 3.2 飞书 SDK 集成

除了 MCP Server 方式外，也可通过 Python SDK (`lark-oapi`) 直接调用飞书 API。适用于需要自定义复杂逻辑的场景。

**SDK vs MCP 选型**：

| 场景 | 推荐方式 | 原因 |
|------|:---:|------|
| 标准对话操作 | MCP Server | 零代码、自动工具发现 |
| 复杂自定义逻辑 | Python SDK | 灵活性强、完整API覆盖 |
| 混合场景 | MCP + SDK | MCP做路由，SDK做深度操作 |
| Web兜底 | Playwright MCP | 飞书 Web 界面自动化 |

### 3.3 Codex CLI 集成模式

| 模式 | 适用场景 | 命令 |
|------|------|------|
| 对话模式 | 探索/测试 | `codex chat` |
| 单次执行 | 脚本化/CI | `codex exec` |
| 持久Agent | 持续监控/定时任务 | `codex agent` |
| 多Agent并行 | 批量操作 | `codex agent --parallel N` |

## 七、可复用SOP模板

### 7.1 Codex Agent 飞书自动化模板

```bash
# 模板结构
codex agent \
  --task "<飞书自动化任务描述>" \
  --workspace "E:/龙虾AI主控中心/工作区/飞书自动化" \
  --allowed-tools "mcp:feishu,mcp:feishu-docs,mcp:feishu-bitbase,shell,file_rw" \
  --timeout 1800 \
  --model opus

# 替换 <飞书自动化任务描述> 为具体需求
# 示例："读取飞书Base表XX，筛选条件为YY的行，汇总后创建飞书文档并发送到ZZ群"
```

### 7.2 mcp.json 最小配置模板

```json
{
  "mcpServers": {
    "feishu": {
      "command": "npx",
      "args": ["-y", "@larksuite/lark-mcp-server"],
      "env": {
        "FEISHU_APP_ID": "${FEISHU_APP_ID}",
        "FEISHU_APP_SECRET": "${FEISHU_APP_SECRET}"
      }
    }
  }
}
```
