## 一、文章核心思想

### 核心理念：Codex 从"会写代码"走向"能处理工作"

本文的核心论点不是 Codex 技术本身有多强，而是 **Codex 终于开始接入真实工作流**。通过飞书 CLI 这一桥梁，AI 不再只是代码生成器或对话机器人，而是可以直接操作企业协作工具的**任务执行者**。

**关键转变**：

```
之前：AI 回答你 → 你手动去飞书操作
现在：AI 替你操作飞书 → 你只需确认结果
```

**核心价值公式**：

> Codex + 飞书 CLI = 对话式企业自动化

## 二、关键技术点拆解

### 2.1 飞书开放平台

| 技术组件 | 作用 | 关键概念 |
|----------|------|----------|
| 飞书开放平台（open.feishu.cn） | 应用创建与管理的 Web 控制台 | 应用凭证、权限范围（scope）、OAuth 授权 |
| App ID / App Secret | 应用身份认证凭证 | 飞书 API 调用的必备参数，需安全保管 |
| OAuth 2.0 授权 | 用户授权流程 | 获取 Access Token 以代表用户操作飞书资源 |
| 权限 Scope | 精细化权限控制 | 日历/文档/Base/消息等不同资源的读写权限 |

### 2.2 CLI 自动化架构

```
┌─────────────┐     对话交互      ┌──────────────┐     API调用      ┌─────────────┐
│   Codex     │ ◄──────────────► │  飞书 CLI     │ ◄─────────────► │  飞书服务端   │
│  (AI对话层)  │                  │  (命令执行层)  │                 │  (业务层)    │
└─────────────┘                  └──────────────┘                 └─────────────┘
```

**三层架构说明**：

1. **AI 对话层（Codex）**：接收自然语言指令，翻译为 CLI 命令，处理返回结果
2. **命令执行层（飞书 CLI）**：封装飞书 API 调用，管理认证和配置
3. **业务层（飞书服务端）**：实际执行日历/文档/Base/消息等业务操作

### 2.3 API 集成关键路径

| 步骤 | 操作 | 输出 |
|------|------|------|
| Step 1 | 安装飞书 CLI | 可执行命令行工具 |
| Step 2 | 创建飞书应用 + 配置凭证 | App ID + App Secret |
| Step 3 | OAuth 用户授权 | Access Token |
| Step 4 | 验证 API 调用 | 确认权限链路畅通 |

## 三、可复用场景总结

### 3.1 按飞书能力分类

| 飞书能力 | 自动化场景 | 典型应用 |
|----------|-----------|----------|
| **日历** | 智能排会、日程自动创建/查询 | "帮我创建下周一的项目评审会" |
| **文档** | 自动生成周报/日报/会议纪要 | "把今日站会内容整理成飞书文档" |
| **Base（多维表格）** | 客户管理、任务追踪、数据录入 | "把这份 Excel 导入飞书 Base" |
| **消息** | 自动通知、定时提醒、群消息推送 | "每天早上 9 点推送今日待办" |
| **知识库** | 知识自动归档和整理 | "把项目文档归类到对应知识库" |
| **会议** | 预约视频会议、获取会议纪要 | "创建项目评审会议并邀请相关人" |
| **邮箱** | 邮件自动发送/归档 | "给客户发送周报邮件" |

### 3.2 按业务场景分类

**场景一：企业自动化**

- 每日晨会 → AI 自动生成会议文档 + 发送群通知
- 项目里程碑 → AI 创建里程碑文档 + 关联日历事件
- 客户跟进 → AI 记录沟通要点到 Base + 创建跟进任务

**场景二：日程管理**

- 智能排会：AI 查团队空闲时间自动安排会议
- 日程冲突检测：AI 自动跳过已有日程的事件
- 周期性提醒：每周/每月自动创建固定日程

**场景三：文档协作**

- 文档模板自动填充：AI 按模板生成标准化文档
- 多人协作文档校对：AI 检查格式和内容一致性
- 文档版本归档：AI 定期归档过期文档到知识库

## 四、操作 Checklist

### 4.1 首次接入 Checklist

- [ ] **环境检查**：确认 Codex CLI 已安装且正常运行
- [ ] **Node.js 环境**：确认 Node.js ≥ 16（如需）
- [ ] **飞书账号**：确认具备飞书开放平台应用创建权限
- [ ] **安装飞书 CLI**：`npm install -g feishu-cli`
- [ ] **初始化配置**：`feishu config init`
- [ ] **创建飞书应用**：在 open.feishu.cn 创建应用
- [ ] **配置凭证**：设置 App ID 和 App Secret
- [ ] **配置权限**：在应用管理页添加所需 scope
- [ ] **OAuth 授权**：`feishu auth login` 完成授权
- [ ] **验证测试**：执行日历创建等低风险命令验证
- [ ] **安全加固**：配置 IP 白名单、审计日志

### 4.2 日常使用 Checklist

- [ ] **检查 Token**：确认未过期，否则重新授权
- [ ] **权限确认**：新功能需求时确认 scope 已添加
- [ ] **限流意识**：批量操作时注意 API 频率限制（100次/秒）
- [ ] **错误处理**：遇到 403 先查权限，遇到 401 先查 Token
- [ ] **结果确认**：高风险操作后手动在飞书中确认结果

### 4.3 故障排查 Checklist

- [ ] 网络 → `ping open.feishu.cn`
- [ ] 凭证 → `feishu config show`
- [ ] 授权 → `feishu auth status`
- [ ] 权限 → 飞书开放平台 → 权限管理
- [ ] 调试 → `feishu --debug <command>`
