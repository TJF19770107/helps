## 三、2026年新增课程深度解析

### 3.1 Introduction to Subagents（子代理入门）

**核心内容（4个模块）**：
- 子代理如何工作：独立上下文窗口、输入输出流动、摘要返回机制
- 创建自定义子代理：使用 /agents 命令、配置 description/system prompt/tool access/model
- 设计高效子代理：4个设计模式 —— 结构化输出格式、障碍报告、工具访问限制、自然停止条件
- 何时使用与何时不用：研究任务、代码审查、需要自定义system prompt的任务 → 适合；专家人设提示、顺序管道、测试运行器 → 不适合

**子代理委派判断标准**：
1. 任务可独立完成，不需要与其他任务实时协调
2. 结果可验证，有明确的质量标准
3. 任务超时风险低，单一子任务不超过15分钟
4. 上下文需求大，主体上下文无法容纳
5. 返回结果精炼为主（摘要/结构化数据），而非完整过程日志

**反模式（避免）**：
- 任务太小（子代理创建开销 > 任务执行时间）
- 过度嵌套（子代理里再创建子代理）
- 失败不处理（Promise.all 错误传播导致全盘丢失）
- 返回原始日志而非精炼摘要

### 3.2 Introduction to Claude Cowork（协同工作入门）

**核心内容**：
- Cowork 是 Claude 直接操作本地文件/文件夹/应用的桌面代理产品
- 任务循环：读取文件 → 执行操作 → 生成输出
- 插件系统：扩展 Claude 的桌面能力
- 文件工作流：自动化重复任务
- 多步骤工作引导：安全可控地完成复杂操作

**限制条件**：
- 需要 Claude 桌面应用（macOS/Windows）
- 需付费计划（Pro/Max/Enterprise）
- 不支持网页版或移动端

### 3.3 AI Capabilities and Limitations（AI能力与局限）

**核心内容**：
- LLM 实际能力：摘要、分类、结构化推理、代码生成
- 操作局限：幻觉、提示依赖、上下文约束
- 企业采纳预期管理
- 首次中立课程，不绑定任何产品

### 3.4 Introduction to Agent Skills（Agent技能入门）

**6节课 / 30分钟视频**：
- Skill 是什么：Markdown 指令文件
- Skill 与 CLAUDE.md、Hooks、Subagents 的区别
- 从零编写 SKILL.md（frontmatter 格式、触发描述）
- 渐进式披露：目录结构控制上下文窗口消耗
- 高级配置：allowed-tools、background scripts
- 团队共享：commit到仓库、plugin分发、企业 managed settings
- 排错指南：触发失败、优先级冲突、运行时错误

## 四、Claude Code AI OS 四大支柱深度解析

### 4.1 思维模型总纲

| 组件 | 角色 | 类比 | 何时使用 |
|------|------|------|---------|
| Skills | 长期记忆和专业知识 | AI的教育 | 始终——这是基础 |
| Hooks | 事件触发的自动反射 | AI的反射 | 质量门控和审计追踪 |
| MCP | 与外部系统的实时连接 | AI的感官 | 需要实时数据时 |
| Subagents | 并行、隔离的Claude会话 | AI的双手 | 大型或独立的任务 |

### 4.2 支柱1：Skills（长期记忆）

**架构设计**：
```
~/.claude/skills/          # 全局安装
├── skill-name/
│   └── SKILL.md           # 含 frontmatter 的 Markdown 文件
```

**frontmatter 示例**：
```yaml
---
name: code-reviewer
description: 审查代码变更、PR或评估代码质量时使用
---
```

**核心机制**：Claude 在会话开始时扫描所有 frontmatter（每个约20-50 token），仅在任务匹配时加载完整内容。50个skills库约增加 ~2,000 token 开销。

### 4.3 支柱2：Hooks（自动反射）

**关键事件**：
- PreToolUse：工具使用前触发（安全检查、审计日志）
- PostToolUse：工具完成后触发（代码检查、类型检查、测试运行）
- SessionStart：新会话开始时触发
- SessionEnd：退出时触发

**配置示例**：
```json
{
  "hooks": {
    "PostToolUse": [{
      "matcher": "Edit",
      "hooks": [{
        "type": "command",
        "command": "cd $CLAUDE_PROJECT_DIR && npx tsc --noEmit 2>&1 | head -20"
      }]
    }]
  }
}
```

### 4.4 支柱3：MCP（实时连接）

**三种核心原语**：
- Tools：模型控制的动作（查数据库、发API请求）
- Resources：应用控制的唯读数据（配置文件）
- Prompts：预定义指令组合

**传输方式**：
- stdio：本机通信
- Streamable HTTP：远程通信

### 4.5 支柱4：Subagents（并行执行）

**创建配置**（`.claude/agents/security-reviewer.md`）：
```yaml
---
name: security-reviewer
description: 审查代码安全漏洞
tools: Read, Grep, Glob, Bash
model: opus
---
```

**关键机制**：
- 独立上下文窗口，不受主对话污染
- 任务完成后仅返回精炼结果
- 可配置专属 skills、工具、模型

## 五、Subagents 三大设计模式（实战代码）

### 5.1 Pattern 1: Map-only（无依赖并行）

```typescript
async function analyzeRepos(repos: string[]): Promise<RepoAnalysis[]> {
  const results = await Promise.all(
    repos.map(url =>
      TaskTool.run({
        description: `分析仓库 ${url}`,
        prompt: `分析 GitHub 仓库 ${url}：提取 stars、最后提交日期、主语言，输出 JSON`,
        subagent_type: 'general-purpose',
      })
    )
  );
  return results.map(r => JSON.parse(r) as RepoAnalysis);
}
```

适用：10+ 个独立任务，每个 5-20 分钟。

### 5.2 Pattern 2: Map-Reduce（并行+汇总）

```typescript
// 第一阶段：并行提取
const partialResults = await Promise.all(
  jdUrls.map(url => TaskTool.run({ ... }))
);

// 第二阶段：主Agent汇总
const finalReport = await Anthropic.messages.create({
  model: 'claude-sonnet-4-6',
  messages: [{ role: 'user', content: `合并 ${partialJSON.length} 份分析为统一报告...` }]
});
```

适用：100+ 子任务，最后需要综合分析。

### 5.3 Pattern 3: Pipeline（多阶段，每阶段并行）

```typescript
// 第一阶段：并行爬取
const rawData = await Promise.allSettled(
  competitors.map(name => TaskTool.run({ ... }))
);

// 第二阶段：并行清洗+对比
const cleaned = await Promise.all(
  successfulRaw.map(d => TaskTool.run({ ... }))
);

// 第三阶段：生成最终报告
const finalReport = await Anthropic.messages.create({ ... });
```

适用：多步骤工作流，每步内部可并行。

### 5.4 三大生产事故与修复

**事故1：来回查同一参考文档10次**
- 原因：每个子代理重复加载完整参考文档
- 修复：先由主Agent一次性提取各子代理所需片段（200 token/段），再分发给各子代理

**事故2：Promise.all 错误传播**
- 原因：一个子代理失败导致所有结果丢失
- 修复：使用 Promise.allSettled + retry queue，失败项60秒后重试

**事故3：子代理开销 > 任务时间**
- 原因：小任务用子代理，创建开销比省的时间多
- 修复：设置阈值（任务<5秒不用子代理），决策公式：并行耗时>串行耗时则不用

## 七、Claude Code 最佳实践精要

### 7.1 给 Claude 验证自己工作的方式
- 提供可运行的检查：测试、构建、屏幕截图
- 每个操作后要求显示证据：测试输出、命令返回、截图对比
- 从"提示内验证"到"Stop hook 确定性门控"逐步升级

### 7.2 先探索，再规划，最后编码
```
Plan Mode 探索 → 制定详细计划 → 切换出Plan Mode实现 → 提交
```

### 7.3 上下文管理黄金法则
- 不相关任务间频繁 /clear 重置上下文
- 用 subagents 做调查，保持主对话干净
- /compact 压缩对话历史，自定义保留关键信息
- /rewind 恢复检查点重新开始

### 7.4 CLAUDE.md 精简原则
- 只写 Claude 无法猜到的、删掉会导致它犯错的内容
- 排除它能从代码中推断的标准约定
- 如果 Claude 持续犯错且规则已写明，说明文件太长被忽略了

### 7.5 多会话并行与扇出
- Writer/Reviewer 模式：两个 Claude 会话分别编写和审查
- 跨文件扇出：循环遍历任务列表，每个文件一个 claude -p 调用
- Auto mode：分类器审查命令，阻止范围升级操作
