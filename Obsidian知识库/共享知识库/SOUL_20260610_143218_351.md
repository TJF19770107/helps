## 一、核心设计哲学

### 1.1 从「工具」到「协作伙伴」

AI Agent 不再是响应提示词的文本生成器，而是拥有「手」和「眼」的数字协作者：
- 自主规划 → 工具执行 → 结果验证 → 反馈修正
- 在复杂的开发/生产工作流中主动介入，而非被动等待指令

### 1.2 Agent 设计黄金法则

```
目标 + 约束 > 步骤
```

不要教 Agent 怎么做，告诉它目标是什么、边界在哪。让 AI 发挥推理能力而非当脚本执行器。

## 二、五大核心原语设计原则

### 2.1 子代理 (Subagents)

| 原则 | 说明 |
|------|------|
| 功能特定化 | 越具体越好，避免通用"QA代理" |
| 上下文隔离 | 独立上下文窗口，不污染主对话 |
| 工具最小化 | 只给必要工具，确保安全边界 |
| 记忆持久化 | 三级记忆（user/project/local）按场景选用 |
| git worktree | 并行开发时隔离分支 |

### 2.2 命令 (Commands)

| 原则 | 说明 |
|------|------|
| 纯用户驱动 | AI 不可自动调用 |
| 团队共享 | 提交到 git，统一入口 |
| 内循环工作流 | 每天 >1 次的操作转为命令 |

### 2.3 技能 (Skills)

| 原则 | 说明 |
|------|------|
| 触发器描述 | "当用户...时使用"，给人看的摘要无价值 |
| 文件夹非文件 | SKILL.md + references/ + scripts/ + examples/ |
| 渐进式披露 | 按需加载子目录，不一次性注入 |
| Gotchas 积累 | 每次失败记录，随时间积累可靠性 |
| context: fork | 隔离运行，主对话只看结果 |
| 不给步骤给约束 | 不给"第一步第二步"，给"目标和约束" |

### 2.4 钩子 (Hooks)

| 原则 | 说明 |
|------|------|
| 确定性保护 | 钩子执行率 100%，指令遵从率仅 20% |
| PostToolUse | 自动格式化/验证 |
| Stop | 推动继续工作 |
| PreToolUse | 拦截破坏性命令 |

### 2.5 记忆 (Memory)

| 原则 | 说明 |
|------|------|
| 长度控制 | CLAUDE.md ≤ 200 行（60 行最优） |
| 确定性配置 | settings.json 替代 CLAUDE.md 中的 Must 指令 |
| `<important if="...">` | 包裹领域特定规则提高遵守率 |
| 延迟加载 | rules/ 目录 paths: frontmatter |

## 三、Multi-Agent 协作原则

### 3.1 协调器模式

```
协调器 (Leader) → 多个专业子代理 (Specialists)
```

- Leader 掌握全局意图，分解任务
- Specialist 在独立上下文执行局部任务
- 共享文件系统 + 独立上下文 = 最大化协同

### 3.2 职责分离

- 代码生成 Agent ≠ 代码审查 Agent
- 测试 Agent ≠ 开发 Agent
- 搜索 Agent ≠ 决策 Agent

不同视角、不同上下文窗口发现互补问题。

### 3.3 并行调度

- 无依赖子任务并行派发
- git worktrees 隔离开发
- Agent Teams 多会话协作

## 四、安全与权限设计

| 层次 | 机制 | 优先级 |
|------|------|--------|
| 组织级 | managed-settings.json | 最高（不可推翻） |
| 钩子级 | /careful + /freeze | 强制拦截 |
| 规则级 | deny > ask > allow | 逐级降权 |
| 智能级 | Auto Mode | 自动安全分类 |
| 隔离级 | 沙箱模式 | 文件+网络隔离 |

## 五、Agent 质量度量

- **技能触发率**：描述字段是否精准匹配用户意图
- **Gotchas 增长曲线**：技能随时间是否更可靠
- **上下文效率**：压缩频次、上下文使用率
- **PR 粒度**：118 行中位数参考
- **自主修复率**：不靠人工指导自行解决 bug 的比例
