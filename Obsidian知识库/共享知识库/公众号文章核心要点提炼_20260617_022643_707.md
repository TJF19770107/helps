## 一、文章核心命题

## 二、核心架构（三层）

```
┌─────────────────────────────────────────────┐
│  L3 交互层：飞书（移动端/桌面端）               │
│  - 发消息触发任务                              │
│  - 实时进度卡片显示                            │

└─────────────────────────────────────────────┘
```

## 三、关键发现与洞察

### 3.1 技术选型亮点

| 亮点 | 说明 |
|------|------|
| **飞书长连接模式** | 无需配置公网回调地址，无需 SSL 证书，降低部署门槛 |
| **本地执行** | 代码不经过云端，保障源码安全 |
| **心跳机制** | 长任务不黑盒，实时反馈"Codex 仍在运行" |
| **会话持久化** | state.json 原子写入，重启后恢复会话 |
| **双模式** | 直连模式（个人用）+ 桥接模式（团队群协作） |

### 3.2 与已有能力的互补

| 现有能力 | 这次补充 | 互补效果 |
|---------|---------|---------|
| 龙虾 AI 分身（桌面端） | 飞书远程调度 Codex | 移动端 + 桌面端全场景覆盖 |
| openclaw 飞书插件（已有） | feishu-codex-bridge | 插件侧重消息通知，bridge 侧重任务执行 |
| 飞书 CLI（npm 包） | Bridge 桥接 | CLI 适合 Agent 直接命令，Bridge 适合人类远程调度 |

## 五、可复用的 SOP 模板

### 5.1 Codex + 飞书接入 SOP

```
Step 1: 环境检查
  ☐ Node.js 18+
  ☐ Codex CLI 已登录
  ☐ 飞书企业应用已创建

Step 2: 飞书应用配置
  ☐ 获取 App ID + App Secret
  ☐ 启用机器人 + 长连接
  ☐ 订阅 im.message.receive_v1
  ☐ 发布版本

Step 3: 部署 Bridge
  ☐ git clone + npm install
  ☐ 配置 .env
  ☐ 启动服务 → 健康检查通过
  ☐ Windows 服务注册（可选）

Step 4: 验证
  ☐ 飞书发送 /status → 返回正常
  ☐ 飞书发送 /run 简单任务 → 正常执行
  ☐ 心跳正常反馈
```

### 5.2 飞书 CLI 安装 SOP

```
Step 1: npm install -g @larksuite/cli
Step 2: npx skills add larksuite/cli -y -g
Step 3: lark-cli auth login（扫码授权）
Step 4: lark-cli --version（验证）
Step 5: lark-cli calendar +agenda（功能验证）
```
