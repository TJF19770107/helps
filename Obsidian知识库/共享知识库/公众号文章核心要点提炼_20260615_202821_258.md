## 一、核心观点提炼

1. **Codex开始接上真实工作流**：Codex不再只是"会写代码的AI"，通过飞书CLI，它可以直接操作文档、Base、日历、消息、任务、邮箱、知识库、会议纪要等真实办公场景。

2. **四步即可打通全链路**：安装飞书CLI → 配置飞书应用 → OAuth授权 → 验证接入，全程只需与Codex对话，无需编写任何代码。

3. **飞书CLI是AI操作飞书的通用中间层**：`@larksuite/cli` 作为飞书官方CLI工具，覆盖11+业务域200+命令，不仅是Codex的桥梁，Claude Code、Cursor、OpenClaw等工具均可复用同一套CLI能力。

4. **从"会写代码"到"能处理工作"的质变**：AI的进化方向不是更强的代码能力，而是接入真实的办公工作流，替代人类完成端到端的任务。

5. **低门槛验证是关键设计**：文章强调先用"创建日历"这种低风险命令验证，通后再扩展——这种渐进式接入策略降低了用户的心理门槛和安全顾虑。

## 二、技能操作摘要

### 四步流程关键点

| 步骤 | 操作 | 关键动作 | 耗时 |
|------|------|---------|:---:|
| 1 | 安装飞书CLI | `npm install -g @larksuite/cli` | 4-5分钟 |
| 2 | 配置飞书应用 | 浏览器打开配置链接 → 创建应用 → 获取App ID/Secret | 5分钟 |
| 3 | OAuth授权 | 浏览器打开授权链接 → 确认权限范围 | 2分钟 |
| 4 | 验证接入 | 创建低风险日历事件，确认链路通畅 | 1分钟 |

### 核心命令速记

| 能力域 | 典型命令 |
|--------|---------|
| 文档 | `lark-cli docs create --title "xx" --content file.md` |
| Base | `lark-cli base record-create --app-token <t> --table-id <id> --data records.json` |
| 日历 | `lark-cli calendar event-create --summary "xx" --start-time "..." --end-time "..."` |
| 消息 | `lark-cli im messages-send --chat-id <cid> --content "xx"` |
| 任务 | `lark-cli task create --summary "xx" --due-date "2026-06-20"` |
| 会议 | `lark-cli vc minutes-get --meeting-id <mid>` |

## 三、学到的方法论

### 核心洞见

> **"AI 不只是回答你，它开始替你完成任务。"**

这句话是全文的点睛之笔。它揭示了AI应用范式的转变方向：从"问答型AI"进化为"执行型AI"。Codex+飞书CLI的组合正是这一转变的典型实践。

### 关键方法论

1. **渐进式接入**：先低风险验证（创建日历），再扩展高风险操作——让用户在安全可控的前提下逐步建立信任。

2. **纯自然语言交互**：全程不需要打开飞书开放平台、不需要写代码、不需要记命令——所有操作通过"和Codex对话"完成，真正实现了自然语言驱动的自动化。

3. **CLI作为通用桥接层**：飞书CLI不仅连接Codex，也连接所有支持Shell执行的AI工具。这体现了"标准化中间层"的架构思维——一次投入，多方复用。

4. **真实工作流 > 炫技Demo**：文章不追求"Codex又多强了"，而是聚焦"Codex终于能干活了"——实用主义导向的产品思维。

## 四、可复用的SOP提炼

### SOP-1：AI+CLI接入新平台的通用模式

```
1. 安装目标平台的CLI工具
2. 配置应用凭据（App ID/Secret）
3. 完成OAuth用户授权
4. 低风险命令验证接入
5. 扩展至全业务域
```

此模式可复用于：钉钉CLI、企业微信CLI、Notion CLI、Slack CLI等任何提供CLI工具的SaaS平台。

### SOP-2：AI自动化任务的渐进式安全策略

| 阶段 | 操作类型 | 风险等级 | 验证方式 |
|------|---------|:---:|---------|
| Phase 1 | 只读查询（查看日程、获取文档） | 🟢 低 | 确认数据正确 |
| Phase 2 | 创建操作（创建文档、创建日历事件） | 🟡 中 | 确认结果可逆 |
| Phase 3 | 批量操作（批量发送消息、批量更新Base） | 🟡 中 | 先 `--dry-run` 预览 |
| Phase 4 | 全自动流水线 | 🔴 需确认 | 完整审计日志 |
