## 一、子代理架构总览

### 1.1 子代理定义
子代理是拥有**独立上下文窗口**的专用AI助手，由主Agent创建和调度，执行隔离任务后仅返回精炼结果。

### 1.2 核心价值
| 价值 | 说明 |
|------|------|
| 上下文隔离 | 每个子代理独立上下文，避免主对话膨胀 |
| 并行执行 | 多个子代理可同时处理不同子任务 |
| 专注高效 | 每个子代理聚焦单一领域，质量更高 |
| 安全边界 | 子代理权限可独立控制，降低风险 |

### 1.3 何时使用子代理
- 任务可拆分为**独立可验证**的子任务
- 子任务执行过程**不需要**与主Agent实时交互
- 结果可**精炼汇总**，不需要完整执行日志
- 任务复杂度**值得**创建子代理的开销

### 1.4 五层能力视角下的子代理定位 (R57 新增)

```
CLAUDE.md → 主Agent + 所有子代理的硬性规则
Skills → 可预加载至子代理的领域知识（需显式声明）
Hooks → 可被子代理继承的确定性执行
MCP → 可被子代理连接的外部工具
```

**关键区别**：与主会话不同，子代理**不会自动按描述匹配加载Skills**。必须通过 `skills` frontmatter字段显式声明需要哪些Skills。

## 二、子代理配置规范

### 2.1 创建子代理 (R57 更新)
```markdown
## 子代理：代码审查专家

### 描述
当用户要求代码审查、PR review、代码质量检查时触发

### 系统提示词
你是一个代码审查专家，专注于：
1. 代码质量和可读性
2. 潜在Bug和安全漏洞
3. 性能优化建议
4. 最佳实践遵循

### 权限
- 读取：当前项目所有文件
- 写入：仅审查报告文件
- 禁止：修改源代码、执行系统命令

### Skills (R57 新增)
skills: [code-review-checklist, security-scan]

### 模型
model: claude-sonnet-4-20250514
```

### 2.2 子代理分类
| 类型 | 特点 | 示例 |
|------|------|------|
| 文件Agent | 文件系统操作 | 搜索、整理、转换 |
| 浏览器Agent | 网页交互 | 表单填写、数据提取 |
| 应用Agent | 应用操作 | 启动、安装、界面交互 |
| 系统Agent | 系统配置 | 设置修改、进程管理 |
| 搜索Agent | 深度搜索 | 学术检索、对比分析 |

### 2.3 子代理与Skills协同 (R57 新增)

**自动触发 vs 显式预加载**：

| 场景 | 主Agent | Subagent |
|------|---------|---------|
| Skill由描述匹配自动加载 | ✅ 自动 | ❌ 不自动 |
| Skill通过frontmatter显式声明 | ✅ 支持 | ✅ 支持 |
| Skill加载后常驻上下文 | ✅ 是 | ✅ 是 |
| token成本 | 计入主会话 | 独立预算 |

**最佳实践**：为每个子代理预加载其专属Skills，避免将不相关的Skills注入。

## 三、Agent SDK 集成 (R57 全新)

### 3.1 SDK 架构

```
Claude Code CLI/IDE
  └─ Agent SDK
       ├─ Agent Loop (消息生命周期)
       ├─ Custom Tools (进程内MCP)
       ├─ Hooks (行为拦截)
       ├─ Checkpointing (文件回滚)
       └─ Cost Tracking (成本追踪)
```

### 3.2 SDK 核心能力

| 模块 | 功能 | 配置 |
|------|------|------|
| agent-loop | 消息处理、工具执行、上下文管理 | SDK默认 |
| claude-code-features | 加载CLAUDE.md、Skills、Hooks | 传入配置路径 |
| custom-tools | 定义进程内MCP工具 | Python/JS函数注册 |
| cost-tracking | Token追踪、成本估算 | 自动记录 |
| file-checkpointing | 文件变更快照与回滚 | 按需启用 |
| hosting | 生产部署 | Docker/Serverless |

### 3.3 子代理SDK化部署

```
1. 在Claude Code中验证子代理行为
2. 使用Agent SDK封装子代理配置
3. 定义Custom Tools（如需要）
4. 配置Hooks（安全guardrail）
5. Managed Settings统一管理
6. 部署至生产环境
```

## 四、Hooks 集成 (R57 新增)

### 4.1 子代理可用的 Hook 事件

| 事件 | 子代理适用性 | 典型用途 |
|------|------------|---------|
| PreToolUse | ✅ 高 | 阻止子代理越权操作 |
| PostToolUse | ✅ 高 | 子代理操作后自动lint |
| SessionStart | ✅ 中 | 子代理启动时注入配置 |
| UserPromptSubmit | ❌ 低 | 子代理通常无用户交互 |

### 4.2 子代理 Hook 配置示例
```json
{
  "subagents": {
    "code-reviewer": {
      "hooks": {
        "PreToolUse": [
          {
            "matcher": "Write|Edit",
            "command": "python check-no-source-edit.py \"$CLAUDE_TOOL_INPUT\""
          }
        ],
        "PostToolUse": [
          {
            "matcher": "Edit",
            "command": "npx eslint --fix \"$CLAUDE_FILE_PATH\""
          }
        ]
      }
    }
  }
}
```

## 五、File Checkpointing (R57 新增)

### 5.1 核心原理
Agent SDK 在每次文件操作前自动创建检查点，支持任意时刻回滚至历史状态。

### 5.2 应用于子代理安全网
- 高风险批量操作前，子代理自动创建检查点
- 操作完成后验证结果，异常时自动回滚
- 避免子代理的批量错误污染主工作区

### 5.3 最佳实践
```
高风险操作 → 创建检查点 → 执行变更 → 验证结果 → 确认/回滚
```

## 六、Managed Settings 组织管理 (R57 新增)

### 6.1 统一管理维度

| 维度 | 控制内容 |
|------|---------|
| 子代理权限 | 工具白名单/黑名单 |
| 模型选择 | 指定子代理使用的模型版本 |
| Skills集合 | 统一管理的Skills库 |
| 安全策略 | Hook规则、操作阻止列表 |
| 成本控制 | Token上限、并发限制 |

### 6.2 Policy Enforcement
- 组织级策略自动注入所有子代理
- 子代理无法绕过组织级安全Hook
- 审计日志记录所有子代理操作
