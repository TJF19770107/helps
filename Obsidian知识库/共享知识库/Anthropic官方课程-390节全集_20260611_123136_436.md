## 二、Claude Code 核心架构：Skills + Hooks + MCP + Subagents

### 2.1 四大支柱思维模型

Claude Code 2026 是一个 AI 操作系统，由四个组件构成：

| 组件 | 角色 | 何时使用 |
|-----|------|---------|
| Skills | Claude 的长期记忆和专业知识（教育） | 始终——这是基础 |
| Hooks | 事件触发自动反射（反射） | 质量门控和审计追踪 |
| MCP | 外部系统实时连接（感官） | 需要实时数据时 |
| Subagents | 并行隔离会话（双手） | 大型或独立任务 |

### 2.2 Skills——长期记忆系统

Skills 是 Markdown 文件，放在 `~/.claude/skills/`（全局）或 `.claude/skills/`（项目级）。

**前端元数据格式：**
```
---
name: code-reviewer
description: Use when reviewing code changes, pull requests...
---
```

**设计精妙之处：** Claude 会话开始时仅扫描 frontmatter（每个 skill 约20-50 token），匹配后才加载完整内容。50个 Skills 仅增加约2000 token 开销。

**推荐起步套装：**
- superpowers（子代理编排）
- skill-creator（构建新技能）
- code-reviewer（PR审查工作流）
- frontend-design（前端设计优化）
- brainstorming（创意设计前需求探索）

### 2.3 Hooks——自动反射机制

Hooks 是事件驱动的自动化触发器，在 `settings.json` 中配置。

**五大 Hook 事件：**

| 事件 | 触发时机 | 典型用途 |
|-----|---------|---------|
| PreToolUse | 工具调用之前 | 安全拦截、参数校验 |
| PostToolUse | 工具调用之后 | 自动 lint/测试/格式化 |
| PostToolUseFailure | 工具调用失败后 | 错误日志、重试机制 |
| Notification | 发送通知时 | 桌面弹窗、音效提醒 |
| Stop | 完成一轮回复后 | 自动保存、完成通知 |

**可用环境变量：**
- `$CLAUDE_TOOL_NAME` - 当前工具名
- `$CLAUDE_FILE_PATHS` - 被操作文件路径
- `$CLAUDE_PROJECT_DIR` - 项目根目录
- `$CLAUDE_TOOL_INPUT` - 工具完整输入（JSON）

**matcher 正则规则速查：**

| 模式 | 含义 | 示例 |
|-----|------|------|
| `""` | 匹配所有工具 | 任何工具都触发 |
| `Write` | 精确工具名 | 仅 Write 触发 |
| `Write\|Edit` | 逻辑OR | 同时匹配两个 |
| `^Bash$` | 精确匹配边界 | 避免 BashScript 误匹配 |

**PreToolUse 退出码2会阻止工具调用，其余退出码不阻断。**

### 2.4 MCP——实时连接协议

MCP（Model Context Protocol）是 AI 连接外部工具的统一标准——即插即用。

**常用 MCP 服务器：**

| 分类 | 服务器 | 包名 | 需要API Key |
|-----|--------|------|------------|
| 文件 | filesystem | @modelcontextprotocol/server-filesystem | ❌ |
| 内存 | memory | @modelcontextprotocol/server-memory | ❌ |
| 数据库 | sqlite | @modelcontextprotocol/server-sqlite | ❌ |
| 数据库 | postgres | @modelcontextprotocol/server-postgres | ❌ |
| 开发 | github | @modelcontextprotocol/server-github | ✅ |
| 开发 | git | @modelcontextprotocol/server-git | ❌ |
| 搜索 | brave-search | @modelcontextprotocol/server-brave-search | ✅ |
| 搜索 | fetch | @modelcontextprotocol/server-fetch | ❌ |
| 知识 | context7 | @upstash/context7-mcp | ❌ |
| 自动化 | puppeteer | @modelcontextprotocol/server-puppeteer | ❌ |

**三大作用域：**

| 作用域 | 存储位置 | 优先级 | 适用 |
|-------|---------|--------|------|
| Local | ~/.claude.json（项目条目） | 最高 | 含API Key |
| Project | 项目根 .mcp.json | 中 | 团队共享 |
| User | ~/.claude.json（全局） | 最低 | 个人通用 |

**选择原则：** 含密钥→Local；团队必需→Project；个人常用→User。

### 2.5 Subagents——并行执行体系

#### Subagent vs Agent Skill 选择

| 对比维度 | Agent Skill | SubAgent |
|---------|-------------|----------|
| 上下文 | 共享主对话上下文 | 完全独立的上下文 |
| 中间过程 | 会进入主对话 | 不回传主对话 |
| Token消耗 | 中间过程消耗主对话token | 独立消耗 |
| 适用场景 | 与上下文关联大、影响小的任务 | 与上下文关联小、影响大的任务 |
| 典型示例 | 写每日总结、格式转换 | 代码审核、大项目搜索分析 |

**决策规则：**
- 🟢 任务简单，结果可融入主对话 → Agent Skill
- 🔵 任务复杂，中间过程会污染主对话 → SubAgent

#### 创建 SubAgent 流程（/agents 交互式）

1. 输入 `/agents` → Create New Agent
2. 选择存放位置：Project (.claude/agents/) 或 Personal (~/.claude/agents/)
3. 选择创建方式：Generate with Claude（推荐）或 Manual
4. 用自然语言描述代理职责
5. 选择工具权限：Read-only / Edit / Bash / MCP
6. 选择模型：Sonnet（日常推荐）/ Opus（复杂架构）/ Haiku（批量处理）
7. 设置颜色标识
8. 配置记忆：Enable（推荐）/ None / Local

## 三、Agent Teams——多 Agent 协作架构（实验性）

### 3.1 Agent Teams vs Subagents

| 维度 | Subagents | Agent Teams |
|-----|-----------|-------------|
| Context | 独立context window；结果返回调用者 | 独立context window；完全独立 |
| 通信 | 仅向主代理报告 | 队友直接相互发送消息 |
| 协调 | 主代理管理所有工作 | 具有自我协调的共享任务列表 |
| 最适合 | 只有结果重要的专注任务 | 需要讨论和协作的复杂工作 |
| Token成本 | 较低 | 较高（每个队友独立Claude实例） |

### 3.2 启用 Agent Teams

```json
{
  "env": {
    "CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS": "1"
  }
}
```

需要 Claude Code v2.1.32+

### 3.3 Agent Teams 最佳场景

1. **并行代码审查：** 生成3个审查者分别关注安全、性能、测试覆盖
2. **竞争假设调试：** 5个队友并行测试不同理论，相互质疑
3. **跨层协调：** 前端、后端、测试各由一个队友负责
4. **新模块开发：** 各自拥有独立文件集，互不干扰

### 3.4 团队架构

| 组件 | 角色 |
|-----|------|
| Team lead | 创建团队、生成队友、协调工作的主会话 |
| Teammates | 各自处理分配任务的独立Claude Code实例 |
| Task list | 队友认领和完成的共享工作项列表 |
| Mailbox | 代理间通信的消息系统 |

### 3.5 Best Practices

1. **给队友足够context：** 生成提示包含特定任务细节（文件路径、技术栈、安全关注点）
2. **适当团队规模：** 3-5个队友最佳；5-6个任务/队友保持生产力
3. **任务大小适中：** 自包含单元，产出清晰可交付成果
4. **从研究和审查开始：** 先做无需写代码的并行任务
5. **避免文件冲突：** 每个队友负责不同文件集
6. **主动监控：** 检查进度，重定向无效方法

### 3.6 已知限制（实验性）

- In-process 队友无会话恢复（/resume和/rewind不恢复）
- 任务状态可能滞后
- 关闭可能缓慢
- 每会话一个团队
- 不支持嵌套团队
- 负责人固定不可转移


## 四、Claude Code 工作流全攻略（10大模块）

### 4.1 环境搭建与认证
- 两种认证：订阅制（Claude Pro/Max）或 API Key

### 4.2 三种交互模式（Shift+Tab 切换）
- **默认模式：** 创建/修改文件前必须询问 → 安全优先
- **自动模式：** 文件操作自动通过 → 效率优先
- **规划模式：** 只讨论不执行 → 架构改造

### 4.3 版本回滚机制
- 连按两次 ESC 快速进入
- 选项：回滚代码和对话 / 仅回滚对话 / 仅回滚代码
- 限制：只能回滚 Claude Code 写入的文件

### 4.4 MCP 多模态开发
- Figma 设计稿精准还原：通过 Figma MCP Server 获取精确数据
- 方法一：直接传图（粗略）

### 4.5 上下文管理
- `/compact`：压缩上下文，保留关键信息
- `/clear`：清空全部上下文
- CLAUDE.md 配置层级：项目级 > 用户级

### 4.6 Hook 实战

### 4.7 Agent Skill 创建

### 4.8 SubAgent 创建

### 4.9 Plugin 生态
