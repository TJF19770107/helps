## 一、文章核心论点

飞书 CLI 是 AI 与飞书之间的"桥梁"——通过 CLI 让 Codex/Claude Code 等 AI Agent 能够直接操作飞书中的一切数据和功能。核心理念：**自然语言 → AI 理解意图 → 飞书 CLI 执行命令 → 飞书 API 调用**。飞书不再是聊天软件，而是多个 Agent 共用的持久数据层——Claude Code 有 memory/skills/hooks，Codex 有 Goals/sandbox/remote SSH，通过飞书 CLI 三者串联，手机端即可操控全部。

## 二、四步接入 SOP（文章重点）

| 步骤 | 操作 | 关键检查 |
|------|------|----------|
| 1 | 安装 CLI：`npm install -g @larksuite/cli` | `lark-cli --version` |
| 2 | 安装 Skills（关键）：`npx skills add larksuite/cli -y -g` | 19个Skills全部安装 |
| 3 | 配置应用 + OAuth 授权：`lark-cli config init --new` → `lark-cli auth login --recommend` | `lark-cli auth status --verify` → verified: true |
| 4 | 重启 AI Agent 工具（不可省略） | 必须完全退出再重启，否则 Skills 不生效 |

## 三、三层命令体系架构（v1.2 新增）

| 层级 | 命令前缀 | 示例 | 说明 |
|------|---------|------|------|
| 快捷命令 | `+` | `lark-cli calendar +agenda` | 人类与AI友好，智能默认值、dry-run预览 |
| API命令 | 模块名 | `lark-cli calendar events instance_view` | 100+精选命令，与飞书OAPI一一对应 |
| 原始API | `api GET/POST` | `lark-cli api GET /open-apis/calendar/v4/calendars` | 直接调用2500+API端点，完全灵活 |

## 七、权限配置要点

- **应用身份**（默认）：发消息、创建文档 — 不需要用户授权
- **用户身份**：访问个人日历/私信/收件箱 — 需额外 OAuth 授权
- 推荐使用 `lark-cli auth login --recommend` 获取常用安全权限集
- 企业账号建议选「测试企业」避开管理员审批
- 重要操作前使用 `--dry-run` 预览
- 输出格式支持：JSON/NDJSON/表格/CSV/美化打印

## 九、常见问题与解决

| 问题 | 解决 |
|------|------|
| Skills 不生效 | 必须完全退出并重启 Agent |
| npm 安装失败 | 使用国内镜像 `--registry=https://registry.npmmirror.com` |
| 应用审批被拒 | 仅选必要权限，不勾 OKR 相关；或使用测试企业 |
| 授权过期 | `lark-cli auth login --recommend` 重新授权 |
| 云盘读不到文件 | 检查 drive 权限是否已添加 |
| 二维码不显示 | 复制授权链接到浏览器打开 |

## 十、文章关键洞察

1. **飞书 CLI 是 AI 自动化的分水岭**：从"AI只能建议"到"AI能执行"
2. **Skills 是命脉**：不装 Skills 等于白装 CLI，19个Skills = 19个Agent能力入口
3. **重启不可省略**：Agent 在新会话启动时才加载本地 Skills
4. **三层体系**：快捷命令→API命令→原始API，根据任务复杂度选择合适的抽象层级
5. **桥接生态已成型**：cc-connect / lark-coding-agent-bridge / feishu-codex-bridge / Larkspur 四种方案各有适用场景
6. **飞书是Agent共享数据层**：Claude Code + Codex + OpenClaw 通过飞书 CLI 共享数据、任务和上下文
7. **不止于飞书**：CLI 范式可扩展至钉钉/企业微信/Notion/Slack 等协作平台
