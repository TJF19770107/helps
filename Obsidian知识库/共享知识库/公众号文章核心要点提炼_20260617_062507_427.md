## 二、Codex CLI 的 Skills 机制与飞书 CLI Skill 对接原理

### 2.1 对接架构

```
用户自然语言 → Codex 解析意图 → 匹配 Skill → 飞书 CLI 命令 → 飞书 API → 飞书服务
```

### 2.2 Skills 机制核心

| 组件 | 说明 |
|------|------|
| SKILL.md | Skill 定义文件，描述名称、触发条件、指令模板 |
| scripts/ | 可执行脚本目录，封装 CLI 调用逻辑 |
| 市场分发 | 通过 `codex skills add <包名>` 一键安装 |
| 运行时继承 | 子 Skill 可继承父 Skill 的配置与权限上下文 |

### 2.3 飞书 CLI Skill 对接步骤

| 步骤 | 操作 | 说明 |
|:---:|------|------|
| 1 | `npm install -g @larksuite/cli` | 安装飞书 CLI |
| 2 | `codex skills add larksuite/cli -y -g` | 安装飞书官方 Skill 包 |
| 3 | `lark-cli auth login --recommend` | OAuth 授权 |
| 4 | 对话触发 | 自然语言即可调度飞书能力 |

### 2.4 MCP 协议集成路径

Codex CLI 通过 MCP 协议标准化对接飞书 API：

```bash
codex mcp add feishu --transport stdio --command "lark-cli mcp serve"
```

MCP Server 模式下，Codex 自动发现飞书 CLI 暴露的全部工具（200+ 命令），实现工具级自动编排。

## 三、安装配置流程

### 3.1 环境准备

| 依赖 | 版本 | 安装命令 |
|------|------|---------|
| Node.js | >= 18 | `winget install OpenJS.NodeJS` |
| npm | >= 9 | 随 Node.js 附带 |
| Codex CLI | latest | `npm install -g @openai/codex` |
| 飞书 CLI | latest | `npm install -g @larksuite/cli` |

### 3.2 授权配置

| 阶段 | 操作 | 关键点 |
|------|------|--------|
| 创建应用 | 飞书开放平台 → 创建自建应用 | 获取 App ID + App Secret |
| 权限申请 | 按需添加 Scope（11 域） | 最小权限原则 |
| OAuth 授权 | `lark-cli auth login --recommend` | 浏览器确认授权 |
| 验证 | `lark-cli calendar agenda` | 检查日程正常返回 |

### 3.3 权限最小化配置矩阵

| 使用场景 | 最小 Scope 集合 |
|---------|----------------|
| 仅日历管理 | `calendar:calendar` |
| 文档+Base | `doc:document` + `bitable:app` |
| 消息通知 | `im:message` |
| 任务管理 | `task:task` |
| 审批流程 | `approval:approval` |
| OKR 跟踪 | `okr:okr` |
| 全功能 | 11 域全部（生产环境不推荐） |

## 五、SubAgent 并行调用能力

Codex CLI 的 Dynamic Workflows 支持千级 SubAgent 并行：

| 能力 | 指标 | 适用场景 |
|------|:---:|------|
| 最大并行数 | 1000+ | 批量处理大量飞书文档 |
| 默认并发 | 16 | 常规多任务 |
| 独立上下文 | 每个 SubAgent 隔离 | 防止信息泄露 |
| 结果聚合 | 父 Agent 自动合并 | 汇总多源数据到 Base |

**典型命令**：
```bash
codex exec "并行分析这 30 个飞书文档，提取关键数据写入 Base" \
  --subagent-max 20 --permission-mode auto-edit
```

## 六、权限与安全最佳实践

### 6.1 OAuth 授权安全

| 实践 | 说明 |
|------|------|
| 最小 Scope | 仅申请当前任务所需的权限域，避免全量授权 |
| Token 生命周期 | 启用 Token 自动刷新，避免过期中断 |
| 设备流 | 使用 OAuth 2.0 Device Flow，授权码单次有效 |
| 定期审计 | 每月检查应用权限，移除闲置 Scope |

### 6.2 生产环境隔离

| 实践 | 说明 |
|------|------|
| 测试企业先行 | 完整流程在测试企业验证通过后再上生产 |
| `--dry-run` 先行 | 所有写操作先预览，确认无误再执行 |
| 灰度发布 | 先对单用户开放，验证后逐步扩大 |
| 回滚预案 | 所有自动化操作预留手动回滚路径 |

### 6.3 数据安全

| 实践 | 说明 |
|------|------|
| 凭据管理 | App Secret 存 OS 密钥链，禁止硬编码 |
| 审计日志 | 所有写操作记录四元组（操作人/时间/命令/结果） |
| 防注入 | 用户输入严格校验，禁止拼接 Shell 命令 |
| 频率控制 | 实施客户端限流，避免触发 API 限流 |

### 6.4 风险等级速查

| 级别 | 示例操作 | 处理 |
|:---:|------|------|
| 🔴 | 删除文档/Base数据/知识库节点/批量拒绝审批 | 必须用户确认 |
| 🟡 | 修改文档/消息群发/创建日历事件 | 建议用户确认 |
| 🟢 | 查询/读取/列表 | 直接执行 |

## 八、核心结论

1. **Skills 机制是桥接关键**：Codex 通过 `codex skills add larksuite/cli` 一键接入飞书能力，无需用户理解底层 API。
2. **MCP 协议标准化工具发现**：飞书 CLI 通过 MCP Server 暴露 200+ 命令，Codex 自动发现并编排。
3. **SubAgent 千级并行解决批量场景**：批量分析文档、批量导入 Base 等场景下，并行调用大幅提升效率。
4. **安全纵深防御五层**：OAuth 最小权限 → 生产隔离 → `--dry-run` 先行 → 审计日志 → 防注入，形成完整防线。
5. **四步接入、零代码、全自动化**：安装 CLI → 配置应用 → OAuth 授权 → 验证，即可用自然语言操控飞书 11 大域全部能力。
