## 二、核心要点提炼

### 要点1：从「纸上谈兵」到「数字员工」

**传统模式**：AI 给建议 → 人手动执行 → 复制粘贴 → 版本错乱

**新模式**：一句话指令 → AI 调用飞书 Skill → 自动执行 → 结果反馈

### 要点2：19个Skill覆盖11大业务域

飞书CLI内置19个开箱即用Skill，覆盖：
- 文档（doc）、电子表格（sheets）、多维表格（base）
- 即时通讯（im）、日历（calendar）、任务（task）
- 知识库（wiki）、云盘（drive）、邮件（mail）
- 通讯录（contact）、视频会议（vc）、妙记（minutes）
- 画板（whiteboard）、事件订阅（event）、API探索
- 工作流：会议纪要汇总、日报生成、自定义Skill

### 要点3：三步接入，Codex零门槛

```
Step 1: npm install -g @larksuite/cli
Step 2: npx skills add larksuite/cli -y -g
Step 3: 把 GitHub README 丢给 Codex → 自动完成全部配置
```

### 要点4：自然语言驱动全链路自动化

| 指令示例 | 自动执行链路 |
|---------|------------|
| 「发你好给我的飞书」 | lark-im → 消息发送 |
| 「读取PRD文档转测试用例」 | lark-doc → 内容提取 → 结构化分析 → 测试点输出 |
| 「汇总本周所有会议待办」 | lark-calendar → lark-minutes → 结构化合并 → 待办创建 |
| 「读取云盘知识管理文件夹生成信息图」 | lark-drive → 批量读取 → GPT-Image-2 生图 |

### 要点5：安全与权限体系

- OAuth 2.0 授权，用户手动放行
- 权限 Scope 细粒度控制（每个操作独立授权）
- 用户身份（User Access Token）与租户访问令牌分离
- 应用凭证仅在企业自建应用中配置

### 要点6：关键踩坑

1. **重启编辑器**：安装Skill后需重启Codex/Cursor才能生效
2. **权限等待期**：新增权限Scope需5-10分钟生效
3. **用户身份**：搜索个人文档需 `lark-cli auth login` 授权
4. **API Key误区**：Codex Plus订阅后无需额外API Key即可调用GPT生图

## 三、可复用SOP模板

### SOP-01：飞书CLI环境搭建标准流程

1. `npm install -g @larksuite/cli`
2. `npx skills add larksuite/cli -y -g`
3. `lark-cli config init --new` → 浏览器创建应用
4. `lark-cli auth login --recommend` → 浏览器授权
5. `lark-cli auth status` → 验证
6. 重启 AI 编辑器

### SOP-02：日报自动化流水线

1. 获取当日日程 → 2. 获取待办状态 → 3. 生成日报草稿 → 4. 发送到邮件组

### SOP-03：周会纪要自动化

1. 获取本周会议列表 → 2. 拉取妙记总结 → 3. 合并周报 → 4. 创建待办并分配
