## 一、文章核心观点

### 1.1 AI Agent已进入"自然语言驱动自动化"阶段

飞书CLI的核心理念：用户完全不需要学习CLI命令，只需用自然语言告诉AI助手，AI会自动调用CLI完成飞书操作。这标志着协作工具从"手动操作"进入"AI代理操作"时代。

### 1.2 Codex + 飞书CLI = 办公自动化新范式

两者的结合实现了：
- 一句话处理飞书所有信息和数据
- 无需额外配置，Agent可直接调用CLI
- 从文档创建、搜索到批量更新，全流程自然语言驱动

## 二、可复用的SOP模板

### 2.1 飞书CLI接入SOP（5步）

| 步骤 | 操作 | 预计时间 |
|------|------|---------|
| 1 | 安装飞书CLI：npm install -g @larksuite/cli | 1分钟 |
| 2 | 添加Skill：npx skills add https://github.com/larksuite/cli -y -g | 1分钟 |
| 3 | 初始化配置：lark-cli config init --new | 2分钟 |
| 4 | 创建飞书开放平台应用，获取App ID/Secret | 5分钟 |
| 5 | 手动授权，重启AI Agent工具 | 2分钟 |
| **总计** | **完成即开即用** | **~11分钟** |

### 2.2 日常操作SOP

触发词清单：
- "帮我写本周周报" → 自动创建文档
- "总结昨天会议并生成纪要" → 日历+会议+文档联动
- "把本地Markdown发到飞书知识库" → MD→飞书文档
- "分析群聊消息活跃度" → 消息统计+报告

### 2.3 高级自动化SOP

1. 创建专属Skill（如feishu-auto-doc）
2. 定义Skill的description让Codex自动触发
3. 设置权限范围（最小权限原则）
4. 测试→调优→固化

## 三、关键权限配置要点

| 配置项 | 说明 | 注意事项 |
|--------|------|---------|
| App ID/Secret | 飞书开放平台应用凭证 | 妥善保管，不可泄露 |
| 权限范围 | docs:doc/create/update/read | 按需授权，最小权限 |
| 用户授权 | OAuth 2.0手动跳转 | 仅授权信任的Agent |
| 代理模式 | 不授权/授权两种 | 敏感数据需授权模式 |

## 四、自动化场景总结

1. 文档自动化：创建/更新/搜索/批量操作
2. 多维表格：类数据库的CRUD操作
3. 消息处理：群聊消息读取/分析/发送
4. 日历管理：日程创建/查询/修改
5. 会议管理：会议创建/纪要生成
6. 知识库同步：本地↔飞书双向同步
