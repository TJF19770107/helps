## 四、Anthropic 六大 Agentic 设计模式

这些设计模式是所有课程背后的架构原理，源自 Anthropic 官方 agentic 使用指南：

### Pattern 1: Read Before You Write（先读后写）
Agent 在生成任何输出或执行任何操作之前，必须从指定信息源加载相关上下文。这是与 RAG 不同但兼容的更广泛原则：Agent 的第一步永远是咨询，而非推理。

**实践要点**：
- 客户支持 Agent 在回复前检查实时知识库
- 销售 Agent 在撰写外联邮件前拉取 CRM 账户记录
- 合规 Agent 在审查合同前获取适用政策文档

### Pattern 2: Layered Context Hierarchy（分层上下文层级）
不同来源的信息具有不同权威等级。从高到低：
1. **System Prompt** — 操作者指令：角色、约束、行为规则
2. **Retrieved Context** — 运行时从权威源获取的文档/记录/数据
3. **Conversation History** — 当前会话历史
4. **User Input** — 用户最新输入

当来源冲突时，Agent 应遵从上位权威，而非平均或默认听起来合理的。

### Pattern 3: Scoped Knowledge Domains（限定知识域）
Agent 需要明确边界：已知什么，未知什么。
- **显式范围约束**：System Prompt 定义可处理/不可处理的问题
- **检索范围**：仅从指定来源检索上下文

### Pattern 4: Minimal Footprint（最小足迹）
仅执行完成任务所需的操作：
- 仅请求任务所需的权限
- 仅访问任务所需的数据
- 采取最小有效行动
- 不存储超出即刻需要的敏感信息
- 避免非预期副作用

### Pattern 5: Prefer Reversible Actions（偏好可逆操作）
两种实现方式可选时，优先可逆路径：
- 移至暂存文件夹而非删除
- 草拟响应而非立即发送
- 标记待审查而非直接修改
- 创建新记录而非覆写已有记录

### Pattern 6: Trust Verification（信任验证）
在多 Agent 系统中，不同来源的指令应获得不同级别的信任。声称的权限不等于授予的权限。

## 五、Claude Code 四大扩展支柱

2026 年 Claude Code 的架构可类比为 AI 操作系统，由四个组件构成：

| 组件 | 角色 | 使用时机 | 类比 |
|------|------|----------|------|
| **Skills** | 长期记忆与专业知识 | 始终 — 基础层 | AI 的教育 |
| **Hooks** | 事件触发的自动反射 | 质量门控与审计追踪 | AI 的反射 |
| **MCP** | 与外部系统的实时连接 | 需要实时数据时 | AI 的感官 |
| **Subagents** | 并行、隔离的 Claude 会话 | 大型或独立任务 | AI 的双手 |

### Skills 详解
- 存储在 `~/.claude/skills/`（全局）或 `.claude/skills/`（项目级）
- 每个 skill 包含带 frontmatter 的 SKILL.md 文件
- Claude 根据上下文自动加载相关 skill
- 通过 markdown 指令注入领域专属知识

### Hooks 详解
- 事件驱动的自动化触发器
- 支持：PreToolUse、PostToolUse、OnSessionStart 等事件
- 用于质量门控（code review before commit）、审计追踪、自动格式化

### MCP 详解
- 三大原语：Tools（执行操作）、Resources（读取数据）、Prompts（模板提示）
- 支持 stdio 和 HTTP 两种传输
- 高级特性：Sampling、Notifications、File System Access

### Subagents 详解
- 独立 Claude 会话，并行执行
- 上下文窗口隔离（不污染主对话）
- 适用场景：大规模代码审查、多文件并行操作、独立项目任务
- 配置方式：CLAUDE.md 中定义 subagent 规范

## 六、上下文工程五层模型（2026 生产模式）

2026年，Context Engineering 已演化为完整工程学科：

| 层级 | 核心问题 | 手段 |
|------|----------|------|
| 1. Progressive Disclosure | 避免一次性塞入过多上下文 | 按相关性分层加载 |
| 2. Context Compression | Token 成本控制 | 滑动窗口 + LLM 摘要压缩 |
| 3. Context Ranking | 最重要上下文识别 | 相关性评分 + 动态排序 |
| 4. Context Optimization | Token 效率最大化 | KV-Cache、Context Masking |
| 5. Context Orchestration | 多来源上下文协调 | 层级设计、多步记忆分层 |
