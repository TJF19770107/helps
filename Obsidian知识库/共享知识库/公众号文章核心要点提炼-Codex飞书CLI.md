## 核心观点

**AI Agent的真正价值不在"回答得对"，而在"能不能把事办完"。** 飞书CLI解决了AI从理解到执行的关键瓶颈——让Agent不再停留在聊天框里给建议，而是直接进入飞书业务系统执行操作。

---

## 五大关键洞察

### 1. "三人群聊"模型

传统的AI对话是"用户 + AI + 电脑"三人群聊，但飞书不在这个群里。飞书CLI把飞书拉进群聊，AI可以直接和飞书对话。

```
装CLI前：用户 → AI → 建议 → 用户手动操作飞书
装CLI后：用户 → AI + CLI → 直接操作飞书 → 用户确认结果
```

### 2. 从"建议输出"到"执行闭环"

| 传统AI | 飞书CLI加持后 |
|--------|------------|
| "你应该建个文档" | 直接建好文档发链接 |
| "建议约个会" | 自动查日历推荐时间并创建 |
| "消息可以这样回" | 直接起草回复让你确认 |
| "数据可以这样分析" | 直接写入多维表格生成仪表盘 |

### 3. CLI专为AI设计的四大特性

1. **错误提示优化**：出错时告诉AI怎么修复，不只是说"错了"
2. **权限引导**：缺权限时自动引导补授权，不让AI卡住
3. **Token消耗优化**：命令设计上考虑了AI的调用成本
4. **高成功率**：AI用CLI调用成功率远高于直接调API

### 4. 12大业务域全能力覆盖

飞书CLI覆盖消息/文档/云空间/电子表格/多维表格/日历/视频会议/邮箱/任务/知识库/通讯录/搜索，形成完整的飞书操作能力矩阵。

### 5. 安装即用，零学习成本

用户只需要说自然语言，AI自动调用CLI。不需要学命令行，就像不需要懂发动机也能开车。

## 可复用的SOP模板

### SOP-01：环境搭建（10分钟）

```
1. 确认 Node.js >= 16
2. 确认 Codex CLI 已安装
3. 发送安装指令给 Codex
4. 扫码授权飞书
5. 重启 Codex
6. 验证：lark-cli auth status
```

### SOP-02：文档创建（5分钟）

```
1. 自然语言描述需求
2. Codex 自动调用 lark-cli docs +create
3. 返回文档链接
4. 在飞书中确认内容
```

### SOP-03：周报自动化（15分钟/可定时）

```
1. AI 搜索飞书消息/群聊提取进展
2. AI 从日历提取会议内容
3. AI 生成结构化 Markdown
4. 创建飞书云文档到"周报"文件夹
5. 返回文档链接
```

### SOP-04：会议纪要自动处理

```
1. AI 获取妙记逐字稿
2. AI 提取待办事项
3. AI 展示计划给用户确认
4. AI 执行（发文档、建会议、发邮件等）
```

### SOP-05：邮件智能分类处理

```
1. AI 定期扫描未读邮件
2. 按优先级分类
3. 重要邮件摘要推送到群聊
4. 低优先级自动归档
5. 为每封邮件起草回复
```

## 错误处理速查

| 问题 | 解决 |
|------|------|
| 命令无响应 | 重启Codex (`exit` → `codex`) |
| 授权失效 | `lark-cli auth login --recommend` |
| 权限不足 | `lark-cli auth login --scope "<scope>"` |
| CLI未找到 | 将npm全局目录加入PATH |
| 文件夹找不到 | `lark-cli drive +search --query "关键词"` |
