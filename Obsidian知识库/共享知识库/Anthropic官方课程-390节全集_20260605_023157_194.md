## 核心架构：Anthropic 五层定制能力体系

| 层级 | 组件 | 加载方式 | 触发条件 | 行数限制 | 使用场景 |
|------|------|---------|---------|---------|---------|
| L1 | **CLAUDE.md** | 每次对话自动加载 | 始终有效 | ≤200行 | 永不跳过的硬性规则（TypeScript严格模式、不得修改DB schema）|
| L2 | **Skills** | Markdown文件，frontmatter描述匹配时自动触发 | 请求匹配描述 | SKILL.md≤500行 | PR评审清单、发布流程、库特定约定 |
| L3 | **Subagents** | 独立上下文窗口运行 | 主Agent委派 | 独立token预算 | 并行研究、隔离繁琐工作、需要独立工具的任务 |
| L4 | **Hooks** | 事件触发，确定性执行 | PreToolUse/PostToolUse等 | 无上下文污染 | Linters、Formatters、Guardrails强制执行 |
| L5 | **MCP Servers** | 工具/资源/提示词三层协议 | 按需调用 | 无限制 | API、数据库、内部系统交互 |

## 2. Claude Code 101

**课程链接**：https://anthropic.skilljar.com/claude-code-101

**课程简介**：
Claude Code 101 is designed for developers who are either new to software engineering or experienced engineers who haven't yet explored AI coding agents. This course walks you through everything from installation to advanced customization.

**学习目标**：
- Explain what an AI coding agent is and how Claude Code differs from chat-based AI tools
- Understand how the agentic loop, context window, tools, and permissions work together
- Install and set up Claude Code in the terminal, VS Code, JetBrains, Claude Desktop, or on the web
- Write effective prompts using approval mode, auto-accept, and Plan Mode
- Follow the Explore -> Plan -> Code -> Commit workflow for any feature or task
- Manage your context window with /compact, /clear, and /context to stay productive
- Create and maintain a CLAUDE.md file to give Claude persistent project memory
- Build custom subagents to delegate tasks and keep your main context clean
- Connect external tools and data sources using MCP servers
- Write hooks for deterministic control over formatting, command blocking, and notifications

**前置要求**：Basic familiarity with a code editor and the command line; A Claude account (Pro, Max, or Enterprise) or an API key

**目标受众**：New developers learning AI-assisted workflows and experienced engineers exploring coding agents

## 🆕 五层定制能力详解 (R57 补充 · 2026-06-05)

### L1: CLAUDE.md — 项目级硬性规则

**加载方式**：每次对话自动注入上下文
**经验法则**：保持 ≤200 行，每行必须经得起"删除它会不会导致Claude出错"的拷问

**最佳实践**：
- 臃肿的 CLAUDE.md 不会让 Claude 遵守更多规则，反而导致重要规则淹没在噪音中
- 超过200行时 → 参考内容移至 Skills；或拆分到 `.claude/rules/` 路径特定规则文件
- 每条规则必须是**硬性约束**，不能是"建议"或"通常"
- 如果一条规则只在某些时候重要，它就不属于 CLAUDE.md

### L2: Skills — 按需加载的领域知识

**加载方式**：frontmatter 描述匹配时自动加载到上下文
**限制**：SKILL.md ≤500行；描述字段 ≤1536字符

**关键规则**：
- frontmatter 描述必须同时写明"做什么"和"何时使用"——跳过后者，Skill永远不会触发
- 一旦加载，内容在会话剩余时间保持在上下文中，产生重复 token 成本
- 长篇参考资料应移至 skill 链接的独立文件

**Skills vs CLAUDE.md**：Skills用于流程和领域知识；CLAUDE.md用于始终适用的硬性规则。不要把一切都塞进Skills——始终适用的约束仍属于CLAUDE.md。

### L3: Subagents — 独立上下文的任务委派

**加载方式**：主Agent创建独立上下文窗口，任务完成后仅返回精炼结果
**核心特征**：隔离上下文 + 独立token预算 + 主Agent不感知执行细节

**委派判断标准**：
1. 可独立完成：不需要与主Agent实时交互
2. 结果可验证：产出有明确质量标准
3. 值得开销：委派成本小于直接执行收益

**Skills注入Subagents**：需通过 `skills` frontmatter字段显式声明；与主会话不同，subagent不会自动按描述匹配加载Skills。

### L4: Hooks — 确定性强制执行

**本质**：五种能力中**唯一完全绕过模型**的机制。事件触发 → Hook运行 → 不管模型怎么想。

| 事件 | 时机 | 用途 |
|------|------|------|
| PreToolUse | 工具调用前 | 验证/阻止危险操作 |
| PostToolUse | 工具调用后 | Linting、格式化、日志 |
| UserPromptSubmit | 用户消息发送前 | 拦截/预处理内容 |
| SessionStart | 会话开始时 | 加载上下文 |

**CLAUDE.md vs Hooks**："绝不编辑.env"在CLAUDE.md中是请求；PreToolUse Hook阻止编辑是强制执行。Linters、Formatters、Validators、Audit Logging都是Hook的典型场景。

### L5: MCP Servers — 连接外部世界

**三层协议**：

| 原语 | 功能 | 示例 |
|------|------|------|
| Tools | 执行操作 | 函数调用、API请求 |
| Resources | 读取数据 | 文件、数据库、API响应 |
| Prompts | 预构建指令 | 模板化交互 |
