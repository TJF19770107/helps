  │   ├── 文本/卡片/富文本

  │   ├── 日程CRUD

## 三、Codex × 飞书 5大核心联动架构

### 架构1：事件驱动流水线

```
GitHub Event ──→ Codex Triggers ──→ Codex Exec ──→ 飞书书消息
     ↑                                                  │
     └──────────── 飞书审批通过 ←── 结果通知 ←──────────┘
```

### 架构2：Agent记忆闭环

```
Agent执行 ──→ 飞书Base写入 ──→ 定期分析 ──→ Codex优化建议
   ↑                                                    │
   └────────────── 上下文注入 ←── 历史查询 ←────────────┘
```

### 架构3：多渠道统一Gateway

```
           ┌─→ 飞书 Webhook ──┐
用户指令 ──┼─→ 微信 Webhook ──┼─→ Gateway Router ──→ Codex Exec ──→ 原渠道回复
           └─→ 钉钉 Webhook ──┘        │
                                   飞书Base日志存储
```

### 架构4：日历驱动任务调度

```
飞书日历查询 ──→ Codex分析日程 ──→ 任务优先级排序 ──→ 预留执行窗口
                                                          │
飞书文档 ←── 会议纪要生成 ←── Codex分析录制 ←── 会议结束获取录制
```

### 架构5：审批自动化部署

```
飞书审批提交 ──→ 审批通过Webhook ──→ Codex部署执行 ──→ 结果通知
                                              │
                                       飞书Base记录 ←── 部署日志
```

## 四、最佳实践速查表

| 场景 | 触发方式 | Codex命令 | 飞书API | 频率 |
|------|---------|----------|---------|------|
| PR审查通知 | GitHub Webhook | `codex exec "审查PR"` | 消息卡片 | 实时 |
| CI/CD通知 | GitHub Actions | 收集构建结果 | 消息卡片 | 每次构建 |
| 工作日报 | Cron `0 18 * * 1-5` | `codex exec "生成日报"` | 文档创建+消息 | 每日 |
| Issue→文档 | GitHub Issue事件 | `codex exec "结构化Issue"` | 文档创建 | 实时 |
| 飞书指令执行 | 飞书消息Webhook | `codex exec "$cmd"` | 消息回复 | 实时 |
| Agent记忆 | Agent每次执行后 | — | Base写入 | 每次 |
| 审批部署 | 飞书审批通过 | `codex exec "部署"` | 消息通知 | 实时 |
| API文档生成 | 代码Push后 | `codex exec "生成文档"` | 文档创建 | 每次Push |
| 日程联动 | Cron `0 8 * * *` | `codex exec "分析日程"` | 日历查询 | 每日 |
| 多渠道路由 | 各渠道Webhook | `codex exec "$cmd"` | 各渠道回复 | 实时 |

## 五、学习路径建议

### 第一阶段：基础入门（第1-2天）

1. 安装 Codex CLI + 飞书CLI，完成认证配置
2. 跑通 `codex exec "hello world"` 和 `feishu message send`
3. 手动完成一次"执行→通知飞书"的端到端流程

### 第二阶段：单场景串联（第3-5天）

4. 实现场景1（PR审查通知）：配置GitHub Trigger + 飞书卡片
5. 实现场景3（定时日报）：配置cron Trigger + 飞书文档
6. 理解认证Token刷新机制

### 第三阶段：记忆与存储（第6-8天）

7. 搭建飞书Base Agent记忆表
8. 实现Agent执行自动写入Base
9. 实现历史查询和上下文注入

### 第四阶段：多渠道Gateway（第9-12天）

10. 搭建Gateway路由服务
11. 接入飞书+微信+钉钉三渠道
12. 统一消息格式和回复逻辑

### 第五阶段：生产化（第13-15天）

13. 凭证迁移到密钥管理服务
14. 添加监控和告警
15. Codex Bedrock企业托管部署
