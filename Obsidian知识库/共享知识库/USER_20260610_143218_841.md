## 一、协作架构总览

### 1.1 三层协作模型

```
┌─────────────────────────────────┐
│         龙虾主控 Agent           │  ← 协调器层
│   (意图理解 / 任务分解 / 结果汇总) │
├─────────┬─────────┬─────────────┤
│ 豆包Agent │ Hermes  │ OpenClaw   │  ← 专业Agent层
│ (应用操作) │(系统运维)│(万能编程)  │
├─────────┴─────────┴─────────────┤
│     Obsidian 共享知识库          │  ← 持久记忆层
│  SOUL / USER / AGENTS / 课程全集 │
└─────────────────────────────────┘
```

### 1.2 Multi-Agent 协作模式（Anthropic 官方标准）

```
协调器 (主控) → 子代理A + 子代理B + 子代理C
         ↓
共享文件系统 + 独立上下文线程
         ↓
线程持久化：协调器可跨轮次调用同一代理
```

**关键特性**：
- 所有代理共享同一容器和文件系统
- 每个代理运行在独立 Session Thread（上下文隔离的事件流）
- 协调器在主线程报告活动，子线程按需生成
- 代理保留之前的所有对话历史

## 二、任务路由规则

### 2.1 路由决策表

| 任务类型 | 路由目标 | 触发条件 |
|---------|---------|---------|
| 应用操作（App/小程序/Steam） | 豆包Agent | 涉及端侧应用交互 |
| 系统运维（Windows设置/进程） | Hermes Agent | 系统级配置/修复 |
| 复杂编程/开发/文件操作 | OpenClaw Agent | 代码生成/文件处理 |
| 深度搜索研究 | Search Agent | 信息获取/分析 |
| 知识库更新迭代 | 龙虾主控直接 | 本体系内维护 |
| 多域协作 | 主控协调多Agent | 跨域复杂任务 |

### 2.2 协作示例

**场景：启动豆包App并调整系统音量**
```
主控 → 豆包Agent: 启动豆包App
     → Hermes Agent: 调整系统音量至50%
```

**场景：文件整理 + 系统清理**
```
主控 → OpenClaw Agent: 整理桌面文件按类型归类
     → Hermes Agent: 清理临时文件和系统缓存
```

## 三、通信协议与状态管理

### 3.1 双向桥接协议

```
Agent A ←→ 主控 ←→ Agent B
    │                    │
    │   共享知识库同步    │
    └────────┬───────────┘
             ▼
    Obsidian 知识库 (SOUL / USER / AGENTS)
```

### 3.2 状态传递规范

| 传递项 | 格式 | 示例 |
|--------|------|------|
| 任务上下文 | `<overall_goal>` + `<current_task>` | XML标签结构 |
| 中间产物 | 工作目录 output/ | 文件路径列表 |
| 记忆引用 | memory_ids | 历史消息ID数组 |
| Agent 延续 | inherit_agent_id | sa-xxx |

### 3.3 知识库同步约定

- 每次重大迭代后同步 SOUL.md / USER.md / AGENTS.md
- 知识库更新触发全分身重新加载
- 冲突解决：主控最终裁决

## 四、Agent 生命周期管理

### 4.1 创建

```
1. 定义角色（功能特定化）
2. 配置工具权限（最小化原则）
3. 编写 CLAUDE.md（≤200行）
4. 预加载技能
```

### 4.2 运行

```
1. 接收任务 → Plan 模式分析
2. 工具调用 → 钩子监控
3. 结果返回 → 自主验证
4. 记忆更新 → Gotchas 积累
```

### 4.3 迭代

```
1. 分析失败记录
2. 更新 Gotchas
3. 优化技能描述
4. 调整工具权限
```

## 五、协作工作流模板

### 5.1 定时任务协作

```
定时触发 → 主控解析任务
         → 并行派发给多个 Agent
         → 汇总结果
         → 更新知识库
         → 产出报告
```

### 5.2 迭代式开发协作

```
Plan 模式 → 规格确认
          → Agent A 编码 → 代码审查 Agent 审查
          → Agent B 测试 → 反馈修复
          → 合并 PR
```

### 5.3 故障排查协作

```
用户报告 → 主控分发
          → Hermes 系统诊断
          → 豆包 应用状态检查
          → OpenClaw 日志分析
          → 主控汇总诊断报告
```

## 六、Agent Teams 配置

### 6.1 Claude Code Agent Teams（参考模型）

- 环境变量：`CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1`
- In-process 模式：所有队员在同一终端内运行
- Split panes 模式：每个队员独立 tmux/iTerm2 窗格
- git worktrees 隔离分支开发

### 6.2 龙虾体系映射

| Claude Code 功能 | 龙虾体系实现 |
|-----------------|------------|
| Agent Teams | 豆包 + Hermes + OpenClaw 三Agent并行 |
| git worktrees | E:\ 龙虾AI主控中心\ 目录隔离 |
| 上下文隔离 | 各Agent独立对话窗口 |
| 任务协调 | 主控 dispatch_task |
