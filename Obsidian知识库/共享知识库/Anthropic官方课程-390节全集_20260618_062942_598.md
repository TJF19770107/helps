## 三、技术专题深度（基于官方文档提炼）

### 3.1 Subagents（子代理）体系

#### 3.1.1 核心理念
- Subagent是把整体任务拆成能独立运行的小单元
- 适用于并行处理与上下文窗口受限的场景
- 主代理负责统筹与复杂逻辑，子代理适合短时、明确输入输出的工作
- 拆分好任务能显著降低主代理的上下文占用，提高稳定性

#### 3.1.2 子代理规格（Spec）设计原则
- 明确输入输出格式
- 字数与风格限制
- 错误返回结构
- 超时策略
- 可复用的spec模板

#### 3.1.3 Subagent文件格式
使用 **YAML frontmatter + Markdown system prompt**：

```yaml
---
name: code-reviewer
description: Reviews code for quality, security, and best practices.
tools: Read, Glob, Grep
disallowedTools: Write, Edit
model: sonnet
permissionMode: acceptEdits
maxTurns: 10
effort: medium
memory: project
color: blue
---
```

#### 3.1.4 完整Frontmatter字段

| 字段 | 必需 | 说明 |
|------|:---:|------|
| `name` | ✅ | 小写+连字符，唯一标识符 |
| `description` | ✅ | **最重要字段**——决定Claude何时自动委托 |
| `tools` | ❌ | 工具白名单。省略=继承所有 |
| `disallowedTools` | ❌ | 工具黑名单。先应用disallowedTools再解析tools |
| `model` | ❌ | sonnet/opus/haiku/inherit |
| `permissionMode` | ❌ | default/acceptEdits/auto/dontAsk/bypassPermissions/plan |
| `mcpServers` | ❌ | 服务器名或内联定义 |
| `hooks` | ❌ | PreToolUse/PostToolUse/Stop |
| `maxTurns` | ❌ | 最大代理轮数 |
| `skills` | ❌ | 启动时预加载到subagent上下文 |
| `initialPrompt` | ❌ | --agent模式时自动提交为第一个用户轮次 |
| `memory` | ❌ | user/project/local 持久记忆范围 |
| `effort` | ❌ | low/medium/high/xhigh/max |
| `background` | ❌ | true/false。true=始终后台运行 |
| `isolation` | ❌ | worktree=在临时git worktree中运行 |
| `color` | ❌ | red/blue/green/yellow/purple/orange/pink/cyan |

#### 3.1.5 四种部署作用域（优先级从高到低）

| 优先级 | 位置 | 作用域 |
|:---:|------|------|
| 1 | Managed settings `.claude/agents/` | 组织范围 |
| 2 | `--agents` CLI标志 | 当前会话 |
| 3 | Project `.claude/agents/` | 当前项目 |
| 4 | User `~/.claude/agents/` | 所有项目 |
| 5 | Plugin `agents/` | Plugin启用位置 |

#### 3.1.6 五个内置Subagent

| 名称 | Model | Tools | 行为特征 |
|------|-------|-------|---------|
| Explore | Haiku | 只读 | 快速低延迟，拒绝Write/Edit，跳过CLAUDE.md |
| Plan | 继承主对话 | 只读 | Plan mode专用，不可嵌套生成subagents |
| General-purpose | 继承主对话 | 所有工具 | 完整读写能力，可递归委托 |
| statusline-setup | Sonnet | 受限 | 自动被/statusline调用 |
| claude-code-guide | Haiku | 受限 | 自动被/面板调用 |

#### 3.1.7 Agent Teams机制
- 队友从引用的subagent继承`tools`和`model`
- 引用的subagent正文作为额外指令追加到队友系统提示
- 不适用于Agent Teams的字段：hooks, mcpServers, permissionMode, background, isolation

### 3.2 Agent Skills体系

#### 3.2.1 核心原则
1. **简洁至关重要**：上下文窗口是公共资源，只有L1元数据（名称+描述）在启动时预加载
2. **默认假设Claude已经非常智能**：只添加Claude尚不具备的上下文
3. **Skills按需加载**：Claude仅在Skill变得相关时才读取SKILL.md
4. **结构化清晰**：好的Skill应当结构清晰、经过实际使用测试

#### 3.2.2 三步激活流程
1. **L1元数据加载**：启动时仅加载name + description到上下文
2. **任务触发匹配**：Claude根据当前任务自动匹配相关Skill
3. **L2全文读取**：仅当Skill被判定为相关后，才读取完整SKILL.md及关联文件

#### 3.2.3 Skill编写最佳实践
- 约50个Token的高效描述（好例：简洁的pdf提取Skill）
- 不要重复Claude已知的通用知识
- 每条信息审视："Claude真的需要这个解释吗？"
- 每条信息审视："这段内容是否值得其Token成本？"

#### 3.2.4 Skills可复用设计
- Skill是跨会话、跨项目的可复用单元
- 通过`skills`字段可在subagent启动时预加载
- 支持`context: fork`模式（为subagent创建独立skill上下文）
- Skills生态从"每个Agent各自造技能"升级为"跨Agent技能共享/交易/订阅"

### 3.3 MCP（Model Context Protocol）集成

#### 3.3.1 MCP核心概念
- **通用接口**：`execute(name, input) → string`，N+M替代N×M集成
- **协议标准化**：MCP已获Google/OpenAI/Meta等主流厂商通用化覆盖
- **Claude Code中的MCP**：通过`.mcp.json`或`settings.json`声明

#### 3.3.2 MCP最小化原则
- 每个MCP服务器应做一件事且做好
- 优先使用官方服务器，自定义服务器需充分测试
- 生产环境中MCP应设为只读优先、写操作需二次确认

#### 3.3.3 MCP安全约束
- Plugin subagent的`mcpServers`字段被忽略（防止第三方声明恶意MCP服务器）
- 40%暴露MCP服务无认证（2026年6月全网扫描数据）
- 67 CVE总览（VIPER-MCP），需持续监控

### 3.4 Hooks系统

#### 3.4.1 四大节点
| 节点 | 用途 | 特点 |
|------|------|------|
| PreToolUse | 安全检查、审计日志 | 无条件触发，不可绕过 |
| PostToolUse | 代码检查（tsc/ESLint）、测试运行 | 比Skill指令更可靠 |
| SessionStart | 加载上下文、检查环境 | 启动时自动执行 |
| SessionEnd | 清理、总结 | 会话结束前执行 |

#### 3.4.2 30种Hook事件
涵盖PreToolUse、PostToolUse、Stop、SubagentStop、SessionStart、SessionEnd等完整生命周期。

#### 3.4.3 Plugin Subagent安全限制
出于安全原因，Plugin subagent的以下字段被忽略：
- `hooks`：防止第三方plugin注入持久化钩子
- `mcpServers`：防止第三方plugin声明恶意MCP服务器
- `permissionMode`：防止第三方plugin绕过权限控制

### 3.5 Claude Code最佳实践

#### 3.5.1 核心约束：Context Window管理
- Claude的context window保存整个对话：每条消息、每个文件读取、每个命令输出
- context填充时LLM性能下降：可能"遗忘"早期指令或犯更多错误
- Context Window是最重要的资源

#### 3.5.2 给Claude一种验证其工作的方式
- 给Claude一个它可以运行的检查：测试、构建、屏幕截图
- "这是你观看的会话和你可以离开的会话之间的区别"
- 检查是任何返回Claude可以在对话中读取的信号的东西

#### 3.5.3 自主性最佳实践
- 描述想要什么，让Claude弄清楚如何构建
- Claude会探索、规划和实现
- 从"自己编写代码并要求Claude审查"转变为"描述需求→Claude自主构建"

#### 3.5.4 生产级模式
- **持久化项目感知设置**：CLAUDE.md + 智能提示 + 结构化工作流
- **控制Claude行为**：CLAUDE.md + Hooks
- **并行化Claude**：多subagent并行执行
- **嵌入SDLC全流程**：从特性研究到CI/CD

### 3.6 Managed Agents

#### 3.6.1 四大核心概念
| 概念 | 描述 |
|------|------|
| Agent | 模型、系统提示、工具、MCP服务器和技能的定义 |
| Environment | 配置的容器模板（包、网络访问） |
| Session | 在环境中运行的代理实例，执行特定任务 |
| Events | 应用与代理之间交换的消息 |

#### 3.6.2 工作流程
1. **创建代理**：定义模型、系统提示、工具、MCP服务器和技能
2. **创建环境**：配置云容器，预装软件包、网络访问规则
3. **启动会话**：启动引用代理和环境配置的会话
4. **发送事件和流式传输响应**：Claude自主执行工具并通过SSE流式传输
5. **引导或中断**：发送额外事件在执行过程中引导代理

#### 3.6.3 适用场景
- 长时间运行执行（数分钟或数小时）
- 云基础设施（安全容器+预装包）
- 最小基础设施（无需自建代理循环/沙箱/工具执行层）
- 有状态会话（持久文件系统+对话历史）

#### 3.6.4 内置工具
- Bash：在容器中运行shell命令
- 文件操作：读取、写入、编辑、glob和grep文件
- 网络搜索和获取：搜索网络并从URL检索内容
- MCP服务器：连接到外部工具提供商

#### 3.6.5 Managed Agents vs Messages API

| 维度 | Managed Agents | Messages API |
|------|:---:|:---:|
| 定位 | 预构建、可配置的代理框架 | 直接模型提示访问 |
| 最佳场景 | 长时间运行任务和异步工作 | 自定义代理循环和细粒度控制 |
| 基础设施 | 全托管环境+性能优化 | 自建 |

### 3.7 上下文管理深度

#### 3.7.1 Context Window优化策略
- 使用自定义状态行持续跟踪context使用情况
- 减少token使用：优先使用Explore subagent做快速探索
- 任务拆分：将大任务委派给subagent，主对话保持精简
- 压缩策略：Claude Code内置提示缓存和压缩优化

#### 3.7.2 会话启动加载序列
```
1. CLAUDE.md层次加载
2. Git状态快照
3. Subagent定义扫描（按优先级）
4. MCP Server连接
5. Hooks注册
6. Skills预加载（L1：name + description）
```

#### 3.7.3 Subagent上下文隔离
- Explore/Plan跳过CLAUDE.md（设计目标：快速廉价）
- 主对话使用完整CLAUDE.md上下文读取subagent结果
- 大多数项目规则不需要到达subagent本身

### 3.8 Plugin体系

#### 3.8.1 Plugin JSON规范
```json
{
  "name": "my-plugin",
  "description": "A description of what this plugin does",
  "author": {"name": "Your Name", "email": "you@example.com"}
}
```

#### 3.8.2 Plugin Subagent安全
- 第三方plugin可定义专用subagent（如code-reviewer、code-architect、code-explorer）
- hooks/mcpServers/permissionMode字段被忽略
- 如需这些字段：将subagent复制到`.claude/agents/`或`~/.claude/agents/`

### 3.9 多Agent协作与编排

#### 3.9.1 任务委派模式
- **基于描述的自动匹配**：Claude根据subagent的description字段自动匹配任务
- **主代理统筹**：负责复杂逻辑和整体协调
- **子代理专注**：处理短时、明确输入输出的工作单元

#### 3.9.2 并行子代理调度
- 同轮内无依赖的多个子任务并行发起
- Explore subagent（Haiku/只读）用于快速并行探索
- General-purpose subagent用于需要完整读写能力的并行任务

#### 3.9.3 Conductor Orchestrator模式
- 任务分解→分配到Specialist Agent→监控进度→合成最终PR
- Shared Blackboard（TASKS.md）作为协调中心
- 3-Strike Rule：失败3次自动升级到senior-dev

#### 3.9.4 Agent Teams配置
```yaml
teams:
  fullstack:
    members:
      - type: code-reviewer
        role: security-auditor
      - type: test-writer
        role: unit-test-generator
```
