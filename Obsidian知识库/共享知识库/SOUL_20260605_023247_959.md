## 一、Agent 内核设计原则

### 1.1 Agentic Loop 黄金闭环
```
收集上下文 → 执行操作 → 验证结果 → 反馈修正
```
- 每个操作后必须验证，形成感知-行动-验证的完整闭环
- 失败时自动回溯，不盲目前进
- Agent SDK 中消息生命周期：User Message → Agent Processing → Tool Call → Tool Response → Next Action

### 1.2 上下文窗口隔离原则
- **子代理隔离**：每个子代理拥有独立上下文窗口，主Agent只接收精炼结果
- **渐进式披露**：按需加载信息，避免一次性塞入全部上下文
- **精准回报**：子代理只返回关键信息，不返回完整执行过程
- **Token预算独立**：子代理消耗不计入主会话上下文

### 1.3 工具与权限分层
| 层级 | 范围 | 权限 |
|------|------|------|
| 核心层 | 读文件、搜索、基础执行 | 默认开启 |
| 扩展层 | 写文件、网络请求、MCP工具 | 按需授权 |
| 特权层 | 系统配置、删除、支付 | 显式确认 |

### 1.4 Anthropic 五层定制能力设计原则 (R57 新增)

```
CLAUDE.md (硬性规则) → Skills (流程知识) → Subagents (任务委派) → Hooks (确定性执行) → MCP (外部连接)
```

| 层级 | 设计原则 | 反模式 |
|------|---------|--------|
| CLAUDE.md (≤200行) | 仅放永不跳过的硬性规则；每行必须经得起"删除后Claude是否会出错"的拷问 | 把建议性内容塞入CLAUDE.md → 臃肿导致重要规则被淹没 |
| Skills (≤500行) | Markdown + frontmatter描述（做什么+何时使用）；加载后常驻上下文 | 描述只写"做什么"不写"何时使用" → Skill永不被触发 |
| Subagents | 独立上下文 + 独立token预算；委派前验证三条件 | 委派需要实时交互的任务 → 通信开销大于收益 |
| Hooks | 唯一绕过模型的机制，用于guardrail强制执行 | 把Hook当Skill用 → 丢失模型判断能力 |
| MCP | 连接外部世界，非思考能力 | 把知识注入当MCP工具 → 本应用CLAUDE.md/Skills |

## 二、多Agent协作设计原则

### 2.1 Lead-Specialist 模式
- **Lead Agent**：负责任务分解、路由、结果汇总
- **Specialist Agent**：专注单一领域，独立上下文执行
- **共享文件系统**：通过文件传递中间结果，避免上下文污染
- **Agent SDK 托管**：生产环境可独立部署各Agent实例

### 2.2 Agent 通信模式
| 模式 | 适用场景 | 特点 |
|------|---------|------|
| 并行执行 | 无依赖子任务 | 最大效率 |
| 链式调用 | 有先后依赖 | 结果传递 |
| 条件路由 | 动态决策 | 基于中间结果分支 |
| 竞争模式 | 多方案择优 | 并行生成+自动排序 |

### 2.3 委派判断标准
- **可独立完成**：任务不需要与其他任务实时协调
- **结果可验证**：产出有明确的质量标准
- **值得开销**：委派的开销小于直接执行的收益

### 2.4 File Checkpointing 回滚机制 (R57 新增)
- Agent SDK 支持会话期间文件变更追踪
- 每次操作后可回滚至任意历史检查点
- 适用于高风险批量操作的安全网设计

## 三、Skills 设计原则

### 3.1 原子化与可组合
- 每个Skill仅做一件事，做好一件事
- Skills之间通过标准化接口组合
- SKILL.md 使用 frontmatter 声明触发条件和优先级

### 3.2 Skills Frontmatter 规范 (R57 更新)

```yaml
---
name: pr-review                    # 唯一标识
description: PR代码审查清单，当用户请求代码审查、PR review时使用  # 必须涵盖：(1)做什么 (2)何时使用
allowed-tools: [Read, Grep, Bash]  # 可选：限制可用工具
model: claude-sonnet-4-20250514    # 可选：指定模型
---
```

**关键规则**：
- 描述字段上限 1536 字符，关键用例前置
- 一旦加载，常驻上下文至会话结束，产生重复token成本
- 长篇参考资料应移至skill链接的独立文件

### 3.3 Skills 与 Subagents 协同
- Subagents 可使用Skills，但需通过 `skills` frontmatter字段显式声明
- 与主会话不同——Subagent不会自动按描述匹配加载Skills
- 最佳实践：为Subagent预加载其专属Skills集合

## 四、Hooks 设计原则 (R57 新增)

### 4.1 核心定位
Hooks 是 Anthropic 五层能力中**唯一完全绕过模型的机制**——事件触发即执行，不涉及AI判断。因此：
- **Guardrail 首选**：安全约束、合规检查、操作阻止 → Hook
- **自动化副作用**：Linting、格式化、审计日志 → Hook
- **非建议性内容**：凡是需要"建议"或"提醒"而非"强制执行"的 → CLAUDE.md 或 Skill，不是 Hook

### 4.2 关键 Hook 事件

| 事件 | 触发时机 | 最佳用途 |
|------|---------|---------|
| PreToolUse | 工具调用前 | 危险操作拦截（禁止编辑.env、禁止删除生产数据）|
| PostToolUse | 工具调用后 | Linter运行、格式自动修正、变更日志记录 |
| UserPromptSubmit | 用户提交前 | 内容过滤、注入补充上下文 |
| SessionStart | 会话开始 | 环境变量注入、项目配置加载 |

### 4.3 Claude Code 典型 Hook 配置示例
```json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Edit|Write",
        "command": "python check-protected-files.py \"$CLAUDE_TOOL_INPUT\""
      }
    ],
    "PostToolUse": [
      {
        "matcher": "Edit|Write",
        "command": "npx eslint --fix \"$CLAUDE_FILE_PATH\""
      }
    ]
  }
}
```

## 五、MCP 设计原则

### 5.1 三层架构
| 层 | 原语 | 功能 | 设计原则 |
|----|------|------|---------|
| 工具层 | Tools | 执行操作 | 幂等性、错误处理、超时控制 |
| 资源层 | Resources | 读取数据 | URI模板化、缓存策略、分页支持 |
| 提示词层 | Prompts | 预构建指令 | 参数化、模板化、多语言 |

### 5.2 MCP vs CLI 选择原则
- **优先CLI**：简单读/写/查询操作
- **使用MCP**：复杂API交互、多步骤事务、需要状态管理的交互
