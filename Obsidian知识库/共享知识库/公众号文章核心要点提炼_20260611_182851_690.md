## 二、核心知识点

### 2.1 Codex 接入飞书后的能力清单

1. **文档**：创建和更新文档
2. **Base（多维表格）**：读写Base数据
3. **日历**：查询日历、创建日历事件
4. **消息**：发送消息（群聊/私聊）
5. **任务**：管理任务
6. **邮箱**：处理邮件
7. **知识库**：检索和创建知识
8. **会议纪要**：会议相关处理

### 2.2 四步接入流程解读

**第1步：安装CLI**
- 让 Codex 自动执行安装命令
- 过程持续 4-5 分钟
- 零手动操作

**第2步：配置应用**
- lark-cli config init 命令
- 获取浏览器配置链接
- 创建飞书应用或绑定已有应用
- 关键凭据：App ID + App Secret

**第3步：OAuth授权**
- lark-cli auth login
- 浏览器确认授权
- 授权范围决定能力边界

**第4步：验证接入**
- 执行低风险命令（如创建日历）
- 验证权限链路是否畅通
- 通过后即可全面使用

## 三、关键步骤详解

### 3.1 飞书 CLI 本质

飞书 CLI 是飞书开放平台提供的命令行工具，封装了飞书全部 Open API，让开发者（和 AI）可以通过命令行操作飞书的所有资源。Codex 通过 CLI 间接调用飞书 API。

### 3.2 凭据流转路径

```
用户 → Codex → 飞书 CLI → 飞书 Open API → 飞书资源
         ↓
    凭据缓存（本地加密存储）
```

### 3.3 安全要点

- App ID + App Secret 是飞书应用的唯一身份凭证，泄露后果严重
- 授权范围应遵循"最小权限原则"
- 定期轮换凭据（建议 90 天）
- 多人场景使用独立应用实例

### 4.2 技术洞见

1. **CLI桥接模式**：AI → CLI → API 是最通用的 AI 接入模式，不仅适用于飞书，还可推广到其他提供CLI的服务
2. **凭据对话传递**：Codex 对话中直接提交凭据，打破了传统需要手动配置文件的方式
3. **浏览器授权承转**：OAuth 流程通过 Codex 输出链接 + 浏览器完成，保留了安全边界

### 4.3 可泛化接入模式

```
工具服务 → 提供CLI → Codex安装CLI → 配置凭据 → OAuth授权 → 验证 → 自动化
```

这个模式适用于：飞书、钉钉、企业微信、Notion、GitHub、Jira、Trello 等所有提供 CLI 或 REST API 的工具。
