## 1. 这个文件在系统里管什么（架构定位）

`vnpy/trader/engine.py` 属 **执行层 / OMS 层的宿主容器**，不是业务引擎。三层结构：

```
        ┌─────────────────── MainEngine（服务定位器 + 生命周期）───────────────────┐
        │  gateways{}        engines{}        apps{}        exchanges[]            │
        └───────┬─────────────────┬────────────────────┬──────────────────────────┘
                │                 │                    │
       BaseGateway（外部）   BaseEngine（内部）      BaseApp（应用包）
       binance/ctp/...      LogEngine              CtaStrategyApp
                            OmsEngine  ★核心        CtaBacktesterApp
                            EmailEngine
                            WechatEngine
                │                 │
                └──── 全部经 EventEngine（vnpy/event/engine.py，147 行）解耦 ────┘
```

- **上游依赖**：`vnpy.event.EventEngine`（事件总线）、`trader.object`（数据模型）、`trader.gateway.BaseGateway`（抽象）、`trader.setting.SETTINGS`（配置）、`trader.converter.OffsetConverter`（今仓/昨仓转换）
- **下游被谁调用**：所有 App（CTA 策略、回测器、数据管理）、`MainWindow`（GUI）、`examples/` 下所有启动脚本

★ **关键架构判定：MainEngine 是「容器/服务定位器」，OmsEngine 才是真正的 OMS。**
`init_engines()`（149-177）把 `get_tick/get_order/get_all_active_orders…` **绑定成 MainEngine 的属性**，
而不是让 MainEngine 继承 OmsEngine。这样上层拿的是「可替换的 callable」，
换 OMS 实现（或塞测试替身）不用改任何调用方 —— 这个手法值得抄（见 D71）。

| 文件 | 层 | 一句话 |
|---|---|---|
| `trader/engine.py` | 执行层（容器） | MainEngine 装配 + 四个内置引擎（Log/OMS/Email/Wechat） |
| `trader/object.py` | **数据层（口径地基）** | 全部数据类；**没有任何手续费字段**（见 D69） |
| `trader/utility.py` | 工具层 | `BarGenerator`（tick→1m→x 分钟/小时/日）、`ArrayManager`（增量指标容器） |
| `event/engine.py` | 事件层 | 147 行：双线程（`_run` 消费队列 + `_run_timer` 每 interval 秒发 `eTimer`） |

## 4. 可迁移设计点（每条写「为什么这么设计更好」）

### D67 · 分钟窗口必须**整除 60**，否则静默降级周期 —— 而它不校验、不抛错

`utility.py:315`：

```python
# Check if window bar completed
if not (bar.datetime.minute + 1) % self.window:
```

这是**按分钟号取模**判闭合，不是累计计数。docstring（179-180）明写「x must be able to divide 60: 2,3,5,6,10,15,20,30」——但代码里**一行校验都没有**。

本轮用它复刻了一遍 `simulate_minute_window()`，实测：

| 输入粒度 | window | 稳态跨度 | 应有跨度 | 结论 |
|---|---|---|---|---|
| 1m | 15 | **15 分钟** | 15 | ✅ 合法 |
| 15m | 4 | **60 分钟** | 60 | ✅ 合法（虽然 `4 % 15 != 0`，但整点命中） |
| 15m | **16** | **60 分钟** | **240** | ❌ **静默产出 1H bar，小 4 倍** |

`window=16` 时触发分钟是 `[15, 31, 47]`，而 15m 数据只落在 `{0,15,30,45}` ⇒ 每小时只在 minute=15 触发一次，稳态每根含 **4** 个 15m 子 bar，首根只含 **2** 个。

**为什么这么设计更好（反例意义上的「更好」）**：vnpy 的写法在「1m→x 分钟（x|60）」这个**唯一约定域内**是对的，且实现极简。但一旦越界，它**不响**。正确做法是把 docstring 的约定变成**可断言检查** —— 本轮落地 `minute_window_legal(data_interval, window)`，判据用**操作定义**（稳态跨度 == `data_interval × window`）而不是抄口诀（口诀会误判 `15m + window=4`）。

### D68 · 聚合完整性必须独立审计：**空桶能丢，半桶丢不掉**

我方 `hypothesis_runner._agg_bars()` 用 `pandas.resample("4h")`（epoch 锚定，对齐是对的），然后：

```python
agg = agg.dropna(subset=["open", "close"])
agg = agg[agg["volume"] > 0]
```

**空桶被丢掉（正确），半桶被当成完整桶（问题所在）**：桶里 16 根 15m 只有 6 根时，`high/low` 被低估 → 突破信号少报；`volume` 被低估 → `sig_vol` 量比失真。而**四只标的全历史里从来没有一行代码检查过这件事**。

本轮落地 `audit_buckets()` 实测（真实数据，非构造）：

| 标的 | 15m 行数 | 4H 桶数 | 半桶数 | 半桶率 | 最少子 bar | 1H 半桶 |
|---|---|---|---|---|---|---|
| BTC | 238,737 | 14,922 | 6 | 0.0402% | 12 | 6 |
| ETH | 237,417 | 14,841 | 7 | 0.0472% | **1** | 8 |
| BNB | 234,870 | 14,680 | 4 | 0.0272% | 12 | 4 |
| DOGE | 215,726 | 13,484 | 5 | 0.0371% | 8 | 4 |

合计 **22 个半桶 / 57,927 个 4H 桶**。ETH 有一个桶**只有 1 根 15m 子 bar**（相当于拿单根 15 分钟当 4 小时用）。

### D69 · OMS 三层计数：信号 → 委托 → 成交，**三个分母不许混用**

`object.py` 把三件事拆得干干净净：

| 层 | 载体 | 字段 | 语义 |
|---|---|---|---|
| 信号 | 策略内部 | — | 闸门分母（**唯一合法的咬合力分母**） |
| 委托 | `OrderData` | `volume` / `traded` / `status` | 一次意图；`traded` 累计 |
| 成交 | `TradeData` | `tradeid` / `price` / `volume` | **一笔委托可拆 N 笔** |
| 在途 | `active_orders` | `ACTIVE_STATUSES` | SUBMITTING 也算（本地已报未确认） |

**为什么这么设计更好**：结构本身就在阻止你混分母。我方第 11 轮踩过 —— 用「笔数比」冒充咬合力，笔数比 99~108% 看着没问题，真实的**信号级放行率**只有 64~78%（「少做单被换一批单掩盖」）。vnpy 这套模型里 `OrderData.volume`（意图）和 `traded`（已完成）**天生两个字段**，你想混都混不了。

本轮落地为 `Funnel` 类，把口径写进方法名：`pass_rate()`（=orders/signals，**这才是咬合力**）、`fill_ratio()`（=fills/orders，另一个口径）、`bite_ratio()`（=1−pass_rate）、`gate_bite()`（咬合力必须 ∈ (0,100%)，端点 = 没测到）。

### D70 · 派生字段不能懒算：`available` 只在 `__post_init__` 算一次

`object.py:212-215`：

```python
def __post_init__(self):
    self.available = self.balance - self.frozen
```

之后 `balance` 改了、`frozen` 改了，**`available` 不动**。单次事件流里没事（每条 `AccountData` 都是新对象），但**一旦复用或缓存对象**，读到的就是上一刻的派生值。

**为什么这是坑而不是设计**：它把「快照语义 vs 实时间语义」藏在一个属性里。正确做法是 `@property`（现算）或字段名带时间戳（`available_at`）。我方 `report.py` 的 `cost_dominated` 也是派生物 —— 本轮一并做了口径自证（见第 7 节）。

### D71 · 接口下沉为**可调用属性**，而非继承

```python
oms_engine: OmsEngine = self.add_engine(OmsEngine)
self.get_tick: Callable[[str], TickData | None] = oms_engine.get_tick
```

**为什么好**：上层（GUI/App）只依赖「有个 `get_tick(str)` 能调用」，不依赖 `OmsEngine` 类型。换 OMS 实现、塞测试替身、加缓存装饰器，都不动调用方。代价是 IDE 跳转变难（类型靠注解）。

### D72 · 关闭顺序 = **先断生产者，再断消费者**

```python
def close(self):
    self.event_engine.stop()     # 先停事件引擎 → 不再有新 timer 事件
    for engine in self.engines.values(): engine.close()
    for gateway in self.gateways.values(): gateway.close()
```

**为什么好**：反过来的话，`engine.close()` 期间 timer 还在往队列里塞事件，消费者可能已析构 → 悬挂回调。我方 `core/events.py:333 stop(timeout=2.0)` 已有 `join`，但**MainEngine 的这种「先停总线」的显式顺序**此前没写进约定 —— 补进设计纪律。

## 5. 可复用代码片段

### 片段 1 · 分钟窗口判定（照抄算法，加断言）

```python
# 来源：vnpy/vnpy/trader/utility.py:281-319（update_bar_minute_window）
# 用途：不问「文档说合法吗」，直接问「稳态跨度对不对」
def simulate_minute_window(data_interval_min: int, window: int, n_bars: int = 400) -> list[dict]:
    fires, minute, children = [], 0, 0
    for i in range(n_bars):
        children += 1
        if (minute % 60 + 1) % window == 0:          # ← vnpy 原判定，一字未改
            fires.append({"index": i, "child_count": children,
                          "span_minutes": children * data_interval_min})
            children = 0
        minute += data_interval_min
    return fires

# 实测：simulate_minute_window(15, 16) 稳态 span=60（应 240）⇒ 1H 冒充 4H
```

### 对第 15 轮 P0-1「实盘 4543 笔 vs 回测 +2.1521%/笔」的**新线索**

## 11. 本轮踩到的真坑（写给下一轮的自己）

1. **断言写错时，失败的是断言不是被测代码**：首跑 3 个 ❌，两个是我自己的期望值算错（`minute_window_legal(15,4)` 的口诀判据误判、`gross_net_pair` 期望值算反），只有 1 个是真判据错。**判据要用操作定义，别抄文档口诀。**
2. **`raw.find(b"\n", i)` 命中的是 CRLF 里的 `\n`**：在它前面插行会把上一行切成 `\r\r\n`（lone CR），末尾行只剩 `\n`（lone LF）。正确写法是**在 `\n` 之后插入**（`raw[:j+1]`），并回读校验 `lone-CR == 0`。
3. **台账是 CRLF，不是 LF**：首版脚本断言 `b"\r\n" not in raw` 直接停手 —— 铁律 #2 救了一次。
4. **时区混用把 mask 全变 False**：`resample` 索引用 tz-aware，而 `_agg_bars` 的 `dt` 列是 tz-naive，`isin` 静默返回全 False（看起来像「0 个半桶」）。**0 与「没测」不可分，这条坑今天自己又踩了一次。**
