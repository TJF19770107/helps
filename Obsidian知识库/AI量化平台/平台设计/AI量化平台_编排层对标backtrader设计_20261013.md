## 二、backtrader `cerebro.py` 四条可迁移设计（D10~D13）

### D10 · 同源双引擎 + **档位差异显式声明**
`run()`（`:1030`）用 `_dorunonce / _dopreload / _dolive` 三个开关互钳：
```
if self._exactbars:  self._dorunonce = False          # 省内存 ⇒ 关向量化
if self._dolive:     self._dorunonce = _dopreload = False   # 实盘 ⇒ 两者全关
```
**外部印证**（BackTrader 中文文档）：
> 「事件和矢量化：**交易逻辑和经纪人始终基于事件运行**；如果可能，**指标的计算是矢量化的**。」

→ 结论：**向量化只是「指标计算」的优化，交易逻辑永远是事件驱动**。
→ 对我方：`core/backtest.py` 的 pandas 向量化只许存在于**指标层**；
   一旦涉及成交/风控/订单时序，必须走 `core/events.py` 事件总线。
→ 待做（P1）：`core/backtest.py` 增加 `stream=True` 逐 bar 模式，与向量模式做结果差异对照。

### D11 · 定时器绑**数据时钟**（`dt0`）★ 本轮已落地

## 三、本轮回填的实现细节

### 3.1 G1 · 含费闭式解
```
旧: qty = (equity × max_risk_per_trade) / |entry − stop|
新: qty = (equity × max_risk_per_trade) / (|entry − stop| + price×fee_rate×2 + price×slippage_rate×2)
```
- 直觉：把手续费/滑点**折算成等效止损点数**，与价格风险同量纲相加。
- 实测（止损距离 1000 / 价 50000 / 单边 0.1%）：**2.0 → 1.8182 张，超配 +10%**；
  止损越近超配越大：止损 0.25% 价格 → **+80%**；止损 1% → **+20%**；止损 5% → **+4%**。
- ★ **已知缺口**：`slippage_rate` 默认 **0 = 未启用** —— 滑点系数必须用实盘成交标定，我没有实盘日志，
  **不静默填假数**（H-011 已证「乐观偏差主因就是执行成本假设」）。

### 3.2 R7/G3 · 顺序锁定（挂单提交即占额度）
- 新增 `reserve_order()`（**过闸 + 占额度 = 一个原子动作**）/ `release_order()` / `release_fill()`（部分成交）。
- R2/R3 的可用额度计算里额外扣减 `pending_notional()`。
- 复刻 2026-10-12 血泪场景：余额 1000、两单各 601.2 →
  第二单被裁到 **398.8**（旧式会双双放行 = 1202.4 敞口）。
- ★ 回测口径局限（AtomCode Q2 确认）：回测里 reserve→成交几乎必然，
  实盘有拒单/部分成交/延迟 → **回测锁定的额度天然偏乐观**。需给回测撮合器注入拒单/部分成交率才能覆盖。

### 3.3 R8 · 令牌桶限流
- 时间源优先用事件时间 `ts`（回测确定性），缺省回退墙钟。
- **只约束增大敞口方向；减仓/平仓无条件豁免**（限流若拦平仓 = 爆仓加速器）。

### 3.4 E1/D8 · 双模 Clock
| 模式 | 定时器归属 | 特性 |
|---|---|---|
| 同步（回测） | `advance_clock(open_ms)` 由 BAR 时钟推进 | 确定性、可复现、无未来函数 |
| 异步（实盘） | 独立 `EventEngineTimer` 线程 | 准时，事件积压不影响（实测 42 次 vs 旧 0 次，最大迟到 1.0 ms）|
