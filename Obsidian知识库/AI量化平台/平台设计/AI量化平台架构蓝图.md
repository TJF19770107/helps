## 一、分层（目标七层）

```
┌─────────────────────────────────────────┐
│ 7 研究层  Research     因子挖掘 / 模型训练 / 参数搜索
├─────────────────────────────────────────┤
│ 6 风控层  Risk         仓位上限 / 回撤闸 / 熔断 / 相关性约束
├─────────────────────────────────────────┤
│ 5 执行层  Execution    下单路由 / 滑点控制 / 冰山 / 重试
├─────────────────────────────────────────┤
│ 4 策略层  Strategy     信号计算 / 组合 / 生命周期
├─────────────────────────────────────────┤
│ 3 回测层  Backtest     撮合模拟 / 手续费 / 延迟建模
├─────────────────────────────────────────┤
│ 2 数据层  Data         行情 / 订单簿 / 落库 / 增量更新
├─────────────────────────────────────────┤
│ 1 事件层  Event        统一事件总线（引擎的心脏）
└─────────────────────────────────────────┘
```

**第一性原理追问**：为什么一定要「事件驱动」？
→ 因为回测与实盘必须共享同一条代码路径，否则回测再好也是自欺。事件总线是让「同一策略代码既跑回测又跑实盘」的**唯一低成本手段**。（此条待用 vnpy `trader/engine.py` 与 nautilus `core` 的实际实现验证。）

## 六、已验证设计（v0.2 新增 · 来自 2026-10-08 源码精读）

> 以下条目**已由真实源码读出**（附 `文件:行范围`），不再是设想；但「搬进本平台」这一步仍属待做。

### 六-1　策略层：目标仓位驱动（源自 `vnpy_ctastrategy/template.py:435-472`）
- **结论**：`CtaTemplate.on_bar/on_tick` 抽象**可以直接承载**黑马策略信号；且 `TargetPosTemplate` 提供的「目标仓位」范式优于事件驱动逐笔下单。
- **为什么采纳**：`pos_change = target_pos - self.pos` 天然幂等 —— 重复信号不会重复开仓，断线重放不会双开。
- **落地动作**：黑马 EA / 策略层改为「信号 → 目标手数 → 差额下单」，并保留「有活动委托先撤再发」。
- **状态**：✅ 设计已验证（源码在），⬜ 平台落地未做。

### 六-2　执行层：实盘网关四约束（源自 `vnpy_binance/linear_gateway.py`）
- **结论**：实盘网关的关键不是「能下单」，而是四条工程约束：
  1. **时间偏移校正**（`404-411`）—— 防签名 timestamp 超窗被拒（-1021），成本 1 次启动请求。
  2. **本地 clientOrderId + reqid→回调双映射**（`455, 1567-1601`）—— 防「下了单不知道下没下」。
  3. **断线自动重订阅**（`1226-1250`）—— 防「重连了但没重订阅」的静默丢行情。
  4. **历史数据剔除未闭合 K 线**（`913-915`）—— 防回测 look-ahead bias。
- **数据层限流实证**：`query_history` 每页 1500 根、页间 `sleep(0.5)`（`830, 911`）；可复用到现行币安数据通路。
- **状态**：✅ 设计已验证（源码在 + 已抽成可复用模块 `binance_gateway_patterns.py` 自测 15/15 PASS），⬜ 平台落地未做。

### 六-3　架构取舍：同构复制 > 强行抽象（源自 vnpy_binance 4 网关并列）
- **结论**：币安现货/合约/币本位/组合四套 API 字段差异大，vnpy 选择「复制模板改差异」而非抽公共基类。
- **启示**：本平台接多交易所/多品种时，**先复制再差异化**，避免过早抽象出一堆 `if 现货/合约`。
- **代价（诚实记录）**：改一处 bug 要改 4 处 —— 用 diff/sed 工程手段缓解。

## 七、诚实边界

- 本蓝图**尚未生产运行任何一条**。它是「学习靶子」，不是交付物。
- v0.2 的「已验证设计」仅指**源码层面验证了设计存在且合理**，**不等于本平台已实现**。
- 「对标一流对冲基金」的具体含义是：**对标它们的工程约束与风控纪律**，不是对标它们的收益率数字。我们没有它们的资金、机位、数据源和团队。
- 黑马策略声称的高倍数表现，属于**待独立复核**项，不因本蓝图而确认。
