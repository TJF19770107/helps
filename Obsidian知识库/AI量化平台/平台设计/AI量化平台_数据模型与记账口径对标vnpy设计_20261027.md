# AI量化平台 · 数据模型与记账口径层 · 对标 vnpy 设计

> 来源：第 16 轮夜学（2026-10-27）。前 15 轮的设计文档按「层」排（事件层 / 风控层 / 撮合层 / 订单对账层 / 成本档位层），
> 本轮补的是**所有层共用的地基**：**一根 bar 是不是真的那根 bar**、**一笔账记的是毛还是净**、
> **一个「砍掉了多少」的分母该是谁**。

## 一、本轮为什么改读「数据模型」而不是「引擎」

vnpy 的功能面（CTA / 回测 / 网关）前几轮已经从别的仓库对标过。它真正**别人抄不走**的东西是三处：

| 位置 | 东西 | 为什么值得抄 |
|---|---|---|
| `trader/object.py` | OrderData / TradeData / PositionData / AccountData 四个数据类 | **手续费字段完全不存在** —— 成本是外部注入，不是数据本体 |
| `trader/engine.py` OmsEngine | `orders` / `trades` / `active_orders` 三张表 | **信号 / 委托 / 成交三层天生分开** |
| `trader/utility.py` BarGenerator | tick→1m→窗口 bar | 中文圈最常被抄的聚合器，而它有静默降级缺陷 |

我方平台对应位：`core/backtest.py`（撮合与净账）+ `core/report.py`（毛净并列）+ `ai_quant_lab/hypothesis_runner._agg_bars()`（聚合）。
本轮实测出三处**与我方同形**的问题，全部补了可断言检查。

## 二、六条落地设计（D67~D72）

### D67 · 周期聚合合法性用「操作定义」判，不许抄文档口诀

- **vnpy 现状**：`utility.py:315` `if not (bar.datetime.minute + 1) % self.window:` —— 按**分钟号取模**判窗闭合；
  docstring（179-180）写「x 必须整除 60」，但**代码零校验**。
- **实测缺陷**：`15m + window=16`（想合成 4H）→ 触发点 `[15,31,47]`，稳态跨度 **60 分钟**（应为 240），
  首根仅 2 个子 bar，稳态 4 个 ⇒ **静默产出 1H bar，周期小 4 倍，无异常无日志**。
- **我方现状**：用 `pandas.resample("4h")`（epoch 锚定，对齐正确），但**没有任何断言证明它真的合成了 4H**。
- **落地**：`vnpy_oms_accounting.minute_window_legal(data_interval_min, window)`，
  判据 = `稳态跨度 == data_interval_min × window`。
- ⚠️ **口诀会误判**：`15m + window=4` 虽 `4 % 15 != 0`，实测跨度正好 60 → **合法**。所以只能用操作定义。

### D68 · 聚合完整性独立审计：空桶能丢，半桶丢不掉

- **我方现状**：`_agg_bars()` 里 `dropna(subset=["open","close"])` + `agg[volume>0]` ——
  空桶被丢掉（对），**半桶被当完整桶**（漏）。
- **后果**：半桶的 `high/low` 低估 → 突破信号少报；`volume` 低估 → `sig_vol` 量比失真。**全历史没有一行代码检查过**。
- **落地**：`audit_buckets(df, rule, expected_children)` → 返回 total / complete / partial / partial_ratio / worst_partial / children_hist。
- **实测（四只标的全历史）**：半桶 **22 个 / 57,927 桶 = 0.027%~0.047%**；ETH 有一桶**只有 1 根 15m 子 bar**。
- **判定：不咬，但必须计数。** 「0 个半桶」与「没测」不可分（第 13 轮 `qty_zeroed=0` 的翻版）。

### D69 · 三层计数（信号 / 委托 / 成交）在数据结构层就分开

- **vnpy 结构**：`OrderData.volume`（意图）+ `OrderData.traded`（累计成交）+ `TradeData`（一笔委托可拆 N 笔）
  + `ACTIVE_STATUSES={SUBMITTING,NOTTRADED,PARTTRADED}`（**SUBMITTING 也算在途**）。
- **为什么重要**：我方第 11 轮踩过 —— 用「笔数比」冒充咬合力，笔数比 99~108% 而真实信号级放行率只有 64~78%
  （「少做单被换一批单掩盖」）。vnpy 这套模型根本不给混的机会。
- **落地**：`Funnel` 类，方法名即口径：
  - `pass_rate() = orders / signals` —— **唯一合法的咬合力分母**
  - `fill_ratio() = fills / orders` —— 另一个口径，**不许当咬合力**
  - `bite_ratio() = 1 − pass_rate()`
  - `gate_bite() → 0 < bite < 1` —— 端点 = **没被测到**（第 13 轮纪律）

### D70 · 派生字段不能懒算；是快照就必须在名字里写清

- **vnpy 反例**：`object.py:212-215` `available = balance - frozen` 只在 `__post_init__` 算一次。
  之后改 balance / frozen，`available` 不动。单次事件流没事，**复用或缓存对象就读到上一刻的值**。
- **我方同形**：`report.py` 的 `cost_dominated` 是派生物；更严重的是 `gross.total_return` 与 `net.total_return`
  **同源**（都取自同一条权益曲线）—— 并列展示会被读成「毛 vs 净」。
- **落地**：`build_cost_account()` 新增 `total_return_basis="net_of_fee"` + `total_return_is_shared=True`，
  并在 `gross`/`net` 两块各加 `n_trades`。
- **原则**：**不假造一份毛总收益**。假造比缺更糟（D65）。

### D71 · 接口下沉为「可调用属性」，而非继承

- `MainEngine.init_engines()`（149-177）把 OmsEngine 的 19 个方法**绑成 MainEngine 的属性**：
  `self.get_tick = oms_engine.get_tick` …
- **好处**：上层只依赖「有个 `get_tick(str)` 可调用」，不依赖 `OmsEngine` 类型 ⇒ 换实现 / 塞测试替身 / 加缓存装饰器，都不动调用方。
- **对我方**：`lab_bridge.get(name)` 是同一思想的弱化版；`live.py` 的「报单唯一入口」可借此再收一层。

### D72 · 关闭顺序 = 先断生产者，再断消费者

- `MainEngine.close()`（321-335）：`event_engine.stop()` → `engines.close()` → `gateways.close()`。
- **理由**：反过来的话，engine 关闭期间 timer 仍在往队列塞事件，消费者可能已析构 → 悬挂回调。
- **我方**：`core/events.py:333 stop(timeout=2.0)` 有 join，但**「先停总线」的显式顺序**此前没写进约定 ⇒ 本轮补进纪律。

## 四、实证结论（三条假设的落地结果）

| 假设 | 状态 | 关键数字 | 对平台的处置 |
|---|---|---|---|
| **H-031** 费率口径 | ✅ 已验证 4/4 | Δ净单笔 **+0.1006~0.1023pp**；成本拖累 0.2012~0.2046 → **0.1006~0.1023pp**；笔数不变 | 第 15 轮所有「费率吃掉 pp」**读作减半**；`r*` **翻倍至 >2%** |
| **H-032** 单笔 vs 总收益 | ✅ 已验证 1/4 | DOGE 净单笔 **+0.5732%**、总收益 **−68.3%**、胜率 16.53%、回撤 99.2% | A/B 表默认四列必挂；「单笔改善」**不构成可交易证据** |
| **H-033** 4H 半桶 | ✅ 已验证 4/4 | 半桶 22/57,927（0.027%~0.047%）；剔除后收阳率 Δ **−0.0064~+0.0039pp** | 不改聚合链，但把 `audit_buckets()` 挂进质检区 |

### 由此收紧的一条旧结论

第 15 轮写「降费要按标的分，DOGE 是成本敏感型」。
本轮把费率腰斩后 **DOGE 仍 −68.3%** ⇒ **降费对 DOGE 无效**。
真正的结论是：**DOGE 的问题不在成本，在信号本身**（或标的本身的低波动不适合这套突破逻辑）。
⇒ 下一步不该再在 DOGE 上做费率敏感性，应该**单独给它换入场逻辑**，或者**直接把它踢出标的池**。
