# AI量化平台 · 多市场组合网关层对标 vnpy_binance 设计（2026-10-20）

> **一句话**：这一轮补的不是「多一个市场」，而是**订单生命周期的前 3 毫秒** ——
> 「我要发」→「发出去了」→「我不知道发没发出去」。我平台此前把这三件事当一件事。

---

## 一、缺口定位（先量化，再动手）

| 层 | 现状（本轮前） | 对标后应有 | 差距类型 |
|---|---|---|---|
| 执行层入口 | `core/live.py` 142 行，**只有信号计算，无报单入口** | 报单唯一入口 + 过闸 + 占额度 | **结构性缺失** |
| 订单状态 | `risk.PendingOrder` 只有「在途 / 释放」两态 | 7 态（submitting/alive/partial/filled/cancelled/rejected/unknown） | **状态维度不足** |

| 多市场路由 | 无（只有 UM 一种） | 按 vt_symbol 后缀 → 端点 | 暂不需要（我方只做 UM） |

## 二、四条设计（D25~D28）+ 一条反例（D29）

### D25 · 端点路由下沉到网关
**做法**：`get_market_type(symbol) -> {um, cm, margin}` 是纯函数，`send_order` 只做一次分支选 `path`。
**为什么**：路由是基础设施事实，不是策略决策。策略层一旦硬编码端点，换市场就要改最难回归测试的代码。
**代价**：上游最后 `return UM` 是 **fail-open** —— 拼错后缀会静默路由到永续。
**我方取舍**：`submit_order()` 先查合约（无则拒绝），**fail-closed**；路由字段暂留 `client_order_id`，`endpoint` 待真实适配器补。
**状态**：⚠️ 部分落地（fail-closed 已落，endpoint 字段未落）

### D26 · 先落库再发请求（submit-then-request）
**做法**：`create_order_data` → `on_order(SUBMITTING)` → `add_request`。
**为什么**：崩溃点最可能落在「已发出去、回报未回」的窗口。若等回报才建订单，此刻本地**不存在**该订单 → 重启后无法对账。
**实证锚点**：`portfolio_gateway.py:704-742`。
**我方落地**：`live.submit_order()` 在调 `risk.reserve_order()` **之前**就生成 `order_id`（否则返回 ID 与 `pending` key 不同 → 额度永久锁死，本轮真 bug）。
**状态**：✅ 已落地（`core/live.py`，自测 4/4）

### D27 · 本地 ID = 交易所幂等键
**做法**：`newClientOrderId = 本地 orderid`；撤单 `origClientOrderId = 本地 orderid`。
**为什么**：省掉「本地 ↔ 交易所」双写映射表 —— 双写必然不一致，不一致就必然产生幽灵订单。
**我方落地**：`submit_order()` 返回 `{order_id, client_order_id}` 同值；`on_order_cancel(order_id)` 直接可撤。
**状态**：✅ 已落地（无真实适配器，语义已对齐）

### D28 · 两类失败必须分开（拒单 vs 未知）
| 事实 | 信号 | 正确动作 | 错误动作的后果 |
|---|---|---|---|
| 交易所明确拒单 | HTTP 4xx/5xx（`on_send_order_failed`） | **释放额度** | 若保留 → 额度泄漏 |
| 网络异常/超时 | exception（`on_send_order_error`） | **保留额度 + 置 UNKNOWN + 等对账** | 若释放 → **重复开仓** |
**为什么**：把「不确定」当「失败」是实盘重复开仓的第一大来源；把「失败」当「不确定」则额度永不释放、平台自锁。
**我方落地**：`ai_quant_lab/20261020.../portfolio_gateway_patterns.py` 的 `OrderLifecycle`：
`on_reject()` 释放 / `on_error()` 保留 / `reconcile_missing()` 收口（只允许从 UNKNOWN 迁出）。
**状态**：✅ 抽象层已落地（13/13）；实盘路径待适配器

### D29 · **反例**：持仓归零必须推送
**上游事实**：`:920` / `:941` 两处 `if position.volume: on_position(...)` —— **平光不推送**。
**后果**：订阅端持仓簿残留陈旧非零仓位 → 组合敞口（R3）越来越松，且**不自愈**。
**我方对照**：`risk.apply_fill()` 净额归零时保留 `Position(qty=0)` 条目（`gross_exposure` 计 0），
`PositionBook.apply_fill()` 无条件 append `{"flat": True}` 事件（自测 `flat_pushed`）。
**状态**：✅ 已落地 + 反向断言

## 三、G2：风控状态机从三态升四态（← 本轮真正的平台改动）

### 3.1 为什么必须改（不是优雅问题，是安全性问题）
原设计：`HALTED` → 人工 `reset()` → 立刻**100% 仓位**。
这在语义上等于：**被回撤闸打停之后，唯一的恢复方式是把仓位原样再赌一次**。
回撤闸拦下的是「策略在当前市场状态下失效」，而 `reset()` 并没有验证「失效是否结束」。

### 3.2 新状态机
```
NORMAL ──(回撤≥预警线)──▶ WARNING ──(回撤≥闸门)──▶ HALTED
   ▲                          │                      │
   │                          └──(回撤回落，仅此一路)─┘
   │                                                 │
   └──(累计 ≥1R 盈利)── RECOVERING ◀──begin_recovery()┘
                            │
                            └──(连亏熔断/回撤闸)──▶ HALTED
```
- **HALTED 是终态**：只有 `reset()`（一步回满，需人工确认）或 `begin_recovery()`（半开）能出。
- **RECOVERING 半开**：开仓数量 ×`scale`，`scale = 0.5 + (0.1−0.5)×min(1, 回撤/闸门)` —— 回撤越深开得越小。
- **晋级判据 = 累计 1R**（1R = 权益 × 单笔风险预算），**不是「连赢 N 笔」**：
  半开状态下单笔金额被压到 0.5 倍，用绝对金额判「盈利」会系统性偏小，而亏损按全口径计 → 判据不对称。
- **减仓/平仓在 RECOVERING 下无条件放行、不缩放**（沿用「闸只缩不放」铁律）。

### 3.3 AtomCode 复核（200 / 122.9s / glm5.3-flash）抓到并已修的漏洞
| 问题 | 原设计 | 修法 | 自测 |
|---|---|---|---|
| **Q1 绕过路径** | `reduce_only` 是**调用方声明**，声明即豁免 → 「平旧仓+开新仓」整包声明即可绕过 RECOVERING/HALTED | 加**持仓交叉校验**：持仓簿无该标的 → 保留豁免；有但数量 > 持仓 → 声明不可信，退回数量推断 | `G2超量reduce_only不豁免` |
| **Q2 统计陷阱** | 「连赢 2 笔」在 15m/持仓数百根下 ≈ 抛硬币，且 0.5 倍仓位导致金额口径不对称 | 改 **R 归一**（pnl ÷ 风险预算），累计 ≥1R 晋级；亏损即归零（不抵消） | `G2R归一晋级` |
| **Q3 系数** | 常数 0.5 | `clamp` 线性式随回撤深度递减（0.5→0.1） | `G2系数随深度` |

**未采纳并写明原因**：Q2 建议的「滚动 N 笔胜率×盈亏比 > 0」需至少 30 笔样本，我方单标的 15m 全历史在恢复期窗口内**凑不到** → 留作 P2（需先有更长实盘样本）。

## 五、诚实边界

1. 本轮**没有任何收益数字**改进。G2 的价值是「恢复期不让你一步满仓」，属**风险约束**，不是收益来源。
2. `live.py` 仍**不能真的下单**（无 API Key、无适配器）。把它当作「门」，不是「腿」。
3. H-020 的结论是**证伪**（let_run 0/4），它只说明「越松越好」不成立，**不能反推**「现有 10/8/5 就是最优」。
4. H-021 的结论带**咬合力警告**：成交率 100% → 测到的只是降费率，**不是**限价单取舍。
5. AtomCode 是 `glm5.3-flash`（免费档），它的建议**一律先当假设**，本轮三条采纳都配了自测断言才进代码。
