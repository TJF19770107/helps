## 一 · 标准化（把"研究"变成"可复用的判断标准"）

### 1.1 建立「三层事实」标准：源码事实 > 官方文档 > 我的记忆

本轮所有结论的优先级：

| 层 | 来源 | 本轮实例 |
|---|---|---|
| **L1 源码事实** | 直接读 GitHub raw 的 .py / .toml / Dockerfile | `QTDockerEnv` 在 `utils.py` 里实例化；数据格式被 `generate.py` 写死；`health_check` 默认查 Docker |
| **L2 官方文档** | README / readthedocs | RD-Agent 只支持 Linux；DeepSeek 需 `deepseek/` 前缀；成本 <$10 |
| **L3 我的记忆** | 训练语料 | 「qlib 只支持到 3.12」—— 这条**被源码验证为真**（pyproject classifiers）；但「RD-Agent 有官方 conda 后端可零改动切换」是**记忆幻觉，源码证伪** |

**标准**：凡涉及"能不能装/能不能跑/默认值是什么"，必须落到 L1。
本轮为此读了 8 个源文件（qlib pyproject、rdagent pyproject/requirements、env.py、utils.py、cli.py、Dockerfile、generate.py、evolving_strategy.py）。

### 1.2 建立「数据能力边界」标准：先量数据，再谈方案

**新增铁律**：
> 任何"引入新框架"的方案，第一件事是**量出本方数据能喂给它多少**，而不是先研究框架能力。

本轮量化结果：

| 指标 | 值 | 方案含义 |
|---|---|---|
| 唯一品种 | 76（88 CSV 去重后） | 截面宽度上限 |
| 日线面板行数 | 52,302 | 截面轨总样本 |
| 历史中位数 | 438 天 | 一半品种不到 1.2 年 |
| ≥1000 天的品种 | **11 个** | 长历史层 |
| **宽度≥30 的交易日** | **553 天** | **截面因子的真实样本窗口** |
| 真实 bar 占比 | 27.26% | 填充风险面 |

### 1.3 建立「过拟合防线」标准：三闸齐上，缺一即废

| 闸 | 防什么 | 判据 | 不能替代的原因 |
|---|---|---|---|
| Purged K-Fold + Embargo | 标签泄漏 | 挖空比例 | 防训练/测试边界互相污染 |
| Deflated Sharpe (DSR) | **多重比较** | >0.95 | 把"试了多少次"折进阈值 |
| PBO (CSCV) | **选择过程的过拟合** | <0.5（实务 <0.35） | 直接模拟"训练最优在测试集垮掉"的概率 |

**标准**：一个新因子入库，必须三闸全过。**不允许"DSR 过了就放行"**。

### 1.4 建立「校验器必须反测」标准（本轮最贵的一条）

> **一个没做过反测的校验器，等于没有校验器。** 它可能永远返回 PASS。

反测设计：必须有**阳性样本**（真信号，应放行）和**阴性样本**（纯噪声，应拒绝），且**区分力要量化**（PBO gap）。

## 二 · 模块化（把"一个大方案"拆成能独立验的零件）

### 2.1 数据层 `build_panel_h5.py`
- **职责**：88 个 15m CSV → 日线 → `MultiIndex(datetime, instrument)` 的 h5
- **关键设计**：**完全不依赖 qlib**。因为 qlib 要 Python≤3.12、项目环境是 3.13 —— 若造数据也要过 qlib，本地链路第一步就断
- **输出**：`daily_pv_1d_all.h5` / `_debug.h5` / `.parquet` / `_manifest.json`

### 2.2 审计层 `audit_panel.py`
- **职责**：把「并集+填充」混成一件事的三态拆开算
- **输出**：`panel_audit.json` / `panel_audit.md` / **`tradable_mask.parquet`**
- **铁律落实**：尾部冻结一律 `False`，与「冻结 ≠ 停牌，绝不放行冻结」对齐

### 2.3 裁决层 `validate_oos.py`
- **职责**：三闸 + 反测 + **唯一允许改 state 的地方**
- **关键**：`pending → promoted` 只能由它写，`export_factors.py` 只能写 pending

### 2.4 出库层 `export_factors.py`
- **职责**：扫 workspace → 内容哈希去重 → 追加式台账 → 可选写 P09
- **铁律落实**：追加式 + run_id（2026-10-29 hypothesis_runner 覆写事故的教训）

### 2.5 部署层（3 文件 + 1 脚本）
- `Dockerfile.rdagent-cpu`：**换掉官方 CUDA 基础镜像**（本机无独显，白扛 3G）
- `docker-compose.yml`：无 DinD 版 + 可选 UI profile + 资源限制 + 非 root
- `entrypoint.sh`：**运行时 import rdagent 读真实数据目录**，不猜默认值
- `run_loop.sh`：把「必须先 prepare」「必须设 OMP 线程」「必须带 --path」三件事固定下来

## 三 · 自动化

### 3.1 容器一键
```bash
./scripts/run_loop.sh smoke          # 端到端冒烟（4 项断言）
./scripts/run_loop.sh factor 1       # 探路一轮
./scripts/run_loop.sh factor 5 --path=...   # 续跑
```
`run_loop.sh` 内置三道前置检查：`.env` 存在且无 REPLACE_WITH 占位符、面板 h5 存在、docker CLI 存在。**不满足就不开跑**（省得烧 token 白跑）。

### 3.2 数据一键
```bash
python scripts/build_panel_h5.py --end-date 2026-10-22
python scripts/audit_panel.py
```
两个脚本幂等、可重复跑、产出带时间戳与指纹。

### 3.3 因子一键
```bash
python scripts/export_factors.py            # 幂等，重复跑新增 0 条
python scripts/export_factors.py --to-kb    # 顺带写 P09
python scripts/validate_oos.py --selftest   # 先验校验器自身
```

### 3.4 交给汤小龙的循环（设计稿，见方案文档 6.2）
```
前置：指纹校验 + mask 存在性
每轮：loop 1 → 出库 → 三闸 → entry_mask 复核 → 落库
硬闸：宽度<30 不参与 IC / PBO≥0.5 全轮拒 / 连续失败 3 次即停
```

### 4.1 从「跑框架」到「判框架」—— 本轮真正的智能增量

**L3 是本轮最有价值的产出**：如果我只是把方案写得漂亮，你会以为"接上就能挖出好因子"。而实测告诉你：**553 天，跑 20 轮就是 100 次多重比较，统计功效根本不够**。这个判断比任何工程代码都值钱。

### 4.2 决策智能化：把"要不要做"变成可计算

```
可用样本 553 天
× 平均截面宽度 ~50  ≈ 2.7 万个截面样本点
候选因子 100 个（20 轮 × 5）
⇒ Bonferroni 下需单次 p < 0.0005
⇒ 553 天的统计功效 ≈ 不足
⇒ 结论：RD-Agent 只能当「假设生成器」，不能当「策略发现器」
```

这个推导链是可以复用的模板：**样本量 → 比较次数 → 校正后阈值 → 功效判断**。

### 4.3 诚实边界智能化（写进 UI 而不只写进文档）

方案文档 5.4 那张「本轮实测到什么程度」的表，把 **✅ 实测通过 / ❌ 未做** 逐项列出。
这是龙虾五步法的要求：**用户看到的是页面/文档，不是我的内心活动**。把边界写在显眼处，比藏在附录里诚实一万倍。

## 五 · 踩到的真坑（本轮六个，全是自己挖出来的）

### 坑 1 ★★★ DSR 的 `sr0` 量纲错误 —— 会把强真信号也拒掉

**现象**：反测 A 组（含稳定 alpha 的强信号，日频夏普 0.1465）被判 `pass=False`。

**根因**：`sr0 = sqrt(1.0) * [...]`，写死方差=1，等于假定「日频夏普的标准差是 1」。
算出来 `SR0 = 2.19` —— 意思是日频夏普要 2.19（年化 41）才算显著。

**修法**：`sr_variance` 必须由调用方传**同批策略夏普的实测方差**。修后 `SR0 = 0.1159`。

**可复用判据**：
> `SR0` 的量级必须能和你的 `SR` 直接比。**差了 10 倍以上，先怀疑量纲，别怀疑数据。**

### 坑 2 ★★★ 反测判据本身设计错了 —— 等于要求硬币必须立起来

**现象**：反测第 4 条「B 组纯噪声应被 PBO 拒绝」失败，B 组 `PBO=0.4246`。

**根因**：**PBO 在纯噪声下的期望就是 0.5**。单次实现落在 0.42 完全正常。
用「B 组 PBO≥0.5」当判据，就是要求随机数必须恰好大于等于期望值。

**修法**：改成判**整体裁决**（A 组 promoted / B 组 rejected）+ 判**区分力**（PBO gap > 0.10）。
修后：A=0.0833 vs B=0.4246，gap=0.341，4/4 通过。

**可复用判据**：
> 反测的判据必须放在「**组合裁决**」层，不能放在「单个指标阈值」层。
> 单个统计量在零假设下都有方差，拿期望值当硬阈值必然随机失败。

### 坑 3 ★★ 硬编码"主流币名单"，结果四个根本没数据

**现象**：第一版 `CORE_POOL = [BTC, ETH, BNB, SOL, DOGE, XRP, ADA, LTC]`，跑完报「核心池缺失 4 个」。

**根因**：`SOLUSDT / XRPUSDT / ADAUSDT / LTCUSDT` **在这 88 个 CSV 里根本不存在**。
凭"主流币应该有"写配置 = 幻觉。

**修法**：改成按实测 `span_days >= 1000` 自动分层，长历史层实测为
`BTC/ETH/DASH/ZEC/BNB/IOST/DOGE/GTC/QNT/MAGIC/LSK` 共 11 个。

**可复用判据**：
> **任何"名单类配置"都必须由实测生成，不能由常识填写。**
> 报「缺失」时，先查数据源有没有，再怀疑代码。

### 坑 4 ★★ 末尾 4 天截面宽度从 76 塌到 6 —— 差点当正常数据用

**现象**：`max=76` 但 `末日只有 6 个品种`，看起来矛盾。

**根因**：各 CSV 的末根日期分**三批**：63 个到 10-22、**7 个到 09-04（早停 48 天）**、6 个到 10-26。
最后 4 天只有那 6 个品种有数据 ⇒ 宽度塌落。

**修法**：加 `--end-date 2026-10-22` 截断（变更测试：52,326 → 52,302，正好裁掉 6×4=24 行）。
并按「宽度≥中位一半」定位出**可用窗口上界**。

**可复用判据**：
> 面板类数据必须看**宽度的时间序列**，不能只看 `max()` / `tail()`。
> 「最大宽度 76」和「末日宽度 6」可以同时为真。

### 坑 5 ★★ `$factor` 列缺失会让 qlib handler 静默 KeyError

**现象**：`generate.py` 的字段列表是 `["$open","$close","$high","$low","$volume","$factor"]`。

**根因**：`$factor` 是 A 股的**复权因子**。币圈没有复权概念 —— 直觉上"这列不适用，去掉"。
但 qlib 的 handler 是**按列名硬取**的，缺了就 KeyError，而错误信息**不会告诉你"因为币圈没复权"**。

**修法**：无条件给一列 `$factor = 1.0`。

**可复用判据**：
> 对接外部框架时，**"这列对我们无意义" ≠ "这列可以不填"**。
> 先按它的契约把位补齐（填中性值），再考虑语义。

### 坑 6 ★ 环境版本死角：项目 3.13，框架要 ≤3.12 / ≤3.11

**现象**：`quant_env` = Python **3.13.14** + numpy 2.5.3 + pandas 3.0.6。
pyqlib classifiers 最高 3.12，RD-Agent 最高 3.11。

**判断**：不是"装一下试试"的问题，是**必炸**。而且**绝不能在 quant_env 里试** —— 会污染现有 16 模块的依赖（numpy 2.5 → 若降级到 <2，`core/` 全部模块可能炸）。

**修法**：三套并行（本地 3.11 venv / 本地 Docker / CNB），**quant_env 一行不动**。

**可复用判据**：
> 引入新框架前先读它的 `classifiers` 和 `requires-python`，与现有环境**列表对照**。
> 只要目标 Python 版本不在对方的 classifiers 里，就不要尝试 pip install。
