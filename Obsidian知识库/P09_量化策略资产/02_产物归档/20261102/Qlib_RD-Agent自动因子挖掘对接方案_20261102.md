## 二 · 完整流水线七步原理（对应本项目的改造点）

> 下图的七步就是 RD-Agent(Q) 论文里的 `Quantitative Finance Pipeline`：
> 数据采集 → 数据预处理 → 因子 R&D → 因子剪枝 → 模型 R&D → 模型训练 → 回测 → 金融分析（闭环）。
> 注意它是个**环**：金融分析的结果回灌给因子 R&D 和模型 R&D，这就是「交替进化」。

### 2.1 步骤一：数据采集（Data Acquisition）

**Qlib 原生做法**：`scripts/get_data.py` 拉 yahoo/baostock 的 A 股日线，`dump_bin.py` 转成 qlib 的 **`.bin` 自定义二进制格式**（`features/<instrument>/<field>.day.bin` + `calendars/day.txt` + `instruments/all.txt`）。

**为什么是自定义二进制**：Qlib 的回测与表达式引擎是**列式按需读取**的 —— 一次回测要读几百个字段 × 几千个标的，CSV 的解析开销会成为瓶颈。`.bin` + 内存映射让「取某字段某时间窗」变成一次指针偏移。

**RD-Agent 更懒**：它不要 `.bin`，直接要 `daily_pv.h5`（HDF5，`key="data"`）。因为它的 factor 代码只需要 OHLCV 六列做表达式计算，不需要 qlib 全套基础设施。

**本项目改造点**：
- 已实现 `build_panel_h5.py`：**88 个 15m CSV → 日线 → MultiIndex h5**，全程不依赖 qlib。
- 这条设计不是偷懒，是**必需**：qlib 要 Python≤3.12，而项目环境是 3.13 —— 如果造数据也要过 qlib，整条链路在本地第一步就断。
- 已验证：`daily_pv_1d_all.h5`（52,302 行 / 2.7MB）+ `daily_pv_1d_debug.h5`（36,430 行），格式契约 3/3 通过。
- **`$factor` 必须存在**（币圈无复权，一律填 1.0）。这是最隐蔽的坑：缺这一列，qlib handler 直接 KeyError，而错误信息不会告诉你"因为币圈没有复权概念"。

### 2.2 步骤二：数据预处理（Data Processing）

**原理**：qlib 用 **Handler** 把原始 OHLCV 加工成「特征矩阵 + 标签」：

- `Alpha158`：158 个因子，手工设计，分 9 类（K 线形态 KMID/KLEN/KUP 等、价格位置 ROC/MA 比、成交量、波动率、量价相关性、时序特征、滚动回归残差……）。绝大多数是**在单标的时序上算的**，但归一到截面使用时再做 `CSRankNorm`（截面排序归一化）。
- `Alpha360`：360 个因子，就是「过去 60 天 × 6 字段」的原始价格序列，几乎不做加工，让模型自己学。
- **标签**：默认 `Ref($close, -2)/Ref($close, -1) - 1`，即「**T+2 收盘 / T+1 收盘 - 1**」。为什么不是 T+1？因为 A 股 T+1 交易制度下，T 日收盘决策只能 T+1 开盘买，所以标签要延一天。**这个细节币圈不适用**（24/7 T+0），直接照抄会人为丢掉一天 alpha。

**本项目改造点**：
- 标签必须改。币圈应改成 `Ref($close,-1)/$close - 1`（次日收盘/今收盘），甚至用 `Ref($vwap,...)` 避免收盘价噪声。
- 归一化必须改。`CSRankNorm` 依赖截面宽度 —— 在宽度只有 1~10 的早期样本上，归一化后的值**在品种间完全不可比**。这是本项目最需要自定义的一处。
- **`$factor` 与 `$vwap`**：Alpha158 的 `VWAP0` 类因子要 `$vwap`，我们的面板没给。要么补一列（`quote_volume/volume` 就有），要么关掉那批因子。

### 2.3 步骤三：因子挖掘（Factor R&D）★ 这是 RD-Agent 的真正价值

**这是唯一值得为 RD-Agent 付出部署代价的一步。** 它的机制是 **CoSTEER**（Collaborative evolving strategy）：

```
LLM 提假设（factor proposal）
   ↓ "20 日动量与波动率之比在震荡市有均值回复特性…"
LLM 写代码（factor implementation，JSON mode 强制结构）
   ↓ class XxxFactor: def calc(...): return Mean($close,20)/Std($close,20)
沙箱执行（QTDockerEnv / LocalEnv）
   ↓
执行反馈 → 报错就带着 traceback 回灌给 LLM 重写（最多 10 次）
   ↓
成功 → 存为 knowledge（含代码 + 反馈 + 相似度 embedding）
   ↓
下一轮：检索"相似因子已实现过什么、踩过什么错" → 避免重复造轮子
```

**真正值钱的是「执行反馈闭环 + 跨轮知识复用」**，不是"LLM 会写代码"。
普通做法（人工写 prompt 让 GPT 生成因子表达式）没有这个闭环：报错了没人修，修好了不记忆，下一轮还会犯同样的错。

**本项目改造点**：
- **prompts.yaml 是核心资产**：`rdagent/scenarios/qlib/prompts.yaml` 里的场景描述（`get_scenario_all_desc`）定义了「告诉 LLM 我们是什么市场、有什么字段」。要换成币圈语义（24/7 交易、无涨跌停、永续资金费率、高波动、长尾归零）。
- **不换 = LLM 会按 A 股逻辑想因子**（比如"涨停板后的溢价""财报期效应"），产出 100% 不可用。

### 2.4 步骤四：因子剪枝（Factor Pruning）

**原理**：两处剪枝。

1. **CoSTEER 内部去重**：新因子与历史因子的代码/embedding 相似度过高 → 丢弃。防「20 日动量」被改名成「月内动量」重复入库。
2. **多因子组合选择**：RD-Agent 的 factor pool 到 model 阶段会用 `feature selection`（LightGBM 的 feature importance 或 qlib 的 `select_feature`）筛掉低贡献因子。

**论文关键数字**：RD-Agent(Q) 用**比基准因子库少 70% 的因子**拿到约 2× ARR。所以剪枝不是降本手段，是**提效手段** —— 因子越少，过拟合面越小。

**本项目改造点**：
- 去重必须加**语义层**：代码哈希只能抓「一模一样」，抓不到「同一个经济逻辑换写法」。建议用「因子值相关系数 > 0.9 即视为重复」做**数值层去重**（比 embedding 更可靠）。
- 剪枝标准要改：A 股看 IC/ICIR，币圈长尾标的噪声大，应该用 **rankIC 的 t 统计量** 且**只在宽度≥30 的日期上算**。

### 2.5 步骤五：模型 R&D + 步骤六：模型训练

**Qlib 的 model zoo**：LightGBM（默认，快）、Linear、MLP、GRU、LSTM、ALSTM、GATs、TCN、TabNet 等。
**RD-Agent(Q) 的 model agent**：LLM 直接改模型超参/结构代码，再跑回测比分数。

**这部分的现实判断**：
- 在**76 品种 × 553 天**的数据上，深度模型（GRU/ALSTM/GATs）几乎必然过拟合。截面样本量 = 553 × 平均宽度 50 ≈ **2.7 万个样本点**，而一个 GRU 参数量轻松上 10 万。
- ⇒ **本项目应只用 LightGBM + 强正则**，甚至只用线性模型做因子筛选，深度模型这条路在数据量补上来之前**不值得投入**。
- 这也是「模型 R&D」这一步在本项目**优先级最低**的原因。

### 2.6 步骤七：回测（Backtest）

**Qlib 回测的核心机制**：`TopkDropoutStrategy` —— 每天按预测分数买前 K 个、卖掉跌出前 K+n 的。这是**组合层面**的回测，天然多标的。

**三层成本模型**（qlib 的 `exchange` 配置）：
- `open_cost` / `close_cost`：双边费率
- `min_cost`：单笔最低费
- **`trade_unit` + 涨跌停限制**：A 股 100 股一手 + 涨跌停不能成交
- **`limit_threshold`**：涨跌停阈值

**本项目改造点（这里的坑最深）**：

| A 股机制 | 币圈现实 | 照抄的后果 |
|---|---|---|
| 涨跌停不能成交 | 无涨跌停，但有**插针** | 回测会低估极端行情下的滑点 |
| 100 股一手 | 可买 0.0001 BTC | `trade_unit` 必须改成极小值 |
| T+1 | T+0，24/7 | 持仓周期假设全错 |
| 无资金费率 | **永续有资金费率**（每 8 小时结算） | **完全没有成本模型**，长持仓策略直接被高估 |
| 有停牌 | 无停牌，但有**下架** | 下架标的的处理没考虑 |

- **资金费率是必须补的一项**。黑马策略平均持仓 397~1774 根 15m（4~74 天），跨 12~222 次费率结算。粗估按 0.01%/8h 计，74 天 ≈ 222 次 × 0.01% ≈ **2.2%**，这不是小数字。
- 这正是本项目记忆里那条铁律的延伸：**「乐观偏差归因到手续费一项」已经是旧结论，资金费率是还没算进去的第二项。**

### 2.7 步骤八（闭环）：金融分析（Financial Analysis）

**qlib 的 `analysis` 模块**产出：IC / rankIC / ICIR / 年化收益 / 最大回撤 / 夏普 / 换手率 / 分组收益（`figure_factory` 画 `analysis_position.report_graph`）。

**它的作用是回灌**：这些指标喂给因子 R&D 和模型 R&D，决定下一轮往哪走。**这就是「自动迭代」的实现方式** —— 也是【过拟合风险】的来源（见第四章）。

## 三 · 优势 · 风险 · 场景边界

### 3.1 优势（哪些是真的）

| 优势 | 真实性判断 |
|---|---|
| 因子假设→代码→执行→反馈**全自动闭环** | ✅ 真优势。这是它区别于"用 GPT 聊天生成因子"的核心 |
| **跨轮知识复用**（相似因子/错误经验检索） | ✅ 真优势。跑得越久越不浪费 token 在重复错误上 |
| 因子-模型**交替进化** | ✅ 有论文支撑（2× ARR / 少 70% 因子 / <$10） |
| 回测/分析基础设施完整（IC/分组/换手/成本模型） | ✅ 真，自建要花几周 |
| "开箱即用" | ❌ **假的**。数据格式、场景描述、标签、成本模型全都得改 |

### 3.2 【过拟合风险】★ 本节是全文最重要的一节

#### 风险 1：搜索式过拟合（selection overfitting）—— 最致命

RD-Agent 的循环是 **「生成 → 在同一段历史上回测 → 用回测分数当奖励 → 选下一轮」**。
跑 N 轮后，你手里的「最优因子」= **N 次针对同一段历史的搜索最优解**。

**它和普通过拟合的区别**：

| | 普通过拟合 | 搜索式过拟合 |
|---|---|---|
| 本质 | 模型参数记住噪声 | **选择过程**记住噪声 |
| 单次样本外测试能否发现 | ✅ 能 | ❌ **不能** |
| 为什么 | 参数被污染，新数据上必然失效 | 你拿「在历史上被选出来的那个」去测，它被选出来**恰恰因为**它在那段历史最好 |

**这个项目上有多严重**：可用截面窗口只有 **553 天**。若跑 20 轮 loop、每轮 5 个因子 = **100 个候选**，在 553 天上挑最好的 —— 这就是教科书级的 **多重比较问题**。Bonferroni 校正下，100 次试验要让单次 p 值降到 0.0005 才算显著，而 553 天的统计功效根本达不到。

**结论**：**RD-Agent 在本项目数据上的产出，默认应视为「假设生成器」，不是「策略发现器」。**

#### 风险 2：面板填充造成的「假信号」

Qlib 的 `instruments` 机制天生是**并集 + 前值填充**。本项目实测：面板 191,976 格里只有 **27.26% 是真实 bar**，**72.42% 是未上市缺失**、**0.32% 是尾部冻结**。

- 未上市缺失（72.42%）如果被填充成前值 → 会造出「某个币在上市前就有价格」的鬼数据。
- **尾部冻结（0.32%，616 格）最危险**：`high==low==close`，任何"突破前高"类因子都会在这里**完美预测**。这正是记忆里 H-039/H-040 已经定性过的坑。
- **RD-Agent 看不见这件事** —— 它的 factor 代码只会老老实实算 `Mean($close,20)`，把假 bar 算进去。

**对策已在代码里**：`audit_panel.py` 产出 `tradable_mask.parquet`（只放行 52,326 格真实 bar），任何因子回测前必须先与它对齐。

#### 风险 3：存活偏差（不可消除，只能披露）

88 个 CSV 全是**现存合约**。2021 年那批 top100 里已归零/下架的，一个都不在面板里。
币圈归零率远高于 A 股 ⇒ 这个偏差会把所有截面策略的收益**系统性高估**。

**唯一正路**：去补已下架合约的历史 K 线。`data.binance.vision` 会清理下架合约，需要第三方归档（如 Binance 公开数据镜像、Kaggle 的 Binance 历史数据集）。**这是下一步该做的事，不是工程能绕过的。**

#### 风险 4：免费池 LLM 的「静默降质」

免费池（0.01 折）的三类风险：
1. 长链路（几十次串行调用）被限流 → loop 断在半路
2. JSON mode / 结构化输出支持不稳定 → 因子代码解析失败率上升
3. **上下文窗口小于 RD-Agent 默认 token 预算 → 触发它内部的 prompt 截断**，表现为「因子质量莫名下降」而**不报错**

第 3 条最坑：它不报错，你只会觉得"这批因子怎么这么平庸"。

#### 风险 5：embedding 缺口（纯免费池特有的硬缺口）

DeepSeek 官方**没有 embedding 模型**（RD-Agent 文档专门写了这点，示范用 SiliconFlow 补位）。免费池同理。
RD-Agent 用 embedding 做 CoSTEER 的知识检索。缺了会降级甚至报错 —— **具体行为未实测，属高风险未知项**。

**已给的补位路径**（写在 `.env.example` 里）：本机 Ollama 的 `bge-m3`（零成本，推荐）> SiliconFlow 免费额度 > 复用网关。

### 3.3 适合 / 不适合场景

| ✅ 适合 | ❌ 不适合 |
|---|---|
| A 股/美股这类**截面宽（300+ 标的）且历史长（10 年+）**的市场 | **单品种时序择时**（黑马的原形态）—— 截面因子的分母无意义 |

```yaml
# 汤小龙的量化因子迭代任务卡（建议固化成定时任务）

       validate_oos.py --returns <因子值矩阵.csv> --n-trials <累计试验数>

```

**「持续迭代」的真正含义**：不是"一直跑就越来越好"，而是**「一直跑，但每一轮都要过闸，过不了的直接进 rejected 池，永不复活」**。这才是能防住搜索式过拟合的唯一做法。

## 七 · 验证流程：怎么防住自动生成因子的过拟合

### 7.1 三道闸（已实现并反测通过）

#### 闸 1：Purged K-Fold + Embargo（防标签泄漏）

**为什么必须 purge**：因子代码里会出现 `Ref($close, -1)`（未来函数）这类标签构造。如果训练集和测试集之间只是简单地切开，**紧邻边界的那几期样本同时携带了两边信息**，形成泄漏。

**做法**：时间轴切 5 折，每折测试段两侧各挖掉 `2% × T` 的 embargo 区，训练集里排除。

**实测输出**（750 期）：
```
fold0: train=584 test=150 挖空=16
fold1: train=583 test=150 挖空=17
...
```

#### 闸 2：Deflated Sharpe Ratio（把"试了多少次"折进阈值）

**公式**：
```
SR0 = sqrt(Var(SR_n)) · [(1-γ)Φ⁻¹(1-1/N) + γΦ⁻¹(1-1/(N·e))]
DSR = Φ( (SR - SR0)·sqrt(T-1) / sqrt(1 - γ3·SR + (γ4-1)/4·SR²) )
```
- `N` = 一共试了多少个因子（这就是"多重比较"的显式化）
- `γ3/γ4` = 收益的偏度/峰度（币圈尖峰厚尾，这一项不可省）
- **DSR > 0.95 才算显著**

**★ 一个必须记住的量纲坑**（本轮反测抓出来的）：
`Var(SR_n)` 必须是**与待检夏普同频**的方差估计。第一版写死 `sqrt(1.0)`（= 假定日频夏普标准差是 1），算出 `SR0 = 2.19` —— 意思是日频夏普得 2.19（年化 41）才算显著，**连强真信号都会被拒**。
修正后 A 组 `SR0 = 0.1159`，量纲正确。
**教训**：`SR0` 的量级必须能和你的 `SR` 直接比；差了 10 倍以上先怀疑量纲，别怀疑数据。

#### 闸 3：PBO（CSCV 方法）—— 直接量"训练最优会不会在测试集垮掉"

**做法**：把收益矩阵的时间轴切 10 块，枚举所有「5 块训练 / 5 块测试」组合（252 种）；每次在训练集挑夏普最高的因子，看它在测试集的**排名分位 ω**；`PBO = P(ω ≤ 0.5)`。

**判据**：`PBO < 0.5` 是学术底线，**实务建议 `< 0.35`**。

**为什么要有这道闸**：DSR 只看单个序列的显著性，看不见"选择过程"。PBO 直接模拟选择过程。

### 7.2 反测结果（这就是"校验器本身不骗人"的证据）

```
反测 A：真信号（750 期 × 40 候选，含跨期稳定 alpha）
  DSR = 0.9997  PBO = 0.0833  →  PROMOTED ✅

反测 B：纯噪声（750 期 × 40 个零 alpha 策略，但我们会挑历史上最好的那个）
  DSR = 0.4993  PBO = 0.4246  →  REJECTED ✅

区分力：PBO(A)=0.0833 vs PBO(B)=0.4246，gap=0.341
✅ 反测 4/4
```

**第一版是 2/4 失败的**，抓到两个真 bug（见 7.1 的量纲坑 + 反测判据设计错误）。
这条本身值得记：**一个没做过反测的校验器，等于没有校验器** —— 它可能永远返回 PASS。

### 7.3 完整验证流程（七步，从上到下不能跳）

## 九 · 沉底结论（六条，可单独引用）

1. **它是截面机器，不是时序机器。** 硬接黑马 = 挖出一堆无定义因子。**必须双轨**：截面轨用日线挖因子，时序轨用 15m 执行。
2. **最大的意外是数据不够，不是工程难。** 面板看着有 6.8 年，真正能算截面因子的只有 **553 个交易日**。这决定了 RD-Agent 只能当「候选因子生成器」。
3. **搜索式过拟合单靠样本外测试抓不住。** 必须三闸齐上（Purged CV + DSR + PBO），且 DSR 的 `sr0` 量纲错了会把真信号也拒掉 —— 这条坑本轮反测抓出来了。
4. **27.26% 的真实 bar 含量**，意味着 Qlib 的并集填充会把 72% 的假数据喂进因子计算。`tradable_mask` 不是可选优化，是**前置条件**。
5. **RD-Agent 值得付出的只有「因子假设生成 + 跨轮知识复用」这一层。** 它的回测/成本模型按 A 股写的，币圈直接照抄会漏掉**资金费率**（74 天持仓 ≈ 2.2%，不是小数）。
6. **免费池的真实成本不是钱，是限流和静默降质。** 便宜的代价是「失败无声」，必须靠 `--loop_n 1` 探路 + `--path` 续跑 + 连续失败 3 次即停。
