## 1. 现象

WorkBuddy 客户端「添加自定义模型」对话框配 `agnes-2.5-flash` 后调用报：

> 自定义模型 agnes-2.5-flash 错误，请切换模型或重试。503 | Trace ID: b5d1ed6dda016417cb861e8363df47ee5

---

## 2. 根因定位路径（实测）

调用 `/v1/models` 端点 → 列出 7 个真实模型（含 `agnes-2.5-flash`）。再对 9 种变体各发一次最小请求 `{"model":"…","messages":[{"role":"user","content":"p"}],"max_tokens":10}`：

| 变体 | HTTP | 用时 | 判定 |
|---|---|---|---|
| `agnes-2.5-flash` ✅ | 200 | 0.44s | **正解** |
| `agnes-2.0-flash` ✅ | 200 | 0.77s | 替选正解 |
| `agnes-2.5-pro` ✅ | 200 | 1.41s | 高阶版（非 503 现象） |
| `Agnes-2.5-Flash` ❌ | **503** | — | 大小写敏感 |
| `Agnes-2.5-FLASH` ❌ | **503** | — | 大小写敏感 |
| `agnes-2.5-Flash` ❌ | **503** | — | 部分大写敏感 |
| `2.5-flash` ❌ | **503** | — | 缺前缀 |
| `agnes-25-flash` ❌ | **503** | — | 横线变体 |
| `agn2.5-flash` ❌ | **503** | — | 缩写 |

后端对**未精确等于 `agnes-2.5-flash` 字符串**的 model 字段一律返 503（不是 400/404，而是 503）——这是关键事实：

> **Agnes 后端把"未识别模型名"判为 service 异常（503），不是 client error（400/404）。**
> 这就解释了为什么客户端 UI 显示的是"自定义模型…请切换模型或重试"——客户端把任何非 200 都一律降级解释为"模型错"。

### 2.1 ★最重要隐藏根因：Unicode 非断连字符 `U+2011`（本次真因）

2026-08-23 第 4 轮最终定位：用户"感觉的大小写问题"**实际不是大小写，而是连字符编码**。

- WorkBuddy 本地配置文件 `C:\Users\Administrator\.workbuddy\models.json` 中，模型名存的是：
  `agnes<U+2011>2.5<U+2011>flash`（`U+2011` = NON-BREAKING HYPHEN，**非 ASCII 减号 `U+002D`**）
- 肉眼完全看不出区别（`‑` 与 `-` 视觉一致），但发给 API 的字符串 ≠ `agnes-2.5-flash`，后端判定"未识别模型"→ 503
- **来源**：从网页文档/聊天记录复制模型名时，文档里的 `‑` 多为 `U+2011`（排版用非断连字符），粘贴进客户端即带毒
- 这是我（agent）在本地 `models.json` 直接修正的：把 `id` / `name` 两个字段的 `U+2011` 全量替换为 ASCII `-`，写回后模型名变为纯 `agnes-2.5-flash`（`U+002D`）

> ✅ **自我净化**：第 2 节表里的"Agnes-2.5-Flash 大小写 503"结论仍对（那是真大小写错），但本次用户真实故障是 `U+2011`，与大小写无关。两条都要记。

## 3. 协议端点探测（base_url 三选）

| 端点 | 协议 | HTTP | 备注 |
|---|---|---|---|
| `https://api.agnes-ai.cn/v1/chat/completions` | OpenAI | 200 | **推荐，WorkBuddy 兼容最好** |
| `https://api.agnes-ai.cn/v1/messages` | Anthropic | 200 | 也支持，WorkBuddy 默认走这条但配置不当易错 |
| `https://api.agnes-ai.cn/v1/messages`（OpenAI payload） | 混搭 | 200 | 路径宽容，body 决定协议 |

→ **base_url 一律用 `https://api.agnes-ai.cn/v1`**（不要加 `/anthropic` 或 `/openai` 等子路径）。

## 4. 修正操作（已自动化闭环 ✅）

> 2026-08-23 第 4 轮：汤哥全权委托，agent 直接改本地 `models.json`，无需人工。

**agent 自动执行的修复（已落地）：**

1. 二进制扫描定位 `C:\Users\Administrator\.workbuddy\models.json`（WorkBuddy 自定义模型本地配置，云端账号之外还有一份本地 JSON 副本）
2. 读该文件，打印 `id`/`name` 字段逐字符码点 → 确认两个字段均为 `U+2011` 非断连字符
3. 把 `id`/`name` 中所有 hyphen-like 非 ASCII 字符（`U+2011/U+2010/U+2013/U+2014/U+2212/U+FF0D`）替换为 ASCII `-`（`U+002D`）
4. 原子写回，校验 JSON 合法，码点确认变为纯 `agnes-2.5-flash`（`U+002D`）

**用户侧唯一动作（不是"改配置"，是"重启应用"）：**

- 完全退出 WorkBuddy 客户端 → 重新打开（让客户端重载 `models.json`）
- 重启后下拉选中 `agnes-2.5-flash` 发一条消息 → 应 200 正常
- 若仍 503：客户端缓存了旧配置，确认已彻底退出（任务管理器无 WorkBuddy 进程）再开

> ⚠️ 陷阱：WorkBuddy 客户端若再次"手动编辑并保存"该模型，可能又把 `U+2011` 写回去（输入框复制带入）。**已生效后就别再去手动改它**。
