## 二、根因分析（五步法·检查→分析）

### 2.1 表层现象
- Chrome 访问 `chromewebstore.google.com` → `ERR_CONNECTION_TIMED_OUT`
- 汤哥以为"本地防火墙拦了 Chrome"

### 2.2 真实根因（三层，逐层剥离）

| 层 | 根因 | 证据 |
|----|------|------|
| **L1** | **GFW 屏蔽**（非本地防火墙） | 本地直连 Google = 000；本地防火墙不管域名级屏蔽 |
| **L2** | 腾讯云安全组只放行 **22(SSH)**，代理端口 443/8388 被云端拦截 | 服务器上 Xray 监听 8388/443，但外部 `nc` 测试全 closed |
| **L3** | **SSH 隧道"半死"**（长时间运行后进程在但数据卡死） | 旧隧道跑 5 小时后：github 通、google 超时；**换新端口重建 → 全站 200** |

### 2.3 关键诊断动作（可复用套路）

```bash
# ① 在服务器上直接测（判断问题在本地还是服务器）
ssh root@43.161.202.206 "curl -s -o /dev/null -w '%{http_code}' https://www.google.com"
# → 服务器返回 200 = 服务器没问题，问题在本地隧道 ✅（本次就是这步定案的）

# ② 本地经 SOCKS5 隧道测（注意 socks5h 让服务器解析 DNS，避开本地 DNS 污染）
curl -x socks5h://127.0.0.1:1081 https://www.google.com -o /dev/null -w "%{http_code}"

# ③ 对比 socks5 vs socks5h
#    socks5  = DNS 在本地解析（易被 GFW 污染）
#    socks5h = DNS 交给服务器解析（推荐）
```

## 四、Obsidian Web Clipper 真相与完整配置

> ⚠️ **重要澄清**：Chrome **没有"内置" Obsidian 插件**。Obsidian 是独立桌面应用（Electron），Chrome 上只有官方 **Obsidian Web Clipper**（网页剪藏器），必须手动安装 + 配合本地 Obsidian 的 Local REST API 才能工作。

### 4.1 三件套缺一不可

```
① Chrome 装 Obsidian Web Clipper 插件   （需代理，已打通可装）
        ↓
② Obsidian 桌面应用启用 Local REST API 社区插件  （当前未开，需手动开）
        ↓
③ Web Clipper 填 API Key + 端口 27123/27124
        ↓
   网页内容 → 一键保存到 Obsidian 库 ✅
```

### 4.2 操作步骤

**Step 1 — 装 Chrome 插件**
1. 双击桌面 `启动Chrome香港代理.bat`（走香港代理的 Chrome）
2. 打开 https://chromewebstore.google.com/detail/obsidian-web-clipper/cnjifjpddelmedmihgijeibhnjdogjmm
3. 点"添加至 Chrome"

**Step 2 — Obsidian 开启 Local REST API**
1. 打开 Obsidian → 设置（齿轮）→ 第三方插件
2. 关闭"安全模式"
3. 点"浏览" → 搜索 **Local REST API** → 安装 → 启用
4. 进入该插件设置 → 生成/复制 **API Key**
5. 确认端口：`27123`(HTTP) 或 `27124`(HTTPS)

**Step 3 — Web Clipper 连上 Obsidian**
1. Chrome 点 Obsidian Web Clipper 图标 → 设置
2. 填 API Key（Step 2 复制的）
3. 填地址 `http://127.0.0.1:27123`
4. 点测试连接 → 显示成功即可

> 💡 **社区插件市场若下载慢**：Obsidian 社区插件从 GitHub 拉取，可在 Obsidian 里配系统代理，或让服务器代跑。

## 五、自愈守护机制（本次核心创新 · 根治"隧道半死"）

### 5.1 问题
SSH SOCKS5 隧道长时间运行（数小时）后进入"半死"状态：**进程在、端口在监听，但数据传输卡死** → 表现为部分站点通、大站点超时。手动排查极费时。

### 5.2 解决：健康自愈守护

**文件**：`C:\Users\Administrator\hk_proxy_guard.bat`（已部署开机自启）

**逻辑**：
```
每 60 秒 → curl 经隧道测 google
   ├─ 成功 → 记录"隧道正常"，继续等 60 秒
   └─ 失败 → 杀掉占用 1081 的进程 → 重建 SSH 隧道 → 记录"隧道已重建"
```

**自愈效果**：隧道半死/断线后**最多 60 秒自动恢复**，无需人工干预。

### 5.3 交付物清单

| 文件 | 位置 | 作用 |
|------|------|------|
| `hk_proxy_guard.bat` | `C:\Users\Administrator\` + 启动文件夹 | **健康自愈守护**（开机自启，60秒检测+自动重建） |
| `启动Chrome香港代理.bat` | 桌面 | 双击开走代理的 Chrome（端口 1081） |

### 10.1 双 Chrome 插件互导（能！三方案）

代理 Chrome 用了独立档案（ProxyProfile），插件按 profile 隔离——所以"缺插件"是正常现象。互导三方案：

| 方案 | 操作 | 特点 |
|------|------|------|
| **A. Google 账号同步** ⭐ | 代理 Chrome 登录同一 Google 账号 → 设置→同步→勾「扩展程序」 | **双向全自动**，一次登录永久同步 |
| B. 企业策略强制装 | 已内置（HKCU ExtensionInstallForcelist，对所有 profile 生效） | 免点击；加新插件=注册表值递增 |
| C. 开发者模式加载 | 拷 `User Data\Default\Extensions\<ID>\<版本>\` → 加载已解压扩展 | 应急，不自动更新 |

**相互导答案：能**——账号同步天然双向；策略层已让两端同时自动装。

### 10.2 停费兜底（90多块不交了也能用）
