## 二、诊断结果

### 端口扫描
| 端口 | 服务名称 | TCP监听 | HTTP响应 | 说明 |
|------|---------|---------|---------|------|
| 15721 | CC-Switch 总网关 | 未显示LISTEN | **200 OK** | API代理端口，正常工作 |
| 4567 | AI Code Switch | 未显示LISTEN | **405** (服务存在) | 备用链路 |
| 57321 | Codex++ 管理端口 | 未显示LISTEN | **404** (非API代理) | 管理界面，不代理API |

### 根因分析
- config.toml 的 `base_url` 指向 `http://127.0.0.1:57321/v1`（管理端口）
- 正确的 API 代理端口是 **15721**（CC-Switch 总网关）
- DualLink Recovery 脚本明确标注："57321返回404=正常, 证明非API代理端口"
- config.toml 的 `wire_api = "responses"` 但 CC-Switch 使用 `chat_completions` 格式

## 三、修复方案

### 方案A（主修复）：修改 config.toml 指向正确端口
```toml

wire_api = "chat_completions"
```

### 方案B（备用）：启动 AI Code Switch 4567 端口
