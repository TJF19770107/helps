## 一、必读 6 篇（按顺序）

### 1. LLM.int8（arXiv 2208.07339）
- **解决**：大模型 INT8 量化后精度崩塌
- **招**：发现**离群特征维度只占 0.1%，却主导了量化误差** → 把这些维度保留 FP16，其余走 INT8（混合精度分解）
- **代价**：实现复杂，离群维度检测需校准；矩阵乘要拆开算，有额外开销
- **记住一句**：**"不是所有维度都值得量化"**

### 2. SmoothQuant（arXiv 2211.10438）
- **解决**：激活的动态范围远大于权重，W8A8 时激活被截断
- **招**：数学等价变换 `Y=(X·diag(s)⁻¹)·(diag(s)·W)`，把激活的量化难度**迁移一部分到权重**
- **代价**：需要选平滑系数 s（超参）；对某些层效果一般
- **记住一句**：**"难度可以搬家，不用硬扛"**

### 3. GPTQ（arXiv 2210.17323）
- **解决**：大模型 INT4 训练后量化（PTQ）精度损失
- **招**：逐层做**二阶（Hessian）误差补偿**，量化一个权重就用剩余权重补偿误差
- **代价**：需要校准集；逐层串行，量化 700B 要很久
- **记住一句**：**"量化误差可以补偿，不是只能承受"**

### 4. AWQ（arXiv 2306.7761）
- **解决**：GPTQ 在极低比特时仍掉点
- **招**：**激活感知** —— 只保护 1% 的显著权重通道（按激活幅值选），其余照常量化
- **代价**：要统计激活分布；保护比例是超参
- **记住一句**：**"保护 1%，救回大半"**

### 5. FP8-LM（arXiv 2310.18313）
- **解决**：FP8 全流程训练（前向/反向/优化器状态）的数值稳定性
- **招**：per-tensor / per-block scaling、delayed scaling（用历史 amax 估 scale）、master weights 保高精度
- **代价**：需要 Hopper 级硬件（Transformer Engine）；调 scale 有门槛
- **记住一句**：**"FP8 不是精度问题，是 scaling 问题"**

### 6. GLM-5 技术报告（arXiv 2602.15763）— 量化相关部分
- **确认的**：SFT 阶段用 **INT4 QAT**，训练与离线权重量化**共用量化内核、逐位一致**；推理侧 **FP8 rollout** 降延迟
- **未披露的**：FP8 训练完整 scale 策略、KV cache 量化方案
- **记住一句**：**"训推一体的量化内核，才是工程化的标志"**

## 三、四篇论文的"一句话关系图"

```
LLM.int8  → 发现离群问题（诊断）
SmoothQuant → 把难度搬家（治激活）
GPTQ / AWQ → 权重量化两条路（治权重）
FP8-LM    → 训练侧全流程（治训练）
GLM-5     → 工程化：训推共内核 + FP8 rollout（治落地）
```

## 四、读论文的正确姿势（我们踩过的坑）

1. **先读摘要 + 图表**，别从头读
2. **只看它和上一代的差异**（增量才是价值）
3. **必看 limitations / 未披露项** —— GLM-5 报告最值钱的就是它没说什么
4. **读完写三行**：解决什么 / 用什么招 / 代价是什么。写不出第三行 = 没读懂
5. **别抄公式**，抄**决策依据**（什么场景选哪篇）

## 五、读完之后能回答的问题

- 我的场景该选 PTQ 还是 QAT？
- 4bit 权重 + BF16 KV 行不行？显存怎么算？
- 为什么 FP8 比 INT8 更受欢迎？（答：硬件原生支持 + 无需复杂校准 + 几乎不掉点）
- 量化会不会影响 RL 训练？（答：会，污染重要性采样比率）
