# 交易量化 · 用 GLM 做信号与研报

> 模块1 的第二条线（你要的"两个都要"）。
> ⚠️ **先把最重要的说在前面**：**LLM 不擅长直接预测价格，别拿它当信号源。**
> 它真正能赚钱的位置在别处 —— 下面按"能 / 不能"分清楚。

## 一、LLM 在量化里的真实位置（能 vs 不能）

| 用途 | 能不能 | 说明 |
|---|---|---|
| **新闻/公告情绪打分** | ✅ 强 | 结构化文本 → 情绪/事件标签，这是 NLP 老本行 |
| **财报/研报要点抽取** | ✅ 强 | 长文档压缩、字段抽取、同比变化 |
| **策略代码生成** | ✅ 强 | 把想法变成 Python/MQL5，省 70% 编码时间 |
| **因子逻辑解释** | ✅ 强 | 解释"为什么这个因子在震荡市失效" |
| **回测报告解读** | ✅ 强 | 把一堆指标翻译成人话 |
| **交易日志复盘** | ✅ 强 | 归类亏损原因 |
| **直接预测涨跌** | ❌ **不可靠** | 别做，做了必亏 |
| **替代技术指标** | ❌ 不可靠 | LLM 看 K 线不如 MA/ATR |
| **实时高频决策** | ❌ 不可行 | 延迟太高 |

**一句话**：**LLM 是"研究员的助手"，不是"交易员"。**

## 二、四条可落地的用法

### 用法 1：事件驱动因子（最实在）
```
输入：财经新闻/公告/政策文本（每日几百条）
  ↓ GLM 抽取：{"event_type": "央行降准|财报超预期|高管变动|监管处罚",
             "entity": "XAUUSD|BTCUSDT|某股",
             "sentiment": -1~1, "magnitude": 1~5, "horizon": "短期|中期"}
  ↓ 聚合成日频因子
  ↓ 进回测：事件因子 × 方向 × 持有期
```
**验收**：因子 IC / IR 显著 ≠ 0；**不是看准确率，是看 IC**

### 用法 2：把黑马策略的逻辑翻译成可检验的假设
我们有 `ea_gold_dark_horse_v2.0`（XAUUSD H4）。可以让 GLM 做：
- 读策略代码 → 输出"这个策略隐含了哪 5 个市场假设"
- 每个假设 → 设计一个可验证的统计检验
- **这一步能抓出策略里"想当然"的部分**

### 用法 3：结构化研报 → 因子候选
- 喂 50 篇券商研报 → GLM 抽取"看多/看空理由类型"
- 统计哪类理由在历史上更常兑现
- 产出：**理由类型 → 未来 N 日收益**的统计表（要带样本数、置信区间）

> ⚠️ 这一步极易过拟合。**必须留出样本外验证 + 报告样本数**。

### 用法 4：交易复盘自动化
- 输入：成交记录 + 当时的行情/新闻
- 输出：亏损归因分类（追高/止损犹豫/逆势/消息误判）
- 价值：**找出系统性错误**，这比找新策略更赚钱

## 三、绝对不能做的三件事

1. **让 LLM 直接给买卖点**
   - 它会给，看起来还很自信，但那只是语言模式的产物
2. **用 LLM 生成的"回测代码"直接跑真钱**
   - 一定会有前视偏差（look-ahead bias）、幸存者偏差
   - 必须人工审代码，重点查：是否用了未来数据、是否用了复权价、是否处理了停牌
3. **用 LLM 解释"为什么昨天涨"然后反推策略**
   - 这叫叙事谬误。事后解释永远成立，事前预测永远不行

## 四、和现有黑马策略怎么接

```
现有：ea_gold_dark_horse_v2.0（XAUUSD H4，MT5）
  ↓
可加的三层（按性价比排序）
  ① 复盘层（立刻能做，0 成本）：用 GLM 做交易日志归因
  ② 研究层（1-2 周）：事件因子抽取 + 统计检验 → 决定要不要加过滤条件
  ③ 执行层（暂不做）：实时 LLM 决策 —— 延迟与稳定性都不达标
```

**关键提醒**：任何新增层**必须先在历史数据上做样本外验证**，且明确"如果它没用，我们怎么知道"。

## 五、评估 LLM 因子的正确指标

| 指标 | 意义 | 门槛 |
|---|---|---|
| **IC**（信息系数） | 因子值与未来收益的相关性 | \|IC\| > 0.03 才有讨论价值 |
| **IR**（信息比率） | IC 的稳定性 | > 0.3 算可用 |
| **换手率** | 成本消耗 | 太高会吃掉收益 |
| **样本数** | 统计有效性 | 事件类因子样本常不足，**必须报告** |
| **样本外表现** | 是否过拟合 | 与样本内差距 > 50% 就是过拟合 |

> **「量不到自己的尺子」铁律**：设筛选条件前先算目标自身特征值，否则目标可能根本不落在样本里。

## 六、成本核算（别忽略）

| 项 | 估算 |
|---|---|
| API 成本 | 每日 500 条新闻 × 500 token ≈ 25 万 token/日 ≈ **¥1-3/日** |
| 工程成本 | 数据管道 + 存储 + 调度，**1-2 周开发** |
| 验证成本 | 回测框架改造 + 样本外测试，**1 周** |
| **隐性成本** | **过拟合导致的实盘亏损** ← 最大的一项 |

## 七、诚实结论

- **LLM 在量化里的最大价值是"省研究员的时间"，不是"提高胜率"**
- 它能帮你更快地淘汰错误假设——**这本身就很值钱**
- 真正决定盈亏的还是：**风控、仓位、执行、成本控制**
- 任何声称"用 GPT 选股月赚 30%"的说法，**默认是假的**
