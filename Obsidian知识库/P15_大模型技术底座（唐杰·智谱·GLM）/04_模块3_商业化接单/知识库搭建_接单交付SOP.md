# 知识库搭建 · 接单交付 SOP

> 对应智谱 Academy 第 3 门课「知识库工程：原理及实现」。
> 市场报价 ¥1 万 - 5 万（见 [[大模型行业落地案例库]]）。**这是最容易标准化、最容易复制的单子。**

## 一、交付物清单（报价就按这个拆）

| # | 交付物 | 客户能不能看见价值 |
|---|---|---|
| 1 | 知识库（清洗后的结构化文档集） | ✅ 能（条目数、覆盖率） |
| 2 | 检索服务（向量库 + 索引） | ⚠️ 看不见，需给指标 |
| 3 | 问答服务（API / 企微机器人 / 网页） | ✅ 能（能对话） |
| 4 | **评测报告**（准确率/拒答率/延迟） | ✅ **最能证明价值** |
| 5 | 运维手册 + 更新流程 | ✅ 能（客户能自己维护） |
| 6 | 培训（1-2 小时） | ✅ 能 |

## 二、七步交付流程

### 第 0 步：需求对齐（1 天，不收费也要做）
必须问清 6 件事：
1. **谁用**？（内部员工 / 外部客户 / 管理层）→ 决定语气与权限
2. **问什么**？（列 20 个真实问题）→ **这 20 条就是验收集**
3. **资料在哪**？（格式、数量、有没有权限限制）
4. **答错代价多大**？→ 决定要不要强制"转人工"
5. **要不要接现有系统**？（企微/钉钉/官网/APP）
6. **谁维护**？→ 决定交付形态

> ⚠️ **第 2 条是生死线**。客户说不清"会问什么"，这单必烂尾。

### 第 1 步：资料盘点与清洗（占 40% 工作量）
```
原始资料（PDF/Word/Excel/网页/聊天记录）
  ↓ 格式统一（转 Markdown/纯文本）
  ↓ 去噪（页眉页脚、水印、目录、重复段）
  ↓ 切分（语义切分，512-1024 token，带 10-20% 重叠）
  ↓ 打标（来源、部门、时效、密级）
  ↓ 入库
```
**这一步的坑**：
- PDF 里的表格 → 必须单独处理（否则全乱）
- 扫描件 → 必须 OCR，且要人工抽查
- 多版本文件（制度 v1/v2/v3）→ **只留最新版 + 标注生效日期**，否则模型会答冲突内容
- 密级 → 必须在元数据里标，检索时过滤

### 第 2 步：检索方案选型

| 方案 | 适用 | 成本 |
|---|---|---|
| 纯向量检索 | 语义相近的问法 | 低 |
| 纯关键词（BM25） | 精确术语、编号、人名 | 低 |
| **混合检索（推荐）** | 大多数真实场景 | 中 |
| + Rerank | 要求高准确率 | 中高 |
| + 查询改写 | 用户问法口语化严重 | 中 |

**默认配置（够用且便宜）**：混合检索（向量 + BM25）+ Rerank top-5 → 送模型。

### 第 3 步：Prompt 与拒答策略
见 [[提示工程_接单实战模板]] 模板 2。
**必须加的**：`confidence` 字段 + `need_human` 字段。

### 第 4 步：评测（★ 最能证明价值的一步）
用第 0 步那 20 个真实问题做测试集，逐条人工判：

| 指标 | 定义 | 目标 |
|---|---|---|
| **命中率** | 答对 / 总数 | ≥ 80% |
| **拒答正确率** | 该拒的拒了 / 该拒的总数 | ≥ 85% |
| **幻觉率** | 编造事实 / 总数 | ≤ 5% |
| **首字延迟** | P50 / P95 | P95 < 3s |
| **引用准确率** | 引用的原文真的支持结论 | ≥ 90% |

> 交付时给**逐条明细表**（问题 / 答案 / 判定 / 原因），不是给一个总分。
> 客户看到明细才知道钱花在哪。

### 第 5 步：接入
- 企微群机器人（我们最熟）
- 网页挂件
- API 给客户自己接

### 第 6 步：交接
- 运维手册：怎么加文档、怎么重建索引、怎么回滚
- **必须教客户自己加文档**，否则你会被永久绑定在低价值维护上

### 第 7 步：运维（月费来源）
- 每周看一次 badcase
- 每月更新知识库
- 每季重跑评测

## 三、报价拆解模板（¥1 万 - 5 万的单怎么拆）

| 项 | 占比 | 说明 |
|---|---|---|
| 资料清洗 | 35% | 最脏最累，别低估 |
| 检索与问答搭建 | 25% | 技术活 |
| 评测与调优 | 25% | **价值最高的部分** |
| 接入与培训 | 15% | 收尾 |
| **运维（另计）** | — | ¥1,000-3,000/月 |

**谈判要点**：
- 资料量超过 500 份 → 按量加价
- 要接多个渠道 → 每个渠道加价
- 要求"准确率 95%+"→ **先做 POC 再承诺**，别直接答应

## 四、五个必踩的坑（提前避）

| 坑 | 后果 | 解法 |
|---|---|---|
| 资料直接扔进向量库不清洗 | 答非所问、重复答案 | 必做去噪 + 去重 |
| 切分太碎（<200 token） | 语义断裂 | 512-1024 + 重叠 |
| 切分太大（>2000 token） | 检索不准 | 同上 |
| 只做向量检索 | 编号/专有名词查不到 | 加 BM25 混合 |
| 不给拒答出口 | 硬编答案，客户投诉 | 强制 `need_human` |

## 五、最小可行交付（MVP 版，适合小单）

**¥1,999-3,999 的小单怎么做**：
1. 只做一个渠道（企微群）
2. 资料 ≤ 100 份
3. 纯向量 + 拒答
4. 不做 Rerank
5. 评测只做 20 条
6. 交付：能用的机器人 + 一页评测表
7. **不承诺准确率**，只承诺"能答常见问题，答不了会转人工"

> 这个版本 1-2 天能交，是**验证客户付费意愿**最好的方式。

## 六、我们的现成优势

- 已打通**企业微信**（31 群）
- 已有**多端知识库经验**（IMA / 乐享 / Obsidian / CNB）
- 已有**六端归档**能力（知识库交付后顺手做归档，是加分项）
- → 差异化卖点：**"我们不只搭知识库，还帮你把知识资产归档成可检索的六端体系"**
