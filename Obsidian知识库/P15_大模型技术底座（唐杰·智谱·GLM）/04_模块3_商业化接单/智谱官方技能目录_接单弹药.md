## 三、怎么装（三种方式，按顺序试）

### 方式 A：Clawhub（官方推荐）

```bash
npx clawhub@latest install <skill-name>
```

**一条命令只装一个**，要装多个就循环：

```bash
for skill in \
  glmocr glmocr-table glmocr-formula glmocr-handwriting \
  glm-image-generation glmv-caption glmv-prompt-gen glmv-resume-screen \
  glmv-grounding glmv-doc-based-writing glmv-pdf-to-ppt glmv-pdf-to-web \
  glmv-prd-to-app glmv-web-replication; do
  npx clawhub@latest install "$skill" || break
done
```

> 循环里有 `|| break` —— 官方特意写的：**首次失败就停**，别硬刷。
> 常见失败：`Rate limit exceeded (retry in 47s, remaining: 0/20)`。

### 方式 B：被限流了

等 reset 时间，或走方式 C。

### 方式 C：从 GitHub 源装

```bash
git clone https://github.com/zai-org/<REPO>.git
```

然后照该技能自己的 `SKILL.md` 做。仓库对应关系：

## 四、API Key（必配，且有安全红线）

**环境变量名**：`ZHIPU_API_KEY`

```bash
export ZHIPU_API_KEY="你的key"
```

**取 key**：https://bigmodel.cn/usercenter/proj-mgmt/apikeys

### ★ 官方写明的四条安全规范（照抄，别自作聪明）

1. **建最小权限 key** —— 只给你要用的技能所需权限，别用全权限 key 跑所有活
2. **只放环境变量** —— 绝不硬编码进源码、绝不提交进版本库
3. **用 `.env` 时，`.gitignore` 里写的是路径 `.env`，不是变量名 `ZHIPU_API_KEY`**
   > 原文点破了：*"Git ignores files by path, not by their contents."*
   > 而且 **ignore 不等于 untrack** —— 已经提交过的 key，ignore 了也还在历史里，必须**吊销重发**。
4. **定期轮换**，不用的立刻在控制台吊销

> 这条对你有直接意义：你的技能库会常驻 `ZHIPU_API_KEY`。按上面第 3 条，**别把 key 写进任何会被 git 跟踪的 SKILL.md 或脚本里** —— 走 `~/.workbuddy/` 下的本地 env 或系统环境变量。

## 五、给汤小龙的用法约定

当有活进来，按这个顺序判断：

```
1. 是"把已有文档变成别的东西"？
   → PDF→PPT / PDF→Web / DOCX→方案   这三条最常命中，且客户预算高

2. 是"从图片/扫描件里取数据"？
   → glmocr-table 优先（表格比纯文字值钱 3 倍）

3. 是"客户只有想法，要个能点的东西"？
   → glmv-prd-to-app，报价按"原型"不是按"开发"，3千起

4. 都不是？
   → 别硬套技能，老实说这个活 GLM 干不了，转人工或拒单
```

**铁律：不承诺"AI 全自动"。** 这些技能都是"人机协作"，交付前必须人工过一遍。
`glmv-prd-to-app` 生成的代码尤其要验 —— 能跑 ≠ 能用。
