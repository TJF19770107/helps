## 一、已跑通（有实测输出）

### `hw1_micro_gpt_numpy.py` — 从零写 Tokenizer + Transformer

```bash
python hw1_micro_gpt_numpy.py --steps 600 --lr 0.08
python hw1_micro_gpt_numpy.py --quick        # 10 步冒烟
```

| 项 | 实测结果 |
|---|---|
| BPE tokenizer | vocab 360 / **104 merges** / 压缩比 **0.81×** |
| 模型 | **64,272 参数**（清华原版 0.1B，缩到 0.064M） |
| **梯度检查** | **17/17 通过**，rel_err 量级 **1e-8 ~ 1e-6** |
| 训练 | loss **5.896 → 0.037**（降幅 99.4%，600 步） |
| 生成 | 能拼出正确中文词组，如「规模决定模型能容纳多少」 |

**两个真 bug（本轮实测踩到，已修）**

1. **`vocab_size` 必须 > 256** —— byte-level BPE 初始词表就是 256 字节。传 140 时 `nxt=256 > 140`，训练循环一次不进，`merges=0`，tokenizer 退化成纯字节编码。
2. **`encode()` 不能写 `while` + `min(new_id)` 反复扫** —— 必须**按学到的先后顺序逐条应用 merge**。前者会漏合并且复杂度爆炸，长文本上尤其明显。

**一个假 bug（检查器的问题，不是代码的问题）**

> 首版梯度检查对 `b1`（ReLU 偏置）报 `rel_err=3.5e-3`，看着像反向写错了。
> **真因是 ReLU 在 0 处不可导** —— 数值差分扰动一步，`pre` 的正负号翻了，算的就不是同一个函数。
> 修法：`h` 从 `1e-5` 缩到 `1e-6`，并加绝对误差兜底（`abs_err < 1e-7` 判过）。
> **教训：梯度检查报错时，先问「这个参数前面有没有不可导算子」，再怀疑公式。**

### `hw3_scaling_law.py` — 拟合 Scaling Law + 留一外推检验

```bash
python hw3_scaling_law.py
```

| 项 | 实测结果 |
|---|---|
| 全量拟合 | E=1.673  A=433  B=345  **α=0.343  β=0.272** |
| 拟合优度 | **R² = 0.9998** |
| **留一外推误差** | 平均 0.018 / **最大 0.024** |
| 反推真参数 | α 真值 0.340→拟合 0.343（**偏差 0.003**）；β 真值 0.280→拟合 0.271（**偏差 0.009**） |
| 外推 1T/20T | 预测 loss ≈ **1.791**（指数 ±10% 敏感区间 1.723 ~ 1.953） |
| compute-optimal | 1e24 FLOPs 下最优 N=3.98e10、D=4.19e12，**105 tok/param** |

**一个真 bug（本轮实测踩到，已修）**

> 首版数据里每个点都取 `D/N = 20`（固定配比）。结果拟合出 **β=0.49 > α=0.26**，
> compute-optimal 直接跑到边界，算出 **`tokens/param = 0.0`** —— 完全是垃圾。
> **真因：N 和 D 完全共线时，α 和 β 不可识别**，模型可以随便分配"功劳"。
> 这正是唐杰六维里「**数据**」那一维的失效形态：**不是数据不够多，是数据没有变化**。
> 修法：让 `D/N` 在 10~40 之间变化，把 N 和 D 解耦。
> **验收升级**：改成「用已知真参数生成数据 → 看能否反推出来」，这样验收才成立。

### `hw5_agent_harness.py` — Agent Harness + Self-Judge

```bash
python hw5_agent_harness.py
python hw5_agent_harness.py --verbose
```

| 项 | 实测结果 |
|---|---|
| 环境 | 7 个测试，3 个预置 bug |
| 基线 | 通过 5/7，score 0.714 |
| 修好 | 通过 7/7，score 1.000 |
| **作弊样本识别** | 2/2 **全部抓住**（`return True` / 测试名特判） |

**本轮挖到的真问题（比脚本设计更值得记）**

> 我标记为 BUG-2 的「空块除零」，在这 7 个测试里**从未被触发** ——
> 因为 `range(0, len, k)` 在 `k>0` 时永远不产出空 chunk。
> **也就是说：测试集有盲区，通过了不代表没问题。**
> → 这正是「Benchmark 成绩不等于用户体验」的最小可复现案例。
> → 一个 Bug 要么被真实数据触发，要么它只是不能被验证的假设。
