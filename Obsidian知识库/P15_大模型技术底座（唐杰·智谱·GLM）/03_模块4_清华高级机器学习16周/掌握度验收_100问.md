# 掌握度验收 100 问

> **用法**：遮住答案区，逐题口述。**答不上来的就是没学会的地方**，回去看对应周次。
> **判级**：
> - 90+ 题能答 → 可以对外讲这门课
> - 70~89 → 能用，但被追问就露
> - 50~69 → 知道名词，不会推理
> - <50 → 只是看过，没学过

## A 组 · 数据与 Tokenizer（W2）· 10 题

1. BPE 训练时，为什么 `vocab_size` 必须大于 256？
2. vocab 从 32K 扩到 128K，embedding 参数怎么变？输出层呢？
3. 同样的中文句子，中文词表偏小的 tokenizer 会多花几倍 token？为什么？
4. 语料去重做到 90% 和做到 60%，分别会导致什么后果？哪个更危险？
5. MinHash + LSH 为什么能近似 Jaccard 相似度？
6. 质量过滤常见的三类信号是什么？
7. 数据配比里「课程学习」指的是什么？为什么后喂的数据影响更大？
8. 合成数据的最大风险是什么？怎么检测？
9. 一个 1T token 的语料，去重后剩 600B，你该不该补合成数据？判断依据是什么？
10. 为什么说 tokenizer 是「唯一一个训练完就冻结、却决定了后面一切」的组件？

<details><summary>参考要点（A 组）</summary>

1. byte-level BPE 初始词表 = 256 个字节。小于 256 时循环条件 `nxt < vocab_size` 一开始就假，一个 merge 都学不到。
2. embedding = 32K×d → 128K×d，涨 4 倍；**输出投影同步涨 4 倍**（若不做 tie）。这一项在大模型里可能是几百 M 参数。
3. 中文一个字若被切成 2~3 字节 token，同样语义要付 2~3 倍 token 费用 —— 直接体现在推理账单上。
4. 去重不足（60%）→ 重复数据让模型过拟合、记忆化、评测污染；去重过度（90%）→ 丢掉合法的常见表述，模型语言能力下降。**去重不足更危险**，因为它会污染评测，让你误判。
5. 用 k 个哈希函数取最小哈希值，两集合最小哈希相等的概率 = Jaccard 相似度。
6. ① 困惑度/模型打分 ② 启发式规则（长度、符号比、重复率）③ 分类器（高质量语料训练的正例判别器）。
7. 先喂通用、后喂高质量/领域数据，让模型「最后记住的」是你要的分布。后喂影响大是因为近因效应 + 学习率退火阶段权重更新更稳。
8. 分布收窄（mode collapse）、错误放大、评测污染。检测：与真实分布做 KL/覆盖率对比、留出真实 held-out。
9. 看**边际收益**：先在小模型上做「加合成数据 vs 不加」的对照，看下游任务通过率，而不是看 loss。
10. 它决定了序列长度、embedding 规模、推理成本、多语言公平性 —— 四项全在模型训练之前就锁死了。

</details>

## B 组 · 架构（W3）· 12 题

11. 写出 self-attention 的完整计算式，标出每一步的显存占用。
12. 为什么 softmax 的雅可比是 `diag(p) - pp^T`？
13. MHA → MQA → GQA → MLA，每一步在拿什么换什么？
14. GQA 的 group 数从 8 降到 1 会怎样？从 8 升到 32 呢？
15. KV cache 的大小公式怎么写？哪些项可以量化？
16. RoPE 相比绝对位置编码好在哪？它怎么支持长度外推？
17. NTK-aware 插值和 YaRN 的核心区别？
18. MoE 的负载不均衡会导致什么？auxiliary loss 的副作用是什么？
19. 共享专家（shared expert）解决了什么问题？
20. Pre-LN 和 Post-LN 哪个训练更稳？代价是什么？
21. RMSNorm 相比 LayerNorm 省了什么？为什么可以省？
22. 一个 7B 模型，hidden=4096、32 层、32 头，KV cache 在 8K 上下文下占多少 GB（FP16）？

<details><summary>参考要点（B 组）</summary>

11. `Q=XWq, K=XWk, V=XWv`；`S=QKᵀ/√d`（B×T×T，**最占显存的一项**）；`A=softmax(S)`；`O=AV`。T=8K 时 S 是 64M 元素/样本。
12. 对 `p_i = e^{x_i}/Σe^{x_j}` 求导：`∂p_i/∂x_j = p_i(δ_ij - p_j)`，写成矩阵即 `diag(p) - ppᵀ`。
13. MHA→MQA：KV 从 h 份减到 1 份（省显存，掉质量）；→GQA：折中成 g 份；→MLA：用低秩压缩 KV（省得更多，但要额外计算）。
14. group=1 退化成 MQA，质量下降明显；group=32（=头数）退化成 MHA，KV cache 涨 32 倍。
15. `2 × layers × kv_heads × head_dim × seq_len × batch × dtype_bytes`。可量化的是 KV 的存储精度（FP8/INT8）。
16. 相对位置内积只依赖偏移量 m-n，有平移不变性；通过调整旋转基底频率可做外推（NTK 改 base，YaRN 加温度缩放）。
17. NTK 改的是 RoPE 的 base（频率分布），是「拉伸」；YaRN 在 NTK 基础上加**注意力温度校正**，是「拉伸 + 补偿」。
18. 少数专家被打爆、多数闲置 → 有效参数量暴跌、训练不稳。aux loss 的副作用：**干扰主任务梯度**，太大会降低质量。
19. 共享专家吸收通用知识，让路由专家专注差异化 —— 减少专家冗余。
20. Pre-LN 更稳（残差路径干净），代价是**表达力略降**、深层可能需要 final LN。
21. 省掉均值中心化（不减均值、不加 bias），因为只是缩放不改变方向；实测效果相当且更快。
22. KV = 2 × 32 × 32 × 128 × 8192 × 2B ≈ **4.3 GB**（每样本，GQA 未用时）。

</details>

<details><summary>参考要点（C 组）</summary>

23. Kaplan 说「参数优先」，Chinchilla 用更多数据、更小模型达到同样 loss —— 数据与参数应同比例增长。
24. 固定算力 C=6ND 下最小化 loss 的解，在不同 E/A/B 参数下会变。数据受限、或推理成本权重高时都不成立（推理密集场景应更小模型）。
25. 用 Adam 拟合 E、logA、logB、α、β 五个参数。取 log 是因为 A、B 跨越 1e1~1e9 量级，直接梯度会崩。
26. R² 只衡量「在已有数据范围内」的拟合程度，不含任何外推信息。外推误差要靠**留出最大点**来测。
27. 检验「用小规模预测大规模」的能力 —— 这才是规模化正确性要问的问题。
28. α 和 β 不可识别：模型可以随便分配参数与数据的功劳，拟合出的指数无意义（本轮实测出现 β>α、tokens/param=0 的荒谬结果）。
29. ① 多轮 epoch（代价：过拟合、收益递减）② 合成数据（代价：分布收窄、污染）③ 提高数据质量/换 domain（代价：成本高、覆盖窄）。
30. 参数 7B×2B=14GB；梯度 14GB；AdamW 的 m+v 各 28GB（FP32）→ 优化器状态 56GB。合计 **84GB**（不含激活）。
31. ZeRO-1 分片优化器状态；ZeRO-2 再分片梯度；ZeRO-3 再分片参数。
32. 因为 TP 每层都要 all-reduce，通信量与层数成正比；跨机带宽远低于 NVLink，会成为瓶颈。
33. 浮点加法不满足结合律，切分方式改变梯度累加顺序，loss 曲线出现细微差异；小规模调好的超参在 TP=8 时可能直接崩。
34. E4M3（4 位指数、3 位尾数）精度高、动态范围小 → 用于**前向的权重/激活**；E5M2 动态范围大、精度低 → 用于**反向的梯度**（梯度量级跨度大）。

</details>

## D 组 · 量化与推理（W7）· 10 题

35. 权重量化、激活量化、KV cache 量化，三者收益分别体现在哪？
36. 什么是 outlier？为什么它是量化的万恶之源？
37. SmoothQuant 的核心思想，一句话说清。
38. per-tensor / per-channel / per-group(128) 三种 scale 粒度，怎么选？
39. GPTQ 和 AWQ 的核心差异？
40. 为什么 KV cache 量化在长上下文场景收益最大？
41. 投机解码的加速比由什么决定？
42. FP8 训练为什么要做 delayed scaling？scale 怎么定？
43. INT4 权重量化后，为什么通常还要保留一部分层在 FP16？
44. 一个 70B 模型，FP8 相比 BF16 能省多少显存？推理速度提升是否等比？

<details><summary>参考要点（D 组）</summary>

35. 权重量化省**显存和带宽**（影响 decode 速度）；激活量化省**计算**（影响 prefill）；KV cache 量化省**长上下文的显存**。
36. 极少数绝对值极大的元素，会逼你把整个 tensor 的 scale 拉大，导致 99% 的正常值精度损失。
37. 把激活的 outlier「搬」到权重上 —— 因为权重是静态的、好处理，激活是动态的、难处理。
38. 粒度越细越准、开销越大。权重用 per-channel，激活用 per-tensor（动态量化时）或 per-token，工业常用 per-group 128。
39. GPTQ 用二阶信息（Hessian）做逐列误差补偿；AWQ 认为「重要权重由激活分布决定」，按激活幅度保护显著通道。
40. KV cache 大小与 seq_len 线性相关，上下文越长占比越大，量化收益越显著。
41. draft model 的接受率（acceptance rate）× draft 与 target 的速度比。
42. 因为 FP8 动态范围窄，需要根据历史最大值滚动确定 scale，避免溢出/下溢。
43. 因为某些层（如第一层、最后一层、norm）对量化误差极敏感，混精可显著减少质量损失。
44. 显存约省一半（70B×2B=140GB → 70GB）；decode 速度提升接近 2×（受带宽限制），但**不是等比**（有 kernel 开销、scale 计算）。

</details>

<details><summary>参考要点（E 组）</summary>

45. 主要是**格式**（怎么说话、什么结构）。它只能模仿示范者，不能超越。
46. 因为 prompt 部分是输入不是答案，算了会让模型学「生成用户的问题」。
47. 成因：分布偏移 + 全部参数更新。缓解：数据混比（掺预训练数据）、LoRA（只训部分参数）、replay（回放旧数据）。
48. 示范者的水平上限。SFT 不能创造比示范更好的策略。
49. ① SFT 建立基础能力 ② RM 学会人类偏好 ③ PPO 按偏好优化策略。
50. 四个：policy、ref、reward、value。显存约为 4× 模型 + 优化器状态。
51. `L = -log σ( β·log(π(y_w|x)/π_ref(y_w|x)) − β·log(π(y_l|x)/π_ref(y_l|x)) )`
52. β 控制偏离 ref 的强度。β→0：不限约束，退化成纯 MLE（无偏好）；β→∞：退化成与 ref 完全一致（不学习）。
53. 没有省掉 —— 它把奖励**隐式内化**成 policy 与 ref 的 log-ratio。代价是失去单独训练/检查/修正 RM 的能力。
54. 因为长度与 log-prob 相关，长答案的 log-ratio 累积更大，β 缩放后天然被偏好。
55. RLVR 的奖励是**判定的**（测试过不过），RLHF 的奖励是**学出来的**（RM 打分）。
56. ① 硬编码测试用例 ② 绕过检查（`except: pass`）③ 学会「让测试跑完」而不是「解决问题」。
57. ① held-out 测试集（模型看不到）② 代码审查/静态检查 ③ 多目标评分（不只看通过数）。
58. RLVR 是「**外置**的自净化」（用测试当裁判）；自净化是把它**内化**到模型里。前者是后者的训练手段。

</details>

<details><summary>参考要点（F 组）</summary>

59. Thought（推理）→ Action（调工具）→ Observation（结果）。
60. 描述越具体越好。「查询用户信息」vs「根据 user_id 查用户，返回 name/email/created_at，user_id 为 8 位数字字符串」—— 后者调用成功率高一个量级。

62. **忘了自己在干嘛**（目标漂移），不是智商不够。
63. 短期=context window；长期=外部存储/向量库；工作记忆=scratchpad/中间文件。
64. 把目标从 context 里**搬到 context 外的显式状态**（文件、结构化 schema），每次重新注入。
65. context 会被压缩、截断、丢失；**文件不会**。文件是可验证的持久状态。
66. 目标、已完成步骤、当前状态、待办、可回滚点。
67. 因为 Agent 会重试。非幂等操作（转账、发消息、建文件）重试会造成重复副作用。
68. **状态不同步** —— 各方对"现在做到哪了"的认知不一致。
69. 「**连续 N 步不失败的概率**」或「任务完成率 @ N 次尝试」。不要用单次成功率。
70. ① 目标无法清晰定义 ② 失败成本极高不可回滚 ③ 任务太短（Agent 开销 > 收益）④ 需要人类判断的责任场景。

</details>
