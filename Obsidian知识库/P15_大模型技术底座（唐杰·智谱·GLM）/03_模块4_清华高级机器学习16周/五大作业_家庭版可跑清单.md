# 五大作业 · 家庭版可跑清单

> 清华那门课的五个作业是真刀真枪。**我们没卡**，但可以按三档降级：
> 🟢 **本机可跑**（CPU/内存）｜🟡 **需租单卡**（¥2-6/小时）｜🔴 **需多卡**（本机与租卡都不划算，只做代码研读）
> 目标不是"完成作业"，是**让汤小龙真的懂每一步在干什么**。

## 总览：三个档位怎么分

| 作业 | 官方要求 | 本机档位 | 降级方案 |
|---|---|---|---|
| HW1 Tokenizer+Transformer+0.1B | 端到端训 0.1B | 🟢 缩版可跑 / 🟡 正式版 | 0.01B 字符级，CPU 可训 |
| HW2 洗语料 + scaling law 外推 | 拟合再外推 | 🟢 **完全可跑** | 小语料 + 4 个尺寸拟合 |
| HW3 Triton attention kernel | 多卡测增益 | 🔴 只读代码 | 无 N 卡，不硬凑 |
| HW4 SFT/DPO/RLVR 对照 | 同基座三路对照 | 🟡 租单卡 | LoRA + 小模型 |
| HW5 可验证环境 + harness + 长程 Agent | 训长程 Agent | 🟢 **完全可跑** | 纯 API，不需要卡 |

## HW1 · 从零写 Tokenizer + Transformer，训 0.1B

### 官方要求
不用现成模型层，自己实现 BPE/Unigram 分词器 + 多头注意力 + 完整训练循环，端到端训出 0.1B 参数模型。

### 🟢 本机降级版（今天就能跑）
**目标**：训一个 **10M 参数**的字符级 GPT，在 CPU 上跑通全流程。

```python
# 骨架（nanoGPT 思路，自己写，不抄库）
# 1) Tokenizer：字符级 → 先跑通，再升级 BPE
chars = sorted(set(text)); stoi = {c:i for i,c in enumerate(chars)}

# 2) 模型：4 层 / 4 头 / d_model=256 / ctx=256  → 约 10M 参数
class Block(nn.Module):   # LayerNorm → MHA(因果mask) → 残差 → MLP → 残差
class GPT(nn.Module):     # Embedding + PosEmb + N×Block + LN + Linear

# 3) 训练：AdamW + 余弦退火 + 梯度裁剪，batch=32, 2000 步
```

**验收硬指标**（不是"跑完了"）：
- loss 从 ~4.2 降到 **< 2.0**
- 采样输出出现**成词片段**（不是乱码）
- 参数量 `sum(p.numel())` 打印出来 ≈ 10M

**耗时**：CPU 约 40-90 分钟。**产出**：`hw1_gpt.py` + loss 曲线图 + 200 字采样样本。

### 🟡 正式版（租一张 4090）
- 升级 BPE（`tokenizers` 库自己训一个 8K 词表）
- 模型放大到 0.1B（d_model=768, 12 层, 12 头）
- 数据：TinyStories 或中文小语料 1-2GB
- **成本**：约 6-10 小时 × ¥2-3/时 ≈ **¥20-30**
- 验收：val loss < 1.6，能续写连贯段落

## HW2 · 洗语料 + 拟合 Scaling Law 再外推 🟢

**这是五个作业里最适合我们的**——不需要卡，纯算力小，但**含金量极高**。

### 步骤
1. **洗语料**：从 raw dump（网页/书籍）做
   - 去重（MinHash 模糊去重，官方说代码去重后唯一 token **+28%**）
   - 质量过滤（语言识别、困惑度过滤、规则清洗）
   - 输出：`clean.jsonl` + **清洗前后 token 数与去重率报表**
2. **训 4 个尺寸**：1M / 3M / 10M / 30M 参数，各训到相近 token 数
3. **拟合**：`L(N) = L∞ + a·N^(-α)`（Chinchilla 形式，可加 data 项）
4. **外推**：预测 100M 的 loss，然后**真的训一个 100M 验证预测误差**

### 本机可行性
🟢 **完全可跑**。4 个小模型 × CPU 各 30-60 分钟，一晚跑完。

### 验收硬指标
- 拟合 **R² > 0.98**
- 外推预测 100M 的 loss，实测误差 **< 8%**
- **预测错了要如实写"为什么错"** —— 这才是科研训练

### 为什么这个作业最值钱
唐杰课上讲的"涌现能力其实和 loss 关系更直接"——**你自己拟合一次 scaling law，就再也不会被"涌现"话术忽悠**。这是判断力的来源。

## HW3 · 手写 Triton Attention Kernel 🔴

### 为什么标红
- Triton 本质是 **NVIDIA GPU 专用**（有 AMD/CPU 后端但生态弱）
- 本机**无独显** → 写出来也**无法验证性能增益**
- 多卡训练增益测试更不可能

### 我们的替代做法（诚实版）
1. **读**：Triton 官方 `fused-attention` tutorial + FlashAttention-2 论文，写**逐行注释版笔记**
2. **写**：在 CPU 上用 NumPy 实现**分块（tiling）注意力**，验证**数值等价性**（与朴素实现 diff < 1e-5）
3. **算**：用 FLOPs 与内存访问量**手推**为什么分块能减少 HBM 读写（理论推导，不测实机）
4. **标注**：明确写"性能数字未实测，因本机无 CUDA 设备"

> 这一条**不许假装跑过**。写"理论推导 + 数值等价验证"，比伪造 benchmark 强一万倍。

## HW4 · SFT / DPO / RLVR 三路对照 🟡

### 官方要求
同一基座上分别做 SFT、DPO、RLVR，横向对照效果。

### 🟡 降级方案（租单卡 或 用 API）
- 基座：**Qwen3-0.6B / 1.7B**（LoRA 单卡可跑）
- 数据：300-1000 条自建指令数据（可用我们接单的真实问答）
- 三路：
  - **SFT**：标准交叉熵
  - **DPO**：偏好对（chosen/rejected）
  - **RLVR**：可验证奖励（数学题对答案 / 代码过单测 / JSON 合规）
- **成本**：单卡 4-8 小时 ≈ ¥15-30

### 对照维度（别只看 loss）
| 维度 | 怎么测 |
|---|---|
| 任务准确率 | 同一测试集三路对比 |
| 输出稳定性 | 同 prompt 跑 5 次，看一致性 |
| 长度膨胀 | DPO 常见"越训越长"，要统计平均长度 |
| 训练成本 | 步数 × 时长 × 单价 |

### 如果连租卡都不行
→ 用 API 做"提示词级对照"：同一任务用 few-shot / CoT / 自洽投票三路，得出**工程结论**，明确标注"非训练级对照"。

## HW5 · 可验证环境 + Harness + 长程 Agent 🟢

**这个不需要卡，纯工程，而且最贴近我们的接单业务。**

### 要搭什么
```
task_spec（任务定义，含成功判据）
    ↓
verifiable_env（可验证环境：能自动判对错）
    ↓
harness（跑批：多轮、多轨迹、记录每步状态）
    ↓
agent_policy（模型 + 工具 + 记忆）
    ↓
self-judge loop（自评 → 返修 → 再评，最多 N 轮）
    ↓
report（通过率 / 平均轮数 / 失败归因分布）
```

### 具体落地（用我们的真实业务）
- **任务**：给定客户需求 → 产出交付物（如一段宣传文案 / 一个数据表）
- **verifiable_env**：写死判据（字数、必含要素、JSON schema、禁用词）
- **长程**：要求 Agent 必须经过「生成 → 自检 → 返修 → 复检」至少 3 轮
- **self-judge loop**：用另一个模型实例做评审，打分不过就返修

### 验收硬指标
- 通过率从 baseline 提升 **≥ 15 个百分点**
- **失败归因表**：必须分类（理解错 / 工具用错 / 判据不清 / 模型能力不足）
- 平均轮数 ≤ 5（轮数爆炸说明 loop 设计有问题）

> 这个作业做完，**可以直接变成我们接单流水线的一个模块**，不是白做。
