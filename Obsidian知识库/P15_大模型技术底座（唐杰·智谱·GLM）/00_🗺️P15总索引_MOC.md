## 四、抓取边界（R2 更新 · ★ 上一轮结论被推翻）

> **2026-11-02 09:40 重要更正**：上一轮（R1）写「沙箱到境外 502，PDF/clone 不可用」——
> **这条是错的。** 真因是**沙箱注入了死代理** `http://127.0.0.1:53468`（没人监听），
> `urllib` 从 Windows 注册表读它，清环境变量无效。
> 用 `build_opener(ProxyHandler({}))` 绕开后：**GitHub API 200、arXiv PDF 200、COS 200**。

> **教训（比结论本身值钱）**：`curl --noproxy '*'` 返 `000` **不等于机器无网**。
> 分流判据：`socket.create_connection` 通 + HTTPS 报 `502 Tunnel` = **代理污染**；TCP 也超时 = 真无网。

> **★ R3 补第二条教训：同一个 GitHub 仓库，换个接口快 77 倍。**
> `raw.githubusercontent.com` 拉 15 KB 的 README 要 **63 秒**，稍大就 `TimeoutError`；
> `api.github.com/repos/{o}/{r}/contents/{path}` 同一文件 **815 毫秒**（返回 base64）。
> 上一轮把 8 个失败**误判成 404**，因为脚本 `except` 只写了 `FAIL`、把错误原文丢了。
> → **定理：失败分支必须落错误原文；GitHub 抓文件首选 contents API，raw 只作兜底。**
