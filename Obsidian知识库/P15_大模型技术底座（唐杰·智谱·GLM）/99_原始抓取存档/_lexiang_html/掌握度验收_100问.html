A 组 · 数据与 Tokenizer（W2）· 10 题

  • BPE 训练时，为什么 vocab_size 必须大于 256？
  • vocab 从 32K 扩到 128K，embedding 参数怎么变？输出层呢？
  • 同样的中文句子，中文词表偏小的 tokenizer 会多花几倍 token？为什么？
  • 语料去重做到 90% 和做到 60%，分别会导致什么后果？哪个更危险？
  • MinHash + LSH 为什么能近似 Jaccard 相似度？
  • 质量过滤常见的三类信号是什么？
  • 数据配比里「课程学习」指的是什么？为什么后喂的数据影响更大？
  • 合成数据的最大风险是什么？怎么检测？
  • 一个 1T token 的语料，去重后剩 600B，你该不该补合成数据？判断依据是什么？
  • 为什么说 tokenizer 是「唯一一个训练完就冻结、却决定了后面一切」的组件？
<details><summary>参考要点（A 组）</summary>
  • byte-level BPE 初始词表 = 256 个字节。小于 256 时循环条件 nxt < vocab_size 一开始就假，一个 merge 都学不到。
  • embedding = 32K×d → 128K×d，涨 4 倍；输出投影同步涨 4 倍（若不做 tie）。这一项在大模型里可能是几百 M 参数。
  • 中文一个字若被切成 2~3 字节 token，同样语义要付 2~3 倍 token 费用 —— 直接体现在推理账单上。
  • 去重不足（60%）→ 重复数据让模型过拟合、记忆化、评测污染；去重过度（90%）→ 丢掉合法的常见表述，模型语言能力下降。去重不足更危险，因为它会污染评测，让你误判。
  • 用 k 个哈希函数取最小哈希值，两集合最小哈希相等的概率 = Jaccard 相似度。
  • ① 困惑度/模型打分 ② 启发式规则（长度、符号比、重复率）③ 分类器（高质量语料训练的正例判别器）。
  • 先喂通用、后喂高质量/领域数据，让模型「最后记住的」是你要的分布。后喂影响大是因为近因效应 + 学习率退火阶段权重更新更稳。
  • 分布收窄（mode collapse）、错误放大、评测污染。检测：与真实分布做 KL/覆盖率对比、留出真实 held-out。
  • 看边际收益：先在小模型上做「加合成数据 vs 不加」的对照，看下游任务通过率，而不是看 loss。
  • 它决定了序列长度、embedding 规模、推理成本、多语言公平性 —— 四项全在模型训练之前就锁死了。
</details>

<details><summary>参考要点（B 组）</summary>
  • Q=XWq, K=XWk, V=XWv；S=QKᵀ/√d（B×T×T，最占显存的一项）；A=softmax(S)；O=AV。T=8K 时 S 是 64M 元素/样本。
  • 对 p_i = e^{x_i}/Σe^{x_j} 求导：∂p_i/∂x_j = p_i(δ_ij - p_j)，写成矩阵即 diag(p) - ppᵀ。
  • MHA→MQA：KV 从 h 份减到 1 份（省显存，掉质量）；→GQA：折中成 g 份；→MLA：用低秩压缩 KV（省得更多，但要额外计算）。
  • group=1 退化成 MQA，质量下降明显；group=32（=头数）退化成 MHA，KV cache 涨 32 倍。
  • 2 × layers × kv_heads × head_dim × seq_len × batch × dtype_bytes。可量化的是 KV 的存储精度（FP8/INT8）。
  • 相对位置内积只依赖偏移量 m-n，有平移不变性；通过调整旋转基底频率可做外推（NTK 改 base，YaRN 加温度缩放）。
  • NTK 改的是 RoPE 的 base（频率分布），是「拉伸」；YaRN 在 NTK 基础上加注意力温度校正，是「拉伸 + 补偿」。
  • 少数专家被打爆、多数闲置 → 有效参数量暴跌、训练不稳。aux loss 的副作用：干扰主任务梯度，太大会降低质量。
  • 共享专家吸收通用知识，让路由专家专注差异化 —— 减少专家冗余。
  • Pre-LN 更稳（残差路径干净），代价是表达力略降、深层可能需要 final LN。
  • 省掉均值中心化（不减均值、不加 bias），因为只是缩放不改变方向；实测效果相当且更快。
  • KV = 2 × 32 × 32 × 128 × 8192 × 2B ≈ 4.3 GB（每样本，GQA 未用时）。
</details>

<details><summary>参考要点（C 组）</summary>
  • Kaplan 说「参数优先」，Chinchilla 用更多数据、更小模型达到同样 loss —— 数据与参数应同比例增长。
  • 固定算力 C=6ND 下最小化 loss 的解，在不同 E/A/B 参数下会变。数据受限、或推理成本权重高时都不成立（推理密集场景应更小模型）。
  • 用 Adam 拟合 E、logA、logB、α、β 五个参数。取 log 是因为 A、B 跨越 1e1~1e9 量级，直接梯度会崩。
  • R² 只衡量「在已有数据范围内」的拟合程度，不含任何外推信息。外推误差要靠留出最大点来测。
  • 检验「用小规模预测大规模」的能力 —— 这才是规模化正确性要问的问题。
  • α 和 β 不可识别：模型可以随便分配参数与数据的功劳，拟合出的指数无意义（本轮实测出现 β>α、tokens/param=0 的荒谬结果）。
  • ① 多轮 epoch（代价：过拟合、收益递减）② 合成数据（代价：分布收窄、污染）③ 提高数据质量/换 domain（代价：成本高、覆盖窄）。
  • 参数 7B×2B=14GB；梯度 14GB；AdamW 的 m+v 各 28GB（FP32）→ 优化器状态 56GB。合计 84GB（不含激活）。
  • ZeRO-1 分片优化器状态；ZeRO-2 再分片梯度；ZeRO-3 再分片参数。
  • 因为 TP 每层都要 all-reduce，通信量与层数成正比；跨机带宽远低于 NVLink，会成为瓶颈。
  • 浮点加法不满足结合律，切分方式改变梯度累加顺序，loss 曲线出现细微差异；小规模调好的超参在 TP=8 时可能直接崩。
  • E4M3（4 位指数、3 位尾数）精度高、动态范围小 → 用于前向的权重/激活；E5M2 动态范围大、精度低 → 用于反向的梯度（梯度量级跨度大）。
</details>

D 组 · 量化与推理（W7）· 10 题

  • 权重量化、激活量化、KV cache 量化，三者收益分别体现在哪？
  • 什么是 outlier？为什么它是量化的万恶之源？
  • SmoothQuant 的核心思想，一句话说清。
  • per-tensor / per-channel / per-group(128) 三种 scale 粒度，怎么选？
  • GPTQ 和 AWQ 的核心差异？
  • 为什么 KV cache 量化在长上下文场景收益最大？
  • 投机解码的加速比由什么决定？
  • FP8 训练为什么要做 delayed scaling？scale 怎么定？
  • INT4 权重量化后，为什么通常还要保留一部分层在 FP16？
  • 一个 70B 模型，FP8 相比 BF16 能省多少显存？推理速度提升是否等比？
<details><summary>参考要点（D 组）</summary>
  • 权重量化省显存和带宽（影响 decode 速度）；激活量化省计算（影响 prefill）；KV cache 量化省长上下文的显存。
  • 极少数绝对值极大的元素，会逼你把整个 tensor 的 scale 拉大，导致 99% 的正常值精度损失。
  • 把激活的 outlier「搬」到权重上 —— 因为权重是静态的、好处理，激活是动态的、难处理。
  • 粒度越细越准、开销越大。权重用 per-channel，激活用 per-tensor（动态量化时）或 per-token，工业常用 per-group 128。
  • GPTQ 用二阶信息（Hessian）做逐列误差补偿；AWQ 认为「重要权重由激活分布决定」，按激活幅度保护显著通道。
  • KV cache 大小与 seq_len 线性相关，上下文越长占比越大，量化收益越显著。
  • draft model 的接受率（acceptance rate）× draft 与 target 的速度比。
  • 因为 FP8 动态范围窄，需要根据历史最大值滚动确定 scale，避免溢出/下溢。
  • 因为某些层（如第一层、最后一层、norm）对量化误差极敏感，混精可显著减少质量损失。
  • 显存约省一半（70B×2B=140GB → 70GB）；decode 速度提升接近 2×（受带宽限制），但不是等比（有 kernel 开销、scale 计算）。
</details>

<details><summary>参考要点（E 组）</summary>
  • 主要是格式（怎么说话、什么结构）。它只能模仿示范者，不能超越。
  • 因为 prompt 部分是输入不是答案，算了会让模型学「生成用户的问题」。
  • 成因：分布偏移 + 全部参数更新。缓解：数据混比（掺预训练数据）、LoRA（只训部分参数）、replay（回放旧数据）。
  • 示范者的水平上限。SFT 不能创造比示范更好的策略。
  • ① SFT 建立基础能力 ② RM 学会人类偏好 ③ PPO 按偏好优化策略。
  • 四个：policy、ref、reward、value。显存约为 4× 模型 + 优化器状态。
  • L = -log σ( β·log(π(y_w|x)/π_ref(y_w|x)) − β·log(π(y_l|x)/π_ref(y_l|x)) )
  • β 控制偏离 ref 的强度。β→0：不限约束，退化成纯 MLE（无偏好）；β→∞：退化成与 ref 完全一致（不学习）。
  • 没有省掉 —— 它把奖励隐式内化成 policy 与 ref 的 log-ratio。代价是失去单独训练/检查/修正 RM 的能力。
  • 因为长度与 log-prob 相关，长答案的 log-ratio 累积更大，β 缩放后天然被偏好。
  • RLVR 的奖励是判定的（测试过不过），RLHF 的奖励是学出来的（RM 打分）。
  • ① 硬编码测试用例 ② 绕过检查（except: pass）③ 学会「让测试跑完」而不是「解决问题」。
  • ① held-out 测试集（模型看不到）② 代码审查/静态检查 ③ 多目标评分（不只看通过数）。
  • RLVR 是「外置的自净化」（用测试当裁判）；自净化是把它内化到模型里。前者是后者的训练手段。
</details>

<details><summary>参考要点（F 组）</summary>
  • Thought（推理）→ Action（调工具）→ Observation（结果）。
  • 描述越具体越好。「查询用户信息」vs「根据 user_id 查用户，返回 name/email/created_at，user_id 为 8 位数字字符串」—— 后者调用成功率高一个量级。
  • 0.99²⁰ ≈ 81.8%。说明长任务的可靠性是乘性的，单步 1% 的失败率会被放大 20 倍。
  • 忘了自己在干嘛（目标漂移），不是智商不够。
  • 短期=context window；长期=外部存储/向量库；工作记忆=scratchpad/中间文件。
  • 把目标从 context 里搬到 context 外的显式状态（文件、结构化 schema），每次重新注入。
  • context 会被压缩、截断、丢失；文件不会。文件是可验证的持久状态。
  • 目标、已完成步骤、当前状态、待办、可回滚点。
  • 因为 Agent 会重试。非幂等操作（转账、发消息、建文件）重试会造成重复副作用。
  • 状态不同步 —— 各方对"现在做到哪了"的认知不一致。
  • 「连续 N 步不失败的概率」或「任务完成率 @ N 次尝试」。不要用单次成功率。
  • ① 目标无法清晰定义 ② 失败成本极高不可回滚 ③ 任务太短（Agent 开销 > 收益）④ 需要人类判断的责任场景。
</details>

<details><summary>参考要点（G 组）</summary>
  • ① projector（MLP 映射，LLaVA 式）② cross-attention（Flamingo 式）③ early fusion（原生多模态）。
  • (1024/14)² ≈ 73² ≈ 5329 个 patch token。这意味着一张图的成本约等于 5000 字文本。
  • 训练数据配比被稀释 —— 加视觉数据必然减少文本数据占比，而模型容量有限。
  • 让视觉数据带语言监督（图像描述、VQA 的答案本身是语言），使视觉训练同时强化语言。
  • 按事件密度自适应采样（关键帧检测），而不是固定 FPS；长视频分层采样（粗→细）。
  • ① 数据污染（训练集见过）② 饱和（都刷到 90+，失去区分度）③ 与真实任务脱节。
  • ① n-gram 重叠检测（测试集与训练集）② 改写扰动测试（改数字/换名词，分数应稳定）③ 时间切分（用截止日期后数据）。
  • 长度偏好、位置偏好（偏好第一个）、自我偏好（偏好同模型输出）、格式偏好（偏好 Markdown）。
  • 单点准确率看「平均对多少」；任务级看「整个任务能不能跑完」。
  • 因为用户体验是乘性的：任何一步崩了，用户就失败了。99% 单步 × 20 步 = 82%。
  • 「基准测试分数一直在涨，但真实世界模型调用量（如 OpenRouter 流量）停住了」。榜单可被优化，调用量是钱投出来的票。
  • 不看分数，跑客户场景的真实 case 50 个，报端到端通过率 + 失败模式分类。
</details>
