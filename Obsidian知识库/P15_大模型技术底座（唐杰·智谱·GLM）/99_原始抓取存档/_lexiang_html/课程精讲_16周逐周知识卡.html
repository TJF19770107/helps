16 周逐周精讲

与 课程总览_16周大纲.md 的分工：那份是大纲（讲什么），这份是精讲（每一讲讲透了什么 + 怎么自检学会了没有）。
每讲固定四段：① 核心问题 ② 必须掌握的概念 ③ 关键洞察（老师的私货）④ 自检题（答不上就是没学会）。
置信度：W1 / W6 / W10 / W16 与五大作业为事实；中间周次按作业梯度反推，标 [推演]。

全课骨架一句话

这门课不是「机器学习导论 2.0」，而是「如何从零造一个大模型，并且证明它真的行」。
主线：数据 → 结构 → 规模 → 对齐 → 做事 → 证明。
它的独特性在于：五个作业串起来 = 一个完整的大模型研发闭环，而不是五个孤立实验。

第一阶段：从零造出一个小模型（W1–W5）

W1 · 导论：这门课到底在教什么 [事实]

核心问题：为什么在 2026 年，还要从零写 Tokenizer 和 Transformer？

必须掌握

  • 大模型技术栈的五层：数据 → 结构 → 训练 → 对齐 → 系统
  • 「能力」与「可验证性」的区别（贯穿全课的主轴）
  • 为什么 0.1B 的小模型能验证 100B 的思路（缩放验证法）

关键洞察

唐杰在第一课就定了调：你要能自己造一个，才有资格评价别人的。
0.1B 不是为了省钱，是为了建立可复现的对照组。没有对照组，所有结论都是玄学。

自检题

  • 为什么 0.1B 模型上的结论不能直接外推到 100B？失效可能在哪几个环节？（提示：六维）
  • 「从零实现」和「调库微调」在认知上差在哪？各能学到什么、学不到什么？

W2 · 数据：Tokenizer 与语料工程

核心问题：为什么 BPE 的 vocab size 是一个架构决策，不是超参数？

必须掌握

  • BPE / WordPiece / Unigram 的算法差异与适用场景
  • vocab size 如何同时影响：序列长度 × embedding 参数量 × 推理成本 × 多语言公平性
  • 语料清洗四件套：去重（MinHash/LSH）、质量过滤、毒性过滤、PII 脱敏
  • 数据配比与「课程学习」：什么先喂、什么后喂

关键洞察

Tokenizer 是唯一一个「训练完就冻结、但决定了后面一切」的组件。
分词错了，模型再大也在补偿一个错误的表示。中文尤其明显：词表偏英文，中文一个字被切成 2~3 个 token，同样的语义你要付 2~3 倍的钱。
→ 这是「为什么国产模型必须自建 tokenizer」的根本原因，不是民族情绪，是成本结构。

自检题

  • 两个模型参数量相同但 vocab 不同（32K vs 128K），推理成本谁高？为什么答案不是显然的？
  • 语料去重做到 90% 和 60%，分别会导致什么后果？哪个更可怕？

W3 · 结构：Transformer 与它的现代变体

核心问题：Attention 的 O(n²) 到底卡在哪，现代架构各自让了什么步？

必须掌握

  • Self-Attention 的完整计算图与显存占用拆解（QKV、scores、softmax、AV）
  • MHA → MQA → GQA → MLA 的演进：每一步在拿什么换什么
  • RoPE 的位置编码原理与长度外推（NTK / YaRN）
  • MoE：专家数、激活专家数、共享专家、负载均衡损失
  • 归一化位置（Pre-LN / Post-LN / RMSNorm）对训练稳定性的影响

关键洞察

注意力的每一次优化，本质都是「少算一些不该算的关系」。
GQA 是「让多个头共享 KV」；稀疏注意力是「只保留 top-k 关系」；MoE 是「只激活部分专家」。
这和唐杰 2019 讲 GNN 时的 GraphSAGE 是同一个动作：采样邻居。
→ 读懂这条线，你就理解了整个架构演进史：不是越来越复杂，是越来越会「挑」。

自检题

  • GQA 里 group 数从 8 降到 1 会发生什么？从 8 升到 32 呢？画出 KV cache 大小的曲线。
  • MoE 的负载不均衡会导致什么？为什么必须要 auxiliary loss，它又带来了什么副作用？

W4 · 规模：Scaling Law 与它的失效

核心问题：Chinchilla 定律说了什么，又错在哪？

必须掌握

  • Kaplan vs Chinchilla：参数与数据的配比之争（20 token/param 的经验值从哪来）
  • 幂律拟合方法：怎么用 5 个点的 loss 拟合出一条能外推的曲线
  • 推演：scaling law 只拟合 loss，不保证下游任务正确性 —— 这正是唐杰 2026 提出「规模化正确性」的课堂源头
  • 数据受限时代的应对：多轮 epoch、合成数据、数据质量优先

关键洞察

Scaling Law 是一条「拟合出来的经验规律」，不是「推导出来的物理定律」。
它告诉你 loss 会降，没告诉你降了 loss 之后模型会不会骗人、会不会跑不通代码、会不会在长任务里崩。
→ 这就是为什么 2026 年唐杰要提「规模化正确性」：loss 曲线是给投资人看的，可验证通过率才是给用户看的。

自检题

  • 给定 3 组 (params, tokens, loss)，怎么拟合出 a、b 指数？如果只有 2 组数据能拟合吗？
  • 为什么「数据用完了」会打破 Chinchilla 的最优配比？此时应该往哪个方向走？

W5 · 系统：分布式训练与并行策略

核心问题：为什么并行不是「加速手段」，而是改变数值行为的东西？

必须掌握

  • 三种并行的切分维度：数据并行（DP）、张量并行（TP）、流水线并行（PP）
  • ZeRO 三阶段：优化器状态 / 梯度 / 参数的分片
  • 通信原语：all-reduce、all-gather、reduce-scatter 的代价模型
  • 混合精度：BF16 / FP16 / FP8，loss scaling 与溢出处理
  • 显存账本：参数 + 梯度 + 优化器状态 + 激活值，各占多少

关键洞察

并行会改变结果。 浮点加法不满足结合律，切分方式一变，梯度累加顺序就变，loss 曲线的细微差异就出现。
小规模调试出来的「稳定配置」，在 TP=8 时可能直接崩 —— 这是唐杰六维里「并行与系统工程」那一维。
→ 凡是没在目标并行度上验证过的超参，都不算调好。

自检题

  • 一个 7B 模型用 AdamW 训练，纯参数/梯度/优化器状态各占多少 GB？BF16 下总共多少？
  • TP 从 1 到 8，通信量增长几倍？为什么 TP 一般不超过单机 GPU 数？

第二阶段：中期检验（W6）

W6 · Proposal：选题与方案设计 [事实]

核心问题：什么是一个「可被证伪」的研究提案？

必须掌握

  • 提案的四要素：问题 / 假设 / 方法 / 判据
  • 判据必须是可测量的，不能是「效果更好」
  • 2–3 人组队分工模式

关键洞察

唐杰的评分逻辑（作业 40% + Final 60%）说明一件事：
他给的分数主要不看你做成了什么，看你能不能说清「怎么算成功」。
这和「自净化」是同一件事：能不能准确判断这一步是不是进步。

自检题

  • 「我的方法比 baseline 好」为什么不是判据？改成可证伪的说法。
  • 如果你的实验跑出来是负结果，什么样的负结果仍然算成功？

第三阶段：让它变便宜、变听话（W7–W11）

W7 · 高效推理：量化、KV Cache、投机解码

核心问题：FP8 到底省了什么，代价是什么？

必须掌握

  • 权重量化 vs 激活量化 vs KV cache 量化（三者收益完全不同）
  • FP8 的两种格式：E4M3（权重/激活）vs E5M2（梯度），为什么这么分
  • per-tensor / per-channel / per-group(128) 的 scale 粒度
  • SmoothQuant 的核心：把激活的离群值「搬」到权重上
  • GPTQ / AWQ / GGUF 的适用场景差异
  • 投机解码：draft model 命中率决定加速比

关键洞察

量化的本质不是「降低精度」，是「重新分配动态范围」。
离群值（outlier）是万恶之源：一个 100 倍的激活值，会逼你把整个 tensor 的 scale 拉大，其他 99% 的正常值全部精度损失。
→ SmoothQuant 的聪明之处：不消除离群值，只把它从难处理的地方搬到好处理的地方。
→ 这是一种通用的工程思维：遇到局部极端值，不要硬扛，换位置。

自检题

  • 为什么 FP8 训练能用 E5M2 存梯度，而推理用 E4M3 存权重？
  • KV cache 量化的收益随 batch size 怎么变？为什么长上下文场景收益最大？

W8 · 对齐一：SFT 的工程真相

核心问题：SFT 学到的是「知识」还是「格式」？

必须掌握

  • SFT 的数据构造：指令多样性 > 数量、loss mask（只算回答部分）
  • 灾难性遗忘的成因与缓解（数据混比、LoRA、replay）
  • 多轮对话的数据组织：如何标注「哪一轮该学」
  • 推演：SFT 的天花板在哪 —— 它只能模仿，不能超越示范者的水平

关键洞察

SFT 教的是「怎么说话」，不是「怎么想」。
这就是为什么 SFT 之后模型很流畅但一做实操就废 —— 它学会了语气，没学会推理路径。
→ 所以必然要走 RL。SFT 是化妆，RL 是练肌肉。

自检题

  • 为什么 SFT 数据的 loss mask 必须只算 assistant 部分？不算会怎样？
  • SFT 数据量从 10 万降到 1 万，质量不变，会怎样？从 10 万升到 100 万呢？

W9 · 对齐二：RLHF 与 DPO 的分野

核心问题：DPO 号称「不需要奖励模型」，它真的省了那一步吗？

必须掌握

  • RLHF 三阶段：SFT → Reward Model → PPO
  • PPO 的四个模型（policy / ref / reward / value）与显存代价
  • DPO 的数学：把 reward 隐式表达为 policy 与 ref 的 log-ratio，从而绕开显式 RM
  • DPO 的失效场景：分布外偏好、长度偏置、reward hacking 的变体
  • 长度偏置从哪来（人类偏好长答案）与怎么治

关键洞察

DPO 没有省掉奖励模型，它把奖励模型「内化」成了 ref model 的一个比值。
代价是：你失去了「单独训练、单独检查、单独修正」奖励模型的能力。
→ 这是一个典型的「用一个隐式组件换掉一个显式组件」的交换，省了工程，丢了可控性。
→ 判断标准：你要的是省事，还是要可调试？ toC 选前者，toB 必须选后者。

自检题

  • 写出 DPO 的 loss，并解释 β 的作用：β→0 和 β→∞ 分别退化成什么？
  • 为什么 DPO 会加剧长度偏置？RLHF 会不会？为什么？

W10 · 中期报告 [事实]

核心问题：怎么在 10 分钟内讲清一个还没做完的实验？

必须掌握

  • 结构：动机 → 假设 → 当前进度 → 遇到的坑 → 下一步 → 需要的帮助
  • 关键：主动暴露问题比掩盖问题得分高

关键洞察

中期报告考的不是成果，是判断力。
你能不能分清「这个坑值得填」和「这个方向该放弃」—— 这正是「自净化」在项目管理层面的形态。

自检题

  • 你的实验复现不出 baseline 的分数，中报该怎么写？
  • 什么情况下应该主动砍掉一个已经投入三周的方案？

W11 · RLVR：可验证奖励 —— 本课的灵魂 [推演，但与唐杰2026公开演讲强对应]

核心问题：为什么「可验证」比「人类偏好」更适合训 Agent？

必须掌握

  • RLVR 的奖励来源：单元测试通过率、编译器通过、数学答案比对、工具调用成功
  • 与 RLHF 的本质差异：reward 是「判定的」不是「学出来的」
  • reward hacking 的新形态：模型学会作弊（硬编码测试用例、绕过检查）
  • 训练环境的重要性：真实 repo、真实 Web、真实执行器

关键洞察

唐杰 2026 原话：「Benchmark 成绩并不等于用户体验。能不能一次跑通，才是决定模型价值的关键。」
RLVR 就是把这句话变成训练信号：不看你答得像不像，看你跑不跑得通。
但它有致命弱点：凡是能被验证的，就能被针对。 模型会学会「骗过验证器」而不是「真解决问题」。
→ 所以 RLVR 的核心工程难点不是算法，是反作弊。

自检题

  • 用单元测试当奖励，模型学会「在代码里 if test_name == 'xxx': return True」怎么办？列出三种防御手段。
  • 为什么数学题比写作更适合 RLVR？写作要怎么构造可验证性？

第四阶段：让它做事（W12–W15）

W12 · Agent 基础：工具调用与规划

核心问题：Agent 和「会调函数的 Chatbot」差在哪？

必须掌握

  • ReAct 循环：Thought → Action → Observation
  • 工具 schema 设计：描述质量决定调用成功率
  • Function Calling 的训练数据构造
  • 失败恢复：重试、回退、降级

关键洞察

姚顺雨（腾讯）说 Agent 难点在稳定性不在演示，唐杰说要看能不能一次跑通 —— 两个人说的是同一件事。
Demo 是单次成功，产品是连续 100 次不崩。
→ 衡量 Agent 的正确指标不是「成功率」，是 「连续 N 步不失败的概率」。10 步、每步 95%，整体只有 60%。

自检题

  • 一个 20 步的任务，单步成功率 99%，整体成功率多少？这说明什么？
  • 工具描述写「查询用户信息」和写「根据 user_id 查用户，返回 name/email/created_at，user_id 为 8 位数字字符串」，调用成功率差多少？为什么？

W13 · 长程任务：记忆与状态维护

核心问题：上下文塞满之后，Agent 靠什么不忘记目标？

必须掌握

  • 短期（context）/ 长期（外部存储）/ 工作记忆（scratchpad）三层
  • 上下文压缩策略：摘要、检索、结构化状态
  • 任务分解与子目标管理
  • 中断恢复：checkpoint 与幂等

关键洞察

Agent 崩掉的第一原因不是智商不够，是忘了自己在干嘛。
长任务的关键设计是「把目标从 context 里搬到 context 外的显式状态里」——
因为 context 会被压缩、会被截断，而写在文件里的状态不会。

自检题

  • 一个跑 2 小时的任务，context 只够 30 分钟，怎么设计？
  • 为什么「把每一步写进文件」比「让模型记住」更可靠？

W14 · 多模态

核心问题：为什么加了视觉，语言能力反而退化？

必须掌握

  • 视觉编码器（ViT）与 LLM 的对接方式：projector / cross-attention / early fusion
  • 分辨率与 token 数的权衡
  • 「视觉增强但语言退化」的成因：模态竞争与数据配比
  • 视频理解：时序建模与帧采样

关键洞察

林俊旸（阿里 Qwen）公开讲过这个难题：「视觉增强但语言能力退化」。
根因是训练数据配比变了：加视觉数据必然稀释文本数据，模型容量是有限的。
→ 解法不是「多喂文本」，而是让视觉数据也带语言监督（图像描述、VQA 的答案本身是语言）。

自检题

  • 一张 1024×1024 图用 14×14 patch、patch size 14，产生多少 token？这意味什么成本？
  • 为什么「先训语言再训多模态」比「一起训」效果好？

W15 · 评测：怎么证明它真的行

核心问题：Benchmark 分数和真实可用性差多远？

必须掌握

  • 静态 benchmark 的三大病：数据污染、饱和、与真实任务脱节
  • 动态/对抗评测、私有 held-out 集
  • 人评 vs 模型评（LLM-as-judge 的偏见）
  • 任务级评测：端到端通过率 > 单点准确率

关键洞察

唐杰的「寒冬预警信号」在这里闭环了：
「基准测试上的分数一直在涨，但真实世界的模型调用量却停住了。」
为什么？因为榜单可以被优化，任务不能。
→ 给汤哥的判断法则：客户问「你的方案能打多少分」，正确回答是「我们不看分，看你这个场景的端到端通过率，先跑 50 个真实 case」。

自检题

  • 怎么检测一个 benchmark 被污染了？给三个可操作方法。
  • LLM-as-judge 有哪些系统性偏见？怎么校正？

第五阶段：Final（W16）

W16 · 结题：报告 + 现场 Demo [事实]

核心问题：NeurIPS 格式的英文报告 + 现场 demo，考的是什么？

必须掌握

  • 学术写作结构：Abstract / Intro / Related / Method / Experiments / Analysis / Limitation
  • Limitation 章节不是自曝短板，是展示你懂边界
  • Demo 的稳定性设计：永远准备 fallback 录屏

关键洞察

评分 60% 给 Final，其中 demo 是现场跑。
这门课最后的考点是：你能不能在有人看着、网络不稳定、时间有限的情况下，让东西跑起来。
这就是工程能力，也是唐杰说的「一次跑通」。

自检题

  • 现场 demo 崩了，正确的应对是什么？
  • Limitation 要写几条？写太少和写太多分别说明什么？
