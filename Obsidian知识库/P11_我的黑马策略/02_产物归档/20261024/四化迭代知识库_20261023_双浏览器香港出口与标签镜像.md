> 本轮主题：让**带 AI 标识的 GPT 浏览器**与**港区 Chrome**同时能上币安，并让两边标签页实时同步；

## 零 · 本轮问题（用户原话拆成三层）

| 层 | 诉求 | 真实卡点 |

## 二 · 模块化（五段链路，每段可单独替换）

```
┌──────────────┐   ┌──────────────┐   ┌───────────────┐   ┌──────────────────┐
│ GPT浏览器 A  │   │ 港区Chrome B │   │ 本地桥接 8888 │   │ SSH隧道 3128     │
│ 原profile    │──▶│ 独立profile  │──▶│ 注入Basic认证 │──▶│ →香港xray 3128   │
│ CDP 9334     │   │ CDP 9222     │   │ hk_proxy_     │   │ →服务器侧解析DNS │
└──────┬───────┘   └──────┬───────┘   │ bridge.py     │   └──────────────────┘
       │                  │           └───────────────┘
       └────────┬─────────┘
          ┌─────▼──────┐
          │ tab_mirror │  双向镜像（只镜像新增，不镜像关闭）
          └────────────┘
```

| 模块 | 文件 | 单一职责 |
|---|---|---|
| 出口隧道 | `start_all_hk.py`（ensure_tunnel） | 建 3128 本地转发，**幂等** |
| 认证桥接 | `hk_proxy_bridge.py` | 给 xray 的 Basic 认证注入头，浏览器才不弹框 |
| 浏览器接管 | `start_all_hk.py`（ensure_gpt / ensure_chrome） | 两个 profile 各自带代理启动 |
| 编程控制 | `cdp_tool.py` | list / eval / click-text / newtab，**纯 HTTP+WS，零驱动依赖** |
| 标签镜像 | `tab_mirror.py` | 双向同步 + 心跳 |
| 数据管线 | `币安账户数据/binance_account_pull.py` | 只读 API 拉半年流水 |

**拆分的价值**：某一段坏了只换那一段。例如隧道可换 frp、桥接可换 PAC，浏览器段完全不用动。

## 三 · 自动化（把 6 步手工操作压成 1 条命令）

```bash
python 技能库/墙内到香港出口隧道/start_all_hk.py          # 缺什么补什么
python 技能库/墙内到香港出口隧道/start_all_hk.py --check   # 只体检
python 技能库/墙内到香港出口隧道/start_all_hk.py --kill    # 只停本方案的进程
```

**幂等设计**：每一步先 `port_open()` 探测，已在跑就跳过，绝不重复起实例
（重复起 = 抢端口 + 抢 profile 锁 + 双重镜像互相打架）。

**体检输出（本轮实测）**：

```
[体检]
  ✅ SSH 隧道 3128
  ✅ 桥上代理 8888
  ✅ GPT 浏览器 CDP 9334
  ✅ 港区 Chrome CDP 9222
  ✅ 标签镜像守护
[结论] 全通
```

**心跳机制**：镜像守护每 6 轮必写一条 `[心跳]`。
原因：它没事可做时不写日志 → 日志 mtime 变旧 → 外部判活**误报死亡**（本轮真踩）。
判活阈值 90 秒，心跳周期 30 秒，留 3 倍余量。

## 四 · 智能化（让状态自己说话，不靠人盯）

1. **判活靠"最近一次证据时间"，不靠"进程存不存在"。**
   进程在但线程僵死、端口在但不转发，都是常态。本轮的镜像判活就是这个思路。
2. **CLI 自动分型报错**：`未安装` / `缺密钥(path)` / `失败` / `已在` / `已启动`，
   五态直出，不用人去猜是哪一段断了。
3. **镜像的"只增不减"原则**：关闭动作承载人的意图，机器不该替人做减法。
   这条原则同样适用于后续所有自动化（自动删文件、自动撤单）。
4. **诚实边界内置**：`--check` 不修任何东西，只报事实；`--kill` 只杀带特定命令行特征的进程，
   不碰用户其它 python/ssh 进程。

## 五 · 踩到的真坑（本轮新增 5 条，已写进技能 v1.1.0）

| # | 现象 | 真因 | 正确做法 |
|---|---|---|---|
| 8 | CDP WebSocket 握手 `403 Handshake` | Chromium 111+ 强制校验 WS 的 `Origin` 头 | `suppress_origin=True`，**不用重启浏览器** |
| 9 | 读 `Tabs_*` 报 `PermissionError` | 浏览器运行中独占锁会话文件 | 只在**备份副本**上解析；URL 是明文，正则可捞（捞出 90 条） |
| 10 | 重启后只剩一个空白页 | `taskkill /F` 与 `--restore-last-session` 同时存在时恢复失效 | 能干净退就干净退；强杀后手工点「恢复」或用备份 `Tabs_*` 重开 |
| 11 | 币安中央弹 `not intended for individuals in Hong Kong` | **香港 IP 触发地区提示**，独立于代理的第二层拦截 | `cdp_tool.py click-text --text "I Understand"`；点不到先查 `window.frames` |
| 12 | 点按钮却弹出「修改书签」 | JS 按文本匹配 `[class*="btn"]` **误命中书签栏同名书签** | 匹配串要足够独特；返回值带候选数，>1 时人工确认 |

**另有一条方法论级的**：
> **判断"定制浏览器能不能接参数"，去 `chrome.dll` 里搜开关名时，要搜不带 `--` 前缀的形式。**
> Chromium 存的是 `switches::kProxyServer = "proxy-server"`。
> 我第一轮搜 `--proxy-server` 全是 `not-found`，差点误判"这个浏览器不支持代理"。

# v2 增补 · 2026-10-24 · 书签（左侧书签栏）跨浏览器真同步 + 一条错结论被推翻

## 九 · 本轮问题（汤哥原话）

> 「香港服务器的标签页里的插件显示出来了，但是左侧标签栏里头没有跟带 AI 标识的同步，去哪了？没同步完。」

## 十 · 先纠错：v1.1.0 写下的「书签不能迁移」是错的

| 项 | v1.1.0 的结论 | v2 实测真相 |
|---|---|---|
| GPT 浏览器 Bookmarks 文件 | 5.2 MB 密文，首字节 `/WW/8/PQfR9Xjj7o`，判定「禁止拷贝、只能同 profile 重启或手工导出 HTML」 | 磁盘密文属实，**但浏览器内存里是明文** |
| 能否跨浏览器搬 | 判定「不能」 | **能。chrome.bookmarks API 全量导出 378 文件夹 / 7552 书签，导入 0 失败** |

**教训：磁盘形态 ≠ 能力边界。** 文件加密只说明「不能拷文件」，不说明「搬不过去」。
错误的边界结论比没写过更糟 —— 它会让你在未来直接放弃尝试。

## 十一 · 书签同步的四个卡点（全部实测踩过）

1. **CDP 官方协议没有 Bookmarks 域** → 调用报 `-32601 'Bookmarks.getTree' wasn't found`（浏览器级、页面级都一样）
2. **chrome.bookmarks 只在 chrome://bookmarks 特权页可用**，普通 https 页面拿到 `NO_API`
3. **根 id 是 `'1'` / `'2'`，不是 `'bookmark_bar'`** → 否则每条都报 `Error: Bookmark id is invalid`
4. **根节点本身不能当 folder 建** → 否则全量书签落进「假根」，getTree 总数照样对得上，但真书签栏是空的

## 一 · 标准化：把「一次性快照」改成「差额补齐」

| 项 | 旧（v2 步骤 8） | 新（v3 步骤 9） |

| 语义 | 全量重建 | 差额补齐（只补对面没有的） |

路径键设计是核心：用「根序号 + 逐级标题」（`R0/工具/xxx`），**不能用根标题**——
「书签栏」和「Bookmarks bar」是同一个根，用标题当键会把整棵树重造一遍。
