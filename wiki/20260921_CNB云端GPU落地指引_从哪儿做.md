## 二、⚠️ 先说清成本（官方定价页原文，2026-09-20 核实）

| 计费项 | 免费额度 | 超额单价 | 折算 |
|---|---|---|---|
| 云原生开发-**CPU** | **1600 核时/月** | ¥0.125/核时 | **免费**（最大 64核128G 也能白跑 25h/月） |
| 云原生开发-**GPU** | **0 核时/月** | **¥0.5/核时** | GPU 节点固定 **16 核 + 48GB 显存** → `16 × 0.5` = **8.0 元/小时** |
| 云原生构建-CPU | 160 核时/月 | ¥0.125/核时 | — |
| 云原生构建-GPU | 0 核时/月 | ¥0.5/核时 | — |
| 仓库存储 | 100 GiB | ¥1/GiB/月 | — |
| 对象存储 | 100 GiB | ¥1/GiB/月 | — |
| AI Credits | 500/月 | ¥0.05/credit | — |

**两条硬规则**（官方原文）：
1. 启动后**每 5 分钟预冻结一次**用量（GPU：16核 × 5min = 1.33 核时）。
2. **预冻结时若检测到额度不足，系统立即终止任务** —— 所以不会跑出超额账单，只会被平台掐断。

**★ 由此得出省钱策略（本指引最重要的一条）**：
> CPU 有 1600 核时/月免费，GPU 是 0 免费。
> **所以：网关联调、协议验证、队列测试、工作流结构校验，全部放到免费 CPU 档做；只在真正出片的那几十分钟开 GPU。**
> 出片完立刻停环境（`python cloudgpu/backend/cnb_env_up.py --down`）。

### ⚠️⚠️ 上机前置条件：组织必须有 GPU 核时额度（2026-09-21 01:00 实测踩出）

**光把 `.cnb.yml` 推上去是不够的。** 实测起环境时，平台在 `Pipeline prepare` 这一步直接终止，原文：

```
Pipeline prepare error: Root Group's workspaces GPU core-hours are insufficient
for pre-freezing (Freezing time: 5.00 min, equivalent to 1.33 core-hours).
Contact the root group administrator to extend.
根组织的云原生开发-GPU配额已不够预冻结（冻结时间：5.00 min，折合1.33核时），
请联系根组织管理员提升配额。
```

**★ 关键：这不是 `.cnb.yml` 写错了。** 同一次构建的日志证明前面全绿：

| 日志原文 | 说明 |
|---|---|
| `Allocation completed: runner 10.235.16.36:8087, cluster size is 3` | runner 分配成功 |
| `Runner runs on cnb:arch:amd64:gpu` | **GPU 规格被正确识别** |
| `Pipeline actual limit cpus: 16, memory: 128` | 16 核 / 128G |
| `labels: ARCH=amd64, GPU=L40, cpus=16, memory=128, vscode=远程开发` | **真的分到 L40 卡** |
| `4 services started`（git-clone / network-bus / vscode / docker） | 4 个 sidecar 全起 |
| `Free GPU workspace limit: 2` | 平台还提到免费 GPU 并发上限 2 |
| **`Pipeline prepare error: ... GPU core-hours are insufficient`** | **只卡在最后一道"预冻结"** |

**解法（二选一）**：

| 路 | 做法 | 成本 |
|---|---|---|
| **A. 充值额度**（要 GPU 就必须走这条） | 组织 → 设置 → 用量管理 → 绑定「腾讯云-云原生构建预算」，入口 `https://console.cloud.tencent.com/cnb`。官方定价页原文：「前往 组织-设置-用量管理，绑定 腾讯云-云原生构建预算，可提升用量上限」 | 预冻结一次 1.33 核时 ≈ **¥0.67**；之后 ¥0.5/核时 × 16 核 = **8.0 元/小时** |
| **B. 改走免费 CPU 档**（今晚就能跑，零成本） | 把 `.cnb.yml` 里 `tags: cnb:arch:amd64:gpu` 那行**注释掉**，`commit + push`，重新点「云原生开发」 | **¥0**（1600 核时/月免费，最大 64核128G 也能白跑 25h/月）。出片慢，但**联调、协议验证、工作流结构校验完全够用** |

> 本次实测**成本 ≈ 0**：预冻结失败 = 资源未被真正占用，构建总耗时 7.24 秒。

## 三、三条路，选一条

### 路 A · 网页点（最稳，永远可行，30 秒）

1. 打开 `https://cnb.cool/TJF19770107/ai-video-pipeline`
2. 确认分支是 `main`，点右上「**云原生开发**」
3. 等 WebIDE 起来（首次要拉镜像 `comfyui-boot:cu130-megapak-pt211`，较久）
4. 在 WebIDE 终端里取公网地址（**不用去控制台点端口**）：
   ```bash
   printenv | grep CNB_VSCODE_PROXY_URI
   ```
   输出形如 `https://xxxxxxxx-{{port}}.cnb.run`，**把 `{{port}}` 换成 `8188`** 即可。
5. 把那串地址写进本地 `CLOUDGPU_CNB_URL`。

### 路 B · 命令行全自动（推荐，已验证）

```bash
cd E:\龙虾AI主控中心\我的AI分身\企业微信群定制接单项目\scripts\gateway_service

python backend\cnb_env_up.py --check    # 体检：CLI / 登录态 / API scope
python backend\cnb_env_up.py --up       # 起环境（读仓库 .cnb.yml 的 vscode 事件）
python backend\cnb_env_up.py --url      # 取地址并回填 .env.local
python backend\cnb_env_up.py --down     # 停环境（省钱，出片完必停）
```

> **★ 本脚本内置一个关键修复，务必保留**：
> 宿主动了手脚往环境里注入了一个 **27 位的 git 专用窄令牌**到 `CNB_TOKEN`；
> 而 `cnb` CLI 源码写的是：
> ```js
> // @cnbcool/cnb-cli/dist/index.js · resolveApiDomain
> let e = process.env.CNB_API_ENDPOINT || "https://api.cnb.cool";
> if (process.env.CNB_TOKEN_FOR_CODEBUDDY || process.env.CNB_TOKEN) return e;  // ← 短路
> let t = loadToken();   // 只有前面都不成立，才去读 ~/.cnb/token
> ```
> **它一旦存在就把 CLI 短路，连 `~/.cnb/token` 里那个 94 位宽 scope OAuth 令牌都不读**，
> 于是 `users / repositories / workspace / charge` 全部回 **403「Missing required scopes」**——
> 极易被误判成「令牌 scope 不够，去补授权」，**归因完全错**。
> 实测：摘掉 `CNB_TOKEN` 后同样三条探针**全部 200**（`get-user-info` 拿到汤嘉锋；`get-repos` total=19；`list-workspaces` total=65）。
> 所以脚本默认主动摘掉它。要强制用环境里那个令牌时加 `--use-env-token`。

### 路 C · 推分支后由 CI 自动起（声明式，留作扩展）

`.cnb.yml` 落到仓库根后，也可以配 `main:` 事件让流水线在 push 时起节点。
当前**没做**——因为 CI 起节点是「跑完即销毁」，而我们要的是**持久化 ComfyUI**，更适合用「云原生开发」。

## 四、`.cnb.yml` 放哪儿、长什么样

**位置**：**仓库根目录**（`ai-video-pipeline/.cnb.yml`），不是子目录。
官方原文：「在仓库根目录下新增 `.cnb.yml` 文件可自定义云原生开发的流水线配置，包括声明资源规格、触发事件及可用时机」。

**结构**（官方模板 + 资源规格声明）：
```yaml
$:
  vscode:                                   # vscode 事件：专供页面「云原生开发」按钮用
    - docker:
        image: docker.cnb.cool/fuliai/cnbest_docker/comfyui-boot:cu130-megapak-pt211
      services:
        - vscode
        - docker
      runner:
        tags: cnb:arch:amd64:gpu            # ★ 这一行 = GPU 节点（16核+48G显存, 8元/小时）
                                            #   删掉它就是免费 CPU 档
      env:
        HF_ENDPOINT: https://hf-mirror.com
        COMFY_DIR: /workspace/comfyui/ComfyUI
        COMFY_PORT: "8188"
      stages:
        - name: 准备持久化 ComfyUI
          script: |
            bash cloudgpu/backend/deploy_cloud.sh
        - name: 拉起 ComfyUI 并打印公网地址
          script: |
            cd "$COMFY_DIR" && nohup python main.py --listen 0.0.0.0 --port "$COMFY_PORT" >/workspace/comfyui.log 2>&1 &
```

## 五、持久化：只依赖 `/workspace`

`/workspace` 是 CNB 云原生开发**唯一持久卷**，容器重启**只丢运行环境，不丢数据**。
所以纪律是：

| 放哪儿 | 内容 |
|---|---|
| **`/workspace`** | 模型权重、自定义节点、ComfyUI 工作流、产出视频、日志 |
| 容器其他路径 | 只放临时物，重启即丢 |

`deploy_cloud.sh` 已按这个纪律写成**幂等**的：已存在的模型直接跳过下载（`dl()` 里 `if [ -s "$dst" ]` 判断）。

## 六、出片前必做：切到 GPU 档

`.cnb.yml` 默认是 **GPU 档**（生产正主）。要省钱联调时，把 `runner.tags` 那一行**注释掉**即走免费 CPU 档；改完 commit + push，重新点「云原生开发」（CNB 每次起环境都读仓库当前 `.cnb.yml`）。
