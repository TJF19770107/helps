## 二、假成功新形态 #12：令牌缺权限域 → 404 伪装

- 实证：`POST /user/keys` 用只有 `repo, user, workflow, write:packages` scope 的 gh token，返回 **404 Not Found**（不是 403 Forbidden）。
- 判定法：先打 `GET /user` 身份探针（200=令牌有效），再查响应头 `X-OAuth-Scopes`。
- 修复：OAuth 设备流补权（gh CLI 公开 client_id `178c6fc778ccc68e1d6a`，scope 加 `admin:public_key`），用户在 `github.com/login/device` 输一次码即可。
- 归类：与「404=仓库不存在伪装」同族——**GitHub 把一切无权限操作统一伪装成 404**，见 404 先查 scope，别急着判端点失效。

## 三、SSH 443 打通（已固化）

`~/.ssh/config` 已写入：

```
Host github.com
    HostName ssh.github.com
    Port 443
    User git
    IdentityFile ~/.ssh/id_ed25519
    IdentitiesOnly yes
```

公钥注册：设备流脚本 `G:\WorkBuddy_Data\tmp\gh_device_flow_register.py` 自动注册 `id_ed25519.pub`。打通后验证：`ssh -T git@github.com`（预期 `Hi TJF19770107!`）。

## 四、香港云服务器不续费影响评估（汤哥核心疑问）

| 链路 | 是否依赖香港服务器 | 实测/依据 |
|---|---|---|
| `git push` HTTPS | **否** | 09-20 直连 ls-remote 认证成功 |
| `git push` SSH | **否** | ssh.github.com:443 直连握手成功 |
| GitHub REST API（gh_api_push.py） | **否** | api.github.com 直连持续可用 |
| 只读兜底 gh-proxy.com | **否** | 镜像站，无需代理 |
| Chrome 访问 github.com | **否（但有条件）** | 直连当前可达；需关掉系统代理 7897（7897 后端是香港隧道，不续费即死） |
| Chrome 访问 Google/B站海外等**被墙站** | **是** | 这才是香港链路的真正不可替代项 |

**结论：不续费香港服务器，GitHub 主链路（push/pull/API/浏览器）全部不受影响；真正受影响的是通用穿墙能力。** CN 直连 GitHub 历史上时通时断（09-19 就断过一天），长期兜底序列：HTTPS 直连 → SSH 443 → gh_api_push（API）→ gh-proxy（只读）。

## 五、Chromium 系内存清理法（GptBrowser 56→19 实例）

- 权限：本会话 `taskkill /F /PID` **可行**（此前 ERROR_ACCESS_DENIED 是当时会话权限问题，非永久限制）。
- 安全清法：**保留最大内存主进程（主窗口）+ 次大进程（GPU）**，杀其余全部渲染/辅助进程。会话/Cookie 落盘不受影响。
- 实测：56 实例 → 19 实例，系统进程总占用 ~7.8GB/31.7GB（此前 90% 压力）。
- 注意：杀渲染进程后 Chromium 会自动重建部分进程（正常现象，读数会小幅回升）。
