## 八、★ 本轮新发现的两个假成功形态（沉淀）

### 形态 9 · 「回执成功但内容错位」（MCP 层最隐蔽）

**实证**：`import_urls` 导乐享页 → 返回 `ret_code:0` + `media_id`，**看似成功**；但知识库里落的是 330 字节的
「腾讯乐享_腾讯旗下企业AI知识库」**登录落地页**，不是正文。
根因：乐享页是 JS 渲染 SPA，爬虫取不到正文（实测 HTTP 200 / 7065 字节 / 无正文关键词）。
更严重的是：**9/16 那 4 条同类条目全是同一种空壳**——即 IMA 端从未真正同步过内容，而历史记录一直记「已同步」。

**判活铁律**：MCP 写库类操作**必须以「回读内容」为验收**（标题/正文关键词命中），不能只看 `ret_code`。
**衍生铁律**：JS 渲染站点（乐享/docs 类）**不可作为 URL 导入源**。

### 形态 10 · 「真因被错误文本掩盖」（三通道回退的副作用）

**实证**：CNB 三通道依次报 `could not read Username for 'https://cnb.cool'`（像是凭据问题），
手工复现后真因是 **non-fast-forward**——远端存在本地没有的提交（远端 47e9c66 vs 本地基点 61af711），
本地克隆过期。凭据完全正常（27 位现签令牌，`ls-remote` 一次就通）。

**判活铁律**：三通道/多通道回退失败时，**不可只报最后一条错误**；必须区分
「认证失败」与「操作层失败（non-fast-forward / hook 拒绝 / 配额）」，否则排查方向被带偏。
**修复动作**：推送前 fetch+merge（合并后必查 `git status --short` 的 ` D` 静默漏写）。

## 八·补、关键通道修复记录（可复用，2026-09-19 实测通过）

### IMA 原生上传：COS V5 签名（本会话已打通，HTTP 200）

| 环节 | 正确写法 | 踩坑 |
|---|---|---|
| KeyTime | create_media 返回的 `start_time;expired_time` | 自己算时间会因时钟/时区错签 |
| SignKey | `hex(HMAC-SHA1(secret_key, KeyTime))` | 必须是 **hex 字符串**，不是 bytes |
| HttpString | `"put\n" + uri_path + "\n" + "" + "\n" + header_list + "\n"` | **末尾 `\n` 必须保留**；uri_path 需 percent-encode |
| 签名头列表 | `host` + `x-cos-security-token`（临时密钥必须签入，且请求头要真的带上） | 漏 token 或漏签 → SignatureDoesNotMatch |
| StringToSign | `"sha1\n" + KeyTime + "\n" + SHA1(HttpString) + "\n"` | 中间哈希要与服务端一致才能定位到 SignKey |
| 请求头 | `Host` / `x-cos-security-token` / `Content-Type` / `Content-Length` / `Authorization` | `Authorization` 里 `q-url-param-list=` 留空 |
| 收尾 | COS 200 后再 `add_knowledge(media_id)`；`duplicate_name_strategy` 取枚举全称 `DUPLICATE_NAME_STRATEGY_SAVE` | 写 `SAVE` 会参数校验失败 |

**验收铁律**：`add_knowledge` 回执 ≠ 成功；必须回读 `get_knowledge_list`，确认 `parse_progress=100` 且 `introduction` 命中正文关键词。

### GitHub 第 5 通道：REST Contents API（本会话已打通，8/8 成功）

- 判据：`github.com` 应用层超时，但 `api.github.com` → 200（1.0s）→ **git 传输死路，API 活路**。
- 凭据：`~/.git-credentials`（用户名 TJF19770107，40 位令牌）；脚本 `scripts/gh_api_push.py` 运行时读取，**不落盘密钥**。
- 坑 1：中文路径必须 percent-encode，否则 `http.client` 抛 `UnicodeEncodeError`。
- 坑 2：**更新**已有文件必须回传其当前 blob `sha`（HEAD 同分支），否则 `422 "sha" wasn't supplied`；新建=201、更新=200。
- 通道优先级更新：① 1081 SOCKS5 → ② github.com 直连 → ③ gh-proxy（只读，仅能拉不能推）→ ④ SSH（需公钥注册）→ ⑤ **API Contents（api.github.com 通时必用）**。
