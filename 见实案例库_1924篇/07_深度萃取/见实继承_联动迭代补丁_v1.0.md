## 二、龙虾五步法 · 第五步「沉淀」升级（可直接合并进正本）

**现状**：第五步「沉淀」= 写技能 + 归档 + 回填知识库。
**升级后**：沉淀必须满足两条硬校验，否则**不算沉淀完成**。

```markdown
## 第五步 · 沉淀（v3.7 升级：记忆四层归位 + Skill 八要素）

沉淀 ≠ 写个文件。沉淀结束前必须过两道闸：

### 闸一 · 记忆四层归位（信息该停在哪一层）
| 层 | 放什么 | 落点 |
|---|---|---|
| ① 身份规则层 | 我是谁/服务谁/价值观/禁忌 | SOUL.md / IDENTITY.md |
| ② Skill 层 | 反复出现、已跑通的流程 | 技能库/<技能名>/SKILL.md |
| ③ 长期记忆层 | 偏好/常用工具/关键项目/长期业务规则 | MEMORY.md（禁止当垃圾桶） |
| ④ 临时会话层 | 本次任务限定/临时判断 | 不落盘 |

判定：只本次有效→会话；反复偏好→长期记忆；跑通流程→Skill；需追踪结果→表格/知识库。
★ 一次性临时判断绝不进长期记忆（否则污染未来判断）。

### 闸二 · Skill 八要素校验（缺一即"半失效"）
适用场景 · 触发条件 · 输入字段 · 执行步骤 · 调用工具 · 输出格式 · 质量约束 · 异常反馈。
★ 触发条件写到"用户说哪句话就命中"（例：不写"客户处理"，写"客户优先级分析/当判断成交概率、跟进顺序、丢单风险时使用"）。
★ 标题/摘要/触发条件 = Agent 渐进披露的调用依据，不是装饰。

### 产出判据（反自欺）
- 每个技能包必须含「可执行框架 + 量化基准 + 避坑」三件，缺一视为未沉淀（只列标题清单 = 没沉淀）。
- 沉淀完要能一句话说清：这条技能下次遇到什么任务会被触发、输入是什么、输出是什么。
```

## 三、全域模板 · 升级（可直接合并进正本，建议加在"交付前自检"章节）

```markdown
## 交付前自检 · 8 要素 + 触发条件（v3.43 升级 · 源自见实 Agent 方法论）

每次交付前过一遍，缺项当场补：
1. 适用场景 —— 这份交付解决谁的什么问题
2. 触发条件 —— 什么情况下该用这份（写清"下次遇到 X 就调 Y"）
3. 输入字段 —— 需要对方给什么
4. 执行步骤 —— 分几步、每步产出
5. 调用工具 —— 用到哪些脚本/接口
6. 输出格式 —— 交付物长什么样（文件/链接/表格）
7. 质量约束 —— 验收硬指标（数字/字节/状态码，不用"感觉良好"）
8. 异常反馈 —— 失败了怎么报、怎么回滚

「三行交付铁律」升级为「三行 + 一钩子」：
✅ 已完成 / 📁 结果路径 / 🔁 可回滚 / 🎯 下次触发条件（说清什么任务会再调它）
```
