# 龙虾自我迭代管控技能

技能名称：龙虾自我迭代管控技能  
技能标识：lobster_self_iteration

## 适用场景（何时调用）
- 需要人工发起一次技能生成/优化/归档
- 需要配置“每日一次”的定时迭代任务（仅生成迭代指令与检查清单，不自动执行写入）
- 需要对共享技能库做冷技能归档、旧版本保留与可回滚治理

## 硬性约束（必须遵守）
- 触发方式：仅人工手动触发或每日一次定时触发；禁止实时、连续、无人值守自迭代
- 体积：纯文本技能 ≤10KB；带执行脚本技能 ≤100KB；技能库总 ≤500MB
- 版本：每次迭代必须新版本号与独立目录/文件名；禁止覆盖旧版；必须可回滚
- 成本：单次迭代消耗 ≤50 积分；预计超额则停止并等待人工指令
- 共享原则：技能不得被重复拷贝到本地/容器/客户端内部；仅维护“索引 + 调用入口”

## 输入
- 迭代目标：新建/优化/归档/合并/拆分（其一或多项）
- 变更范围：涉及的技能名/版本范围/调用方（Trae/Hermes/豆包/微信/VNPY/Llama）
- 资源预算：目标体积上限、预计积分消耗、是否允许归档冷技能
- 验收标准：成功条件、回滚条件、回流数据口径

## 输出
- 迭代方案：改动清单、风险点、回滚路径
- 版本化产物：新版本命名方案与兼容性说明（不覆盖旧版）
- 归档方案：冷技能判定口径、归档位置、索引更新策略
- 预算审计：体积与积分红线检查结果

## 执行流程（固定顺序）
1. 读取当前规则与现有技能索引，确认“禁止重复拷贝、仅索引+密钥、按需拉取”的边界
2. 生成变更最小集：优先复用既有能力，避免新增冗余技能
3. 做红线预检：体积估算、库总量评估、积分预算评估
4. 产出版本化变更：新版本号 + 独立路径；保持旧版可用与可回滚
5. 更新索引：确保所有调用方“自动可见”但不引入本地拷贝
6. 生成回流要求：定义调用结果与问题的回流字段，供后续优化

## 命名与版本规范（建议）
- skill_name: kebab-case 或 snake_case，避免空格与特殊符号
- version: vYYYYMMDD.N（例如 v20260423.1）
- 兼容：如存在破坏性变更，必须保留旧调用入口或给出迁移映射
