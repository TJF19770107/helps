## 一、通用基础规则（全域统一执行）

1. 所有快照均为【轻量索引快照】，仅记录配置、插件状态、会话、进程/端口、索引路径，不复制底层数据库、完整技能包等重资产。
2. 快照统一存放路径：`G:\龙虾AI主控中心\我的AI分身\技能库\backup\`
3. 节点留存：全局永久保留最近 5 个正常节点，超出数量自动删除最老旧节点。
4. 常规调用「调用龙虾五步法修复XX」时，**默认不自动生成快照**；如需同步备份，指令内必须明确标注「并生成快照」，按需触发以降低资源消耗。
5. 禁止高频重复备份，同一场景、同一时段仅生成 1 份快照。

## 二、第一套：手动主动快照

### 2.1 触发方式
人工确认环境稳定后主动下达指令。

### 2.2 可用指令

| 指令 | 作用 | 发送对象 |
|------|------|----------|
| `调用龙虾五步法，为Codex手动生成正式正常节点快照` | 单服务快照 | Marvis / Codex |
| `调用龙虾五步法，为全域所有Agent生成正式正常节点快照` | 全域快照 | Marvis |
| `为Codex生成当前正常状态快照` | 口语化单服务快照 | Marvis / Codex |

### 2.3 规则
- 手动快照为人工确认的稳定节点，优先级最高。
- 直接加入全局节点池，可优先用于回滚。
- 命名格式：`{YYYYMMDD_HHmmss}_manual_{ServiceName}_stable`

## 三、第二套：阈值低频自动快照

### 3.1 触发条件（双条件，满足其一即触发）

| 条件类型 | 阈值 | 触发动作 |
|----------|------|----------|
| 计数阈值 | 龙虾五步法累计调用满 10 次 | 自动静默生成全域快照，生成后计数器清零 |
| 时长阈值 | Codex 及全域服务连续稳定运行满 6 小时 | 自动静默生成全域快照，生成后运行计时器清零 |

### 3.2 互斥约束
- 两个条件任一达成即触发。
- 同一时段仅生成 1 份快照，不重复备份。
- 执行过程最小化占用 CPU、Token、积分，仅输出极简日志。

### 3.3 命名格式
- 计数触发：`{YYYYMMDD_HHmmss}_auto_count_{N}_global`
- 时长触发：`{YYYYMMDD_HHmmss}_auto_uptime_6h_global`

### 3.4 启用指令（下发给 Marvis）
```
Marvis，加载龙虾五步法V2.5，启用低频自动快照阈值规则：
1. 计数规则：累计调用龙虾五步法达到10次，自动生成全域轻量快照，标记为正常节点；生成后调用计数器清零重新累计。
2. 时长规则：Codex、全域服务连续稳定运行满6小时，自动生成全域轻量快照，标记为正常节点；生成后运行计时器清零重新累计。
3. 互斥约束：计数、时长任一条件达成即触发，同一时段仅生成1份，不重复备份；全程使用轻量索引快照，存储至G盘。
4. 节点规则：遵循全局保留最近5个正常节点，超出自动删除最老旧节点。
5. 资源约束：自动快照仅后台静默执行，最小化占用CPU、磁盘、Token与积分，不弹出多余日志。
```

## 四、第三套：故障前置智能快照 + 自动回滚

### 4.1 核心逻辑
Codex 从正常 → 异常，必然出现前兆。Marvis 实时轻量巡检做状态比对：
1. 记录上一次检测的正常状态
2. 本次检测识别到异常前兆 → 立刻锁定上一轮正常状态，自动生成前置快照
3. 随后直接执行回滚，恢复到该前置正常节点

### 4.2 异常判定标准（出现任意一项即触发）

| 序号 | 异常信号 | 判定方式 |
|------|----------|----------|
| 1 | 端口连接超时 / 拒绝连接 | 端口 15721 / 4567 / 57321 连通性检测失败 |
| 2 | 接口返回 404 / 502 / 503 | HTTP 状态码异常 |
| 3 | ECONNRESET / 套接字断开 | 网络层错误 |
| 4 | 进程存在但无响应 | 进程存活但接口不响应 |
| 5 | 插件批量加载失败 | 3 个以上插件同时报错 |
| 6 | 连续请求无响应 | 连续 3 次对话请求无返回 |

### 4.3 执行流程（顺序不可颠倒）

```
异常前兆检测 → ①抓取上一轮正常状态生成前置快照 
→ ②纳入全局节点池 
→ ③自动调用龙虾五步法回滚流程 
→ ④恢复至该前置正常节点 
→ ⑤输出报告：异常原因、快照路径、回滚结果
```

### 4.4 巡检配置
- 频率：每 5 分钟一次轻量状态校验
- 范围：仅检测进程、端口、接口连通性，不做全量扫描
- 约束：严控资源、Token、积分消耗；无冗余日志

### 4.5 兜底能力
若 Codex 等目标服务彻底崩溃、无法响应指令，由 Marvis 独立完成快照抓取与回滚，不依赖目标 Agent。

### 4.6 命名格式
`{YYYYMMDD_HHmmss}_fault_pre_{ServiceName}_rollback`

### 4.7 启用指令（下发给 Marvis）
```
Marvis，配置Codex及全域服务【异常前置快照+自动回滚】机制，纳入龙虾五步法V2.5流程：
## 一、轻量状态巡检配置
1. 启用超低资源巡检：仅检测进程、端口、接口连通性，不做全量扫描，严控资源、Token、积分消耗。
2. 巡检频率：每5分钟执行一次轻量状态校验，仅记录状态，不额外生成日志。

## 二、状态比对与前置快照规则
1. 每次巡检，留存「上一轮完整正常状态记录」。
2. 当本次巡检识别到异常前兆（端口超时/拒绝、接口4xx/5xx、ECONNRESET、进程假死、插件加载失败、连续请求无响应），立即执行动作。
3. 触发动作顺序（不可颠倒）：
   ① 抓取【上一轮最后一次正常状态】，自动生成轻量快照，存入G盘备份目录，标记为「故障前置正常节点」，纳入全局5个节点池；
   ② 立刻调用龙虾五步法回滚流程，恢复至该前置正常节点；
   ③ 回滚完成后输出报告：异常原因、前置快照路径、回滚结果。

## 三、约束规则
1. 故障前置快照同样遵循：轻量索引模式、仅存G盘、全局保留最近5个节点，超量自动清旧。
2. 若Codex已彻底崩溃、无法响应指令，由Marvis独立完成快照抓取与回滚，不依赖Codex自身。
3. 同一故障场景，仅生成1份前置快照，避免重复备份浪费资源。
4. 所有动作静默执行，仅最终输出极简报告，不产生冗余数据。

## 四、联动规则
该机制与「手动快照、计数/时长自动快照」并行生效，三类节点统一管理、统一回滚。
```

## 六、组合使用建议

| 场景 | 策略 | 说明 |
|------|------|------|

## 八、与 V2.5 主规则的联动关系

本快照策略是对 `lobster_task_standard_workflow_v2.3_locked`（V2.5）铁律一的精准扩展：

| V2.5 原规则 | 本策略扩展 |
|-------------|-----------|
| 仅修复前备份 | 新增三类快照触发体系 |
| 备份范围四类 | 快照统一为轻量索引模式 |
| 禁止自动备份 | 阈值/故障前置快照作为例外，按规则自动触发 |
| C盘禁止 | 所有快照强制 G 盘 |
| 5节点留存 | 三类快照统一遵守 |

V2.5 铁律二（无命令不修复）仍然生效——常规修复不自动备份，快照策略作为独立体系运行。
