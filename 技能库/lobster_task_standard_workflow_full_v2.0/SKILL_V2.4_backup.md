### 软件服务故障诊断专用流程（v2.3 新增）

适用场景：桌面应用/IDE/Agent 出现 502/ECONNRESET/socket断开/fetch failed 等网络层错误。

#### 诊断步骤
1. **症状采集**：读取应用日志（`%LOCALAPPDATA%\{AppName}\logs\main.log`），提取最后 500 行中的 ERROR/warn 条目
2. **根因判别矩阵**：

| 日志关键词 | 根因方向 | 下一步 |
|-----------|---------|--------|
| `ECONNRESET` + `127.0.0.1:7897` | 代理残留 | 执行代理清理 |
| `fetch failed` + `skillhub` | 网络不通 | 检查直连 + DNS |
| `Client network socket disconnected` | TLS阻断 | 检查代理/防火墙 |
| `render-process-gone: killed` | 连续错误崩溃 | 先修网络再重启应用 |
| `connect ECONNREFUSED 127.0.0.1:50551` | MCP本地服务未启动 | 检查MCP进程 |

3. **代理残留检测**（最频发根因）：
   - `reg query "HKCU\Software\Microsoft\Windows\CurrentVersion\Internet Settings" /v ProxyEnable`
   - 若 ProxyEnable=1 且端口无 LISTENING → 确认为代理残留
4. **跨应用影响评估**：同一代理残留会同时影响所有遵循系统代理的应用（豆包/WorkBuddy/Chrome 等）

#### 修复流程
1. 终止代理进程：`taskkill /F /IM "clash-verge.exe" /IM "mihomo.exe" /IM "v2ray.exe"`
2. 清除系统代理注册表项
3. 网络栈完整重置（winhttp + winsock + int ip + flushdns）
4. 直连验证：ping 百度确认通
5. 重启受影响应用，逐一验证功能恢复
6. 验证清单：进程存活、窗口正常、无新错误日志、远程接口可通

#### 输出物
- 诊断报告：症状/日志证据/根因确认/受影响组件清单
- 修复记录：执行命令 + 结果
- 验收清单：各组件验证通过状态

### 程序自动化白名单管理子流程（v2.4 新增）

适用场景：app-agent需要对Windows桌面应用（EXE）执行截图、进程启停、配置修改、接口校验等自动化操作，但应用不在白名单中被拦截。

#### 白名单权限模型

| 权限项 | 作用 | 无此权限时的表现 |
|--------|------|-----------------|
| screenshot | 截图应用窗口 | 截图返回空/拒绝 |
| process_control | 关闭/启动/重启进程 | 无法操作进程 |
| config_repair | 读写应用配置文件 | 配置修改被拦截 |
| interface_connectivity_check | 网络连通性诊断 | 网络检查失败 |
| full_automation | 全自动化超级权限 | - |

#### 操作流程
1. **查**：读取 `{Marvis-User-Data}\skills\automation_whitelist.json` 获取当前白名单
2. **增**：构造权限对象（executable_path + permissions + status），加入 whitelist 对象
3. **删**：从 whitelist 中移除目标应用 key
4. **改**：翻转 permissions 中的对应开关
5. **验**：加入后必须执行四步验证闭环（截图→进程启停→日志健康→子进程存活）

#### 备份策略
- 每次修改前自动备份：`automation_whitelist.json.bak.{YYYYMMDD}`
- 恢复命令：用 .bak 覆盖原文件
