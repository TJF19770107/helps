# 4. 审稿回复（自研流程 + MIT 素材）

## 用途
把审稿意见拆成可执行修改项，生成学术规范的逐条回应信。
✅ 回应结构、措辞、修改计划　❌ 虚构「已补充实验」、伪造数据、杜撰引用

## 触发指令
```
审稿回复：以下是三位审稿人意见……（附原文）
逐条回应：R2 第3条质疑样本量不足，如何回复
```

## 执行步骤
1. **分类**：每条意见归入 ①方法 ②结果 ③论述 ④文献 ⑤格式语言
2. **定态**：接受 / 部分接受 / 有理反驳（反驳须有方法学依据，不情绪化）
3. **读 playbook**：`参考文献写作素材/rebuttals.md`（MIT，Devi Parikh 等同行 rebuttal 经验蒸馏）
4. **补证据**：需补数据→转技能 2 实跑；需补文献→转技能 1
5. **写回信**：逐条「审稿人意见 → 作者回应 → 修改位置（页/行）」
6. **自检**：`参考文献写作素材/checklists.md` 过一遍投稿前清单；**未真正做出的补充分析不得写入**

## token 预估
| 模式 | 预估 |
|------|------|
| 标准回复（默认） | **≈ 5–8k** |
| 精简回复 | ≈ 3k |

## 人工核验点
- [ ] 每条「已修改」由作者实际完成
- [ ] 修改位置与最终稿件一致
- [ ] 措辞尊重审稿人，无情绪化表达
