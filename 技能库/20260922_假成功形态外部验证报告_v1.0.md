## 二、外部比对面（公开案例佐证普适性）

### 形态 #1-2「exit 0 静默失败」——业界同款 ×4
- worldprogramming.org《Your CI is green and your pipeline produced nothing》：**「exit code 只有一比特信息，而真正的问题有两个维度」**——绿了两周博客却是空的。文末防法（产物存在+大小+数量+新鲜度四验）与本库「写完回读+试跑」同构。
- dev.to《Pipeline green for three weeks…never compiled》：`| tee` 吞掉编译器非零退出码，**绿了三周、部署了从未编译成功的构建**。防法 `set -o pipefail`。
- dev.to《pytest ran zero tests and reported success》：**「found nothing 和 looked at nothing 是同一行输出」**——同时佐证 #11 守卫误报/可信度。
- claudelab.net《Logged as success, but it produced nothing》：定时任务 exit 0 零产物，与本项目「任务 Result=0 却没干活」头号形态逐字同款。防法 end-of-run assertions = 本库「产物 manifest」铁律。

### 形态 #21/#24/#25「凭据分层与遮蔽」——业界同款 ×5
- dev.to《The credential was live and dead at the same time》：**「一个密钥有两个家，就有两个过期时间」**——轮换只更新一处，git 层全绿掩盖 API 层全挂。与本库「凭据来源分层+摘除法」同构。
- clawmage.ai Gateway Token Mismatch：诊断第一步 = **打印进程实际继承的环境变量**（/proc/pid/environ）= 本库形态 #25 防法原文。
- promptindexhub：.env 改了但进程内存钉死旧值 → 401。= #25。
- zivv.pro 401 排查指南：系统级变量覆盖终端新值 = #21 遮蔽。
- 阿里云开发者社区：`load_dotenv()` 默认不覆盖已存在的 env → 旧 Key 走进真实请求。实证本库铁律「环境变量 > 配置文件（也是坑）」。
