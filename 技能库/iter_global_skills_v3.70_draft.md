### 协议 #224：龙虾-Agent运行时多层沙箱统一编排协议 v1.0

> **协议编号**：#224 | **版本**：v1.0 | **状态**：DRAFT
> **对标来源**：腾讯云AgentRuntime #221 + 华为AgentSphere #220 + 微软MXC #187 + Claude Cowork #192
> **升级关系**：整合并升级 #187 MXC沙箱 + #192 本地文件沙箱 + #220 AgentSphere对标 + #221 AgentRuntime沙箱

#### 2.1 设计动机

当前沙箱协议分散在4项独立协议中，分别覆盖操作系统级（#187 MXC：四档隔离）、本地文件（#192：文件夹级授权）、硬件加速（#220 AgentSphere：100ms启动）、软件全栈（#221 AgentRuntime：60ms冷启动）。实际Agent运行时场景需要多层沙箱按需组合、统一编排。本协议提供**五层沙箱统一编排框架**，将分散的沙箱能力整合为可组合的防御纵深。

#### 2.2 五层沙箱架构

```
Agent运行时多层沙箱统一编排协议 v1.0
│
├── L0 请求层沙箱（API Gateway 前置）
│   ├── 请求来源验证（人 vs Agent 水印识别）
│   ├── 操作意图分类（只读/写入/删除/系统调用）
│   ├── 风险预判路由（低风险直通 / 中风险L1 / 高风险L2+）
│   └── 对齐：#221 Zero-Trust Gateway + #206 L1身份水印
│
├── L1 进程级沙箱（快速隔离，~60ms冷启动）
│   ├── gVisor/Nabla 用户态内核
│   ├── 临时文件系统（tmpfs）
│   ├── 网络白名单（仅允许已声明域名/IP）
│   ├── 系统调用过滤（Seccomp BPF）
│   └── 对齐：#221 Agent沙箱（60ms/分钟16万）+ #220 AgentSphere（100ms/10万级）
│
├── L2 容器级沙箱（中等隔离，~500ms冷启动）
│   ├── Docker/Podman 容器
│   ├── 持久化卷挂载（白名单目录只读/读写）
│   ├── 资源限制（CPU/Memory/IO cgroups）
│   └── 对齐：#187 MXC Session隔离 + #192 文件夹级授权
│
├── L3 虚拟机级沙箱（强隔离，~3s冷启动）
│   ├── Firecracker microVM / Hyper-V WSL2
│   ├── 完整OS内核隔离
│   ├── 快照/回滚能力
│   └── 对齐：#187 MXC VM隔离
│
└── L4 云端沙箱（最高隔离，按需启动）
    ├── Win365 Cloud PC / 腾讯云CVM
    ├── 销毁即清零（不可逆操作专用）
    ├── 操作审计全量日志
    └── 对齐：#187 MXC Win365云端 + #220 华为云AgentSphere
```

#### 2.3 智能编排决策树

```
输入：Agent操作请求（操作类型 + 影响范围 + 风险评分）
│
├─ 只读文件查询 → L0 直通（记录审计日志）
├─ 创建新文件（<10MB，非系统路径） → L1 进程沙箱
├─ 修改已有文件（非敏感路径） → L2 容器沙箱（快照后执行）
├─ 删除文件（非系统路径） → L2 容器沙箱 + 回收站保护
├─ 执行第三方代码/脚本 → L3 VM沙箱（无网络）
├─ 修改系统配置/注册表 → L3 VM沙箱 + 人工审批
├─ 联网执行不可信代码 → L4 云端沙箱
└─ 批量操作（>50文件） → L2起 + 分批执行 + L0熔断
```

#### 2.4 跨协议沙箱能力统一接口

```

    operation_type: str,      # "read" | "write" | "delete" | "execute" | "system"

    estimated_impact: int,    # 1-10 影响评分
    requires_network: bool,
    requires_persistence: bool
) -> SandboxConfig:

    cold_start_ms: int
    snapshot_enabled: bool
    audit_level: str          # "basic" | "detailed" | "full"
```

### 协议 #225：龙虾-跨模型技能迁移与自适应包装协议 v1.0

> **协议编号**：#225 | **版本**：v1.0 | **状态**：DRAFT
> **对标来源**：微软SkillOpt #222（梯度优化方法论）+ 龙虾多模型路由 #77/#152 + Hermes 多Provider #165
> **升级关系**：升级 #222 SkillOpt协议（方法论→工程化落地），整合 #77/#152 多模型路由

#### 3.1 设计动机

微软SkillOpt（#222）证明了技能文档可作为"外部权重"通过四阶段训练循环优化，跨模型迁移+15.2分、跨环境迁移+31.8分。但SkillOpt聚焦方法论层面，龙虾体系需要一份**可操作的跨模型技能迁移工程协议**，覆盖当前龙虾生态的6大模型（Claude/Codex/Gemini/Hermes/DeepSeek/GPT）间技能包的无损或低损迁移。

#### 3.2 三阶段迁移流水线

```
阶段一：技能源模型适配分析
├── 输入：源技能文档（Markdown）+ 源模型名称
├── 分析维度：
│   ├── Tokenization差异（BPE/WordPiece/SentencePiece）
│   ├── 上下文窗口差异（200K vs 1M vs 2M tokens）
│   ├── System Prompt注入方式（prefix/suffix/separator）
│   ├── 工具调用格式（MCP/Function Call/Native Tool）
│   ├── 思考模式支持（Extended Thinking/Deep Think/无）
│   └── 输出格式倾向（JSON/Markdown/自由文本）
├── 产出：模型差异矩阵 JSON
│
阶段二：技能文档自适应改写
├── 策略选择（按差异程度自动选）：
│   ├── 策略A：直接迁移（差异度<5%）→ 仅调整工具调用格式
│   ├── 策略B：提示词改写（差异度5%-20%）→ 调整token分配+格式化指令
│   ├── 策略C：结构重组（差异度20%-50%）→ 重排章节+补充桥接指令
│   └── 策略D：深度重构（差异度>50%）→ SkillOpt式四阶段训练循环
├── 自动验证：目标模型执行3个基准任务，评分≥源模型90%即通过
├── 产出：目标模型技能文档 + 迁移报告
│
阶段三：多模型技能注册与路由
├── 技能注册表更新（新增目标模型条目）
├── 网关路由权重初始化（新模型权重=源模型*0.85，冷启动后调优）
├── A/B测试框架：源模型 vs 目标模型 并行执行7天
├── 产出：技能-模型兼容矩阵更新 + 路由权重确认
```

### 协议 #226：龙虾-桌面自动化纵深防御与审计链协议 v1.0

> **协议编号**：#226 | **版本**：v1.0 | **状态**：DRAFT
> **对标来源**：#127 桌面全平台视觉操控 v3.0 + #187 MXC沙箱 + #221 AgentRuntime + Codex Win CU v26.527
> **升级关系**：升级 #127 桌面全平台视觉操控协议（从 v3.0 → v3.1），整合 #187/#221 沙箱能力

#### 4.1 设计动机

协议#127 v3.0 已覆盖 Windows/Mac/Linux 三平台统一操控 + 锁屏后台 + 手机远程指挥，但在以下维度存在缺口：

1. **安全纵深不足**：桌面操控协议本身仅含六层舱壁（禁止管理员/支付/凭证/安全弹窗），缺少与底层沙箱（#187 MXC / #221 AgentRuntime）的纵深联动
2. **审计链不完整**：每一次鼠标点击、键盘输入、窗口切换缺乏不可篡改的审计日志
3. **用户态-内核态边界模糊**：UI Automation API（用户态）与 Seccomp/gVisor（内核态）未形成统一的安全判定链

#### 4.2 四层纵深防御架构

```
桌面自动化纵深防御协议 v1.0
│
├── 防御层 D1：意图安全网关（操控发起前）
│   ├── 用户授权验证（一次性授权 vs 持续性授权 vs 定时授权）
│   ├── 操作白名单（允许的应用/窗口/域名清单）
│   ├── 敏感操作拦截（支付/密码输入/系统设置/注册表）
│   ├── 时段限制（工作时间 vs 非工作时间差异策略）
│   └── 对齐：#206 L1身份水印 + #205 审批疲劳对抗
│
├── 防御层 D2：运行时行为监控（操控执行中）
│   ├── 像素级操作审计（每次点击坐标+目标窗口+截图存储）
│   ├── 键盘输入脱敏（密码框自动跳过+敏感字段掩码）
│   ├── 频率熔断（30秒内>50次操作触发人工确认）
│   ├── 窗口切换追踪（跨应用操作链路记录）
│   └── 对齐：#211 状态漂移自检 + #206 L3自治熔断
│
├── 防御层 D3：沙箱容器隔离（执行环境约束）
│   ├── L1进程沙箱（UI Automation在隔离进程中运行）
│   ├── 剪贴板隔离（Agent剪贴板≠用户剪贴板）
│   ├── 文件系统视图限制（仅白名单目录可见）
│   ├── 网络出口控制（仅允许已声明的API端点）
│   └── 对齐：#224 五层沙箱编排 L1-L2 + #187 MXC
│
└── 防御层 D4：事后审计与回溯（操控完成后）
    ├── 不可篡改审计链（区块链式哈希链接：每条记录含前一条的SHA-256）
    ├── 操作回放能力（截图序列+操作序列可复现）
    ├── 异常检测（偏离常规操作模式的自动标记）
    ├── 定期审计报告（每周自动生成桌面操作安全报告）
    └── 对齐：#204 供应链审计 + #212 中断恢复状态快照
```

#### 4.4 桌面自动化安全等级分类

| 安全等级 | 操作类型 | 沙箱层 | 审批要求 | 审计粒度 | 示例 |
|:---:|------|:---:|:---:|:---:|------|
| S0 公开 | 只读截图、窗口枚举 | L0 | 无 | 摘要级 | 查看桌面布局 |
| S1 低敏 | 文本输入（非密码）、文件拖拽 | L1 | 一次性授权 | 操作级 | 填写表单 |
