## 一、为什么要有这个守卫

2026-09-21 在 CNB 云端 GPU 落地时连踩三坑，共同点是**「报错文本指向的对象 ≠ 真正出问题的对象」**：

| 现象 | 直觉归因（错的） | 真因 |
|---|---|---|
| 所有 CNB API 回 `403 Missing required scopes` | 「令牌 scope 不够，去补授权」 | 宿主往 `CNB_TOKEN` 注入 27 位 **git 窄令牌**，CLI 源码 `if (env.CNB_TOKEN) return;` 直接短路，本地 94 位宽 OAuth 令牌**根本没被读** |
| `status:200` + `sn:` + `message: cnb received, but didn't finish build yet` | 判成失败 | 这是**受理成功**；终态得另查 |
| GPU 环境起不来 | 「`.cnb.yml` 配置写错」 | 配置完全正确（真分到 L40 / 16核128G），卡在 **L4 配额预冻结** |

三个坑的共同解药：**先分层，再归因**。本守卫把它工具化。

## 二、三个能力

### 1. 凭据来源分层（`layers`）

把「这个工具到底会用哪把钥匙」摊平成优先级表，并标出**谁在遮蔽谁**。

关键设计：**只有 `shorts=True` 的层才算真遮蔽**。
- `env` 注入 = 真短路（CLI 源码 `if (env) return;`）→ 报 YELLOW-被遮蔽
- `file → file` = 并列来源（如 `.git-credentials` 与 `gh hosts.yml`）→ **不算遮蔽**

> 这条是刻意防「守卫误报」（假成功形态 #11）。第一版没区分，把 gh/git 正常的多来源全报黄，可信度直接崩。

### 2. 逐层摘除法身份探针（`probe`）

对**每个命中层**分别发一次**与仓库无关的身份请求**（`api.cnb.cool/user`、`api.github.com/user`），拿到状态码矩阵：

| 高层 | 低层 | 结论 |
|---|---|---|
| 403 | 200 | **RED 窄凭据遮蔽宽凭据** → 摘掉高层环境变量 |
| 200 | — | GREEN 无需处理 |
| 403 | 403 | RED 凭据真失效 → 重签令牌，**不要动仓库** |
| — | — | GRAY 匿名 → 404 一律是伪装 |

### 3. 异步受理裁定器（`verdict`）

判据固化成代码：

```
status ∈ {200,201,202,ok,success} + 业务 ID(sn/id/build_id/…) + 异步提示词  → ACCEPTED（不是失败！）
status 成功 + 无业务 ID                                                    → SUSPECT_FAKE_SUCCESS（假成功！）
4xx/5xx 或 errcode/error/code 命中                                        → FAILED（但先做来源分层再归因）
其余                                                                       → UNKNOWN（不许靠关键词猜）
```

### 4. 云平台五层定位（`cloud5`）

`L1 配置解析 → L2 runner 分配 → L3 services 启动 → L4 配额预冻结 → L5 stages`。
典型误判：L4 被拒 → 表现像「环境起不来」→ 被当成 L1 配置错 → 越改越错。

## 五、副产物发现（本机当前状态，供后续处理）

1. `~/.git-credentials` 里 **cnb.cool 存在两条凭据**：27 位窄的排在 94 位宽的前面 → git 操作可能命中窄的，表现为「权限莫名不够」。守卫已加「同 host 多凭据」告警。
2. `CNB_TOKEN`（27 位）宿主每会话注入，摘掉只在当前会话有效 → 长期解：让宿主别注入，或在脚本入口统一 `os.environ.pop('CNB_TOKEN', None)` 后调 cnb CLI。

## 六、硬红线

- 令牌**只进内存**，输出一律脱敏（前 4 后 2 + 长度），不落盘、不进 git、不进任何交付物。
- 脚本只读：不改任何凭据文件，不删不写 `~/.cnb/token` / `.git-credentials`。
- 匿名下 404 **不等于**对象不存在（GitHub/CNB 刻意设计）→ 必须先打身份探针。
