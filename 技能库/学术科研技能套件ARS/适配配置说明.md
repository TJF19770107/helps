# 学术科研技能套件 ARS · 安装与适配配置说明

> v1.0 · 2026-09-09 · 龙虾AI主控中心
> 说明：本文件记录了**上游原版安装步骤**与**龙虾本地调度的适配改造**。
> 我们**不采用**上游的 Codex 插件安装方式（会整包注册、吃 token、且需联网 marketplace），
> 改为「上游仓库只读留档 + 本地薄适配层调度」的成本优先方案。

---

## 一、上游原版安装步骤（摘录，供对照）

来源：仓库 `README.md` § Install ARS-Codex Plugin

```bash
# 方式 A：Codex CLI 插件市场
codex plugin marketplace add Imbad0202/academic-research-skills-codex --ref main
codex plugin add ars-codex@ars-codex

# 方式 B：直接安装 skill
python3 "$HOME/.codex/skills/.system/skill-installer/scripts/install-skill-from-github.py" \
  --repo Imbad0202/academic-research-skills-codex \
  --path skills/academic-research-suite

# 验证
/skills          # 应只看到一条 ARS-Codex 条目
```

**为什么我们不走这条路**：
1. 插件方式会把整个 `ars/` 内嵌套件注册为可调用资源，触发「整包加载」风险（实测单 agent 即 10k+ tokens）
2. marketplace 需联网且受 GitHub 可达性影响（本机实测需清代理或走 socks5 隧道）
3. Codex 桌面版自升级 + `teamorouter-desktop.exe` 会改写 `config.toml`，插件配置易被漂移覆盖

## 二、龙虾本地适配方案（已落地）

### 架构
```
上游仓库（只读留档，不动）
E:\龙虾AI主控中心\我的AI分身\企业微信群定制接单项目\skills\research-suite\
  └── skills\academic-research-suite\ars\        ← 内嵌 ARS 套件（素材源）

本地适配层（Agent 实际调度入口）
E:\龙虾AI主控中心\我的AI分身\技能库\学术科研技能套件ARS\
  ├── SKILL.md                  ← 路由器（唯一入口，强制按需加载）
  ├── 技能调用清单.md
  ├── 风险提示与合规红线.md
  ├── 适配配置说明.md（本文件）
  ├── scripts\                  ← 零积分脚本 ×3
  └── subskills\01..05\         ← 5 个子技能 SKILL.md
```

### 关键改造点
| 改造 | 原版 | 本地适配 |
|------|------|----------|
| 入口 | 单个 436 行路由器 + 内嵌全量 | 路由器 + 5 个独立子技能 SKILL.md，按目录隔离加载 |
| 加载 | 路由到 WORKFLOW.md（11–15k tok） | 先跑零积分脚本，只回读结果；大文件标「需报备」 |
| 检索 | 依 WebSearch（耗积分） | `ars_lit_search.py` 直连 4 个免费学术 API（0 积分） |
| 统计 | 无 SQL 能力 | 新增 `ars_sql_query.py`（duckdb→stdlib 三级降级） |
| 引用 | 内置三层 lint（需 yaml/markdown） | 自研 `ars_citation_check.py` + 可复用上游脚本 |
| 许可 | CC BY-NC 4.0 | 保留标注，商用前须另行确认 |

## 三、依赖安装（已执行，可复现）

```bash
# 在 G 盘建隔离 venv（遵循「venv 不压 C 盘」铁律）
C:/Users/Administrator/.workbuddy/binaries/python/versions/3.13.12/python.exe -m venv G:/g_venv_ars
G:/g_venv_ars/Scripts/python.exe -m pip install pyyaml markdown duckdb
```

验证结果（2026-09-09 实测）：`yaml OK / markdown OK / duckdb OK`
> 说明：`pyyaml` 与 `markdown` 是上游 ARS 脚本的硬依赖（缺 PyYAML 时上游明确失败）；
> `duckdb` 用于 SQL 分析主路径，**不装 pandas**（ duckdb 可直读 CSV/Parquet，省 ~40MB）。
> 未安装也不致命：`ars_sql_query.py` 会自动降级到 stdlib sqlite3。
