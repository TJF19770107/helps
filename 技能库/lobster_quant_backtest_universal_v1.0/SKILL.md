## 核心标准（最高优先级·所有框架必须满足，标准零~五为硬性约束）

本模板的核心标准为量化回测的"必选项"，换任何框架都不可简化或跳过。以下六条为硬性约束，任何框架适配时必须逐条满足：

### 标准零：分步执行强制规则——禁止一步到位

| 规则 | 说明 |
|------|------|
| 步骤不可合并 | 量化回测任务强制分为两个独立步骤，不可在一次执行中合并 |
| 第一步 | 仅启动框架环境、验证依赖、列出可用数据、呈现操作界面，然后暂停待命。**禁止自动运行回测** |
| 第二步 | 仅当收到用户后续明确指令（含策略描述/品种选择/参数配置）后，才运行回测并生成图表 |
| 禁止直接输出 | 严禁在环境启动后自动运行回测或直接输出回测结果 |
| 违规处理 | 若Agent试图合并执行或直接输出结果，视为违反核心标准 |

### 标准一：透明回测闭环——禁止黑盒运行

| 要求 | 说明 |
|------|------|
| 代码可查看 | 回测启动后必须进入策略代码编辑器界面，用户可直接看到完整策略源码 |
| 代码可修改 | 用户可在编辑器中直接修改策略参数/逻辑，修改后实时生效重新运行 |
| 步骤可中断 | 回测分步执行，每步输出中间结果，用户可在任意环节暂停/调整/继续 |
| 禁止一键黑盒 | 严禁"输参数→等结果"模式，必须展示计算过程 |
| K线点位逆向倒推 | 回测图表中任意K线可点击，逆向定位到该笔交易在策略代码中的触发位置（信号行号+触发条件），实现"图表→代码"双向追溯 |

**验收标准**：用户能在编辑器里逐行阅读策略代码、修改参数后重新运行、看到每一步的输出；点击图表上的任意买卖标记，可定位到代码中对应的信号生成逻辑。

### 标准二：三类图表强制输出

任何框架的回测结果，必须同时生成以下三种图表（缺一不可）：

| 图表类型 | 内容要求 | 对标效果 |
|----------|----------|----------|
| ① 带买卖点标记的K线图 | 主K线 + 开仓标记（↑绿色箭头）+ 平仓标记（↓红色箭头）+ 持仓区间色带 | MT5回测可视化效果 |
| ② 资金净值曲线 + 回撤曲线 | 双Y轴：左轴资金净值、右轴回撤百分比；X轴时间；回撤区域红色填充 | 专业回测报告标准 |
| ③ 多方案绩效对比图 | 多方案并列柱状图/雷达图：收益率、最大回撤、胜率、夏普比率、盈亏比、交易次数 | 方案选优决策依据 |

**生成格式**：PNG（≥150 DPI），图表标题含品种/周期/方案名称，自动保存到回测输出目录。

### 标准三：自然语言 ↔ 策略代码双向翻译

| 翻译方向 | 输入 | 输出 |
|----------|------|------|
| 正向（NL→Code） | 用户自然语言描述的交易规则（如"头肩底形态突破颈线做多，止损在右肩低点"） | 可直接运行的策略代码（Python） |
| 反向（Code→NL） | 回测验证通过的策略代码 | 结构化自然语言规则，可直接复制到币安 AI Pro / TradingView / 其他平台使用 |

**翻译要求**：
- 正向翻译：保留原始规则语义，不添加隐式逻辑，参数化所有阈值
- 反向翻译：输出"条件→动作"结构化格式，含入场条件、出场条件、止损止盈、仓位管理
- 中间验证：翻译完成后用3笔历史行情手工验证规则逻辑一致性

### 标准四：跨框架可复用——核心标准不变，仅适配接口

| 层级 | 说明 |
|------|------|
| 核心层（不变） | 五条核心标准（透明回测/三类图表/双向翻译/可复用/图表归档）永久不变 |
| 框架适配层（可变） | 数据加载接口、策略基类、订单执行方式、图表库绑定 —— 按框架差异映射 |
| 参数层（可调） | 品种、周期、初始资金、手续费、滑点 —— 每次任务独立配置 |

### 标准五：图表归档规范——统一输出到 charts 文件夹

| 规则 | 说明 |
|------|------|
| 目录位置 | 项目根目录下 `charts\` 文件夹，与 `results`、`strategy` 同级 |
| 自动创建 | 若 `charts\` 不存在，回测启动时自动创建 |
| 命名规范 | `{品种}_{策略名}_{日期}.png`（如 `BTCUSDT_dragon_leader_20260630.png`） |
| 禁止混放 | 图表严禁与结果数据(.csv/.json)、策略代码(.py) 混放在同一目录 |
| 跨框架适用 | Backtrader → `{project}/charts/`、VNPY → `{project}/charts/`、Zipline → `{project}/charts/`，命名规则统一 |

## VNPY 快速适配示例

以VNPY为例，展示如何将通用模板映射到具体框架：

### 环境准备
```
1. 安装 VNPY（veighna_studio）
2. 确认数据服务（RQData / 本地CSV数据源）
3. 创建策略目录：C:\Users\Administrator\strategies\
4. 启动 VNPY 并打开 CTA策略模块
```

### 策略编码（NL→Code）
```
用户输入："头肩底形态突破颈线做多，止损在右肩低点，止盈为颈线到头部距离的2倍"

VNPY适配：
1. 打开 VNPY CTA策略编辑器
2. 新建策略类，继承 CtaTemplate
3. 在 on_bar() 中实现：
   - 头肩底形态识别（左肩/头部/右肩 + 颈线）
   - 突破颈线 → self.buy()
   - 止损价 = 右肩最低价
   - 止盈价 = 入场价 + (颈线 - 头部) × 2
4. 参数化：形态容差、止损ATR倍数等
```

### 图表输出
```
1. K线买卖点图：使用 VNPY ChartWidget + 手动标注买卖信号
2. 资金回撤图：从 DailyResult 提取数据，用 matplotlib 绘制
3. 绩效对比图：多参数组合回测结果用 matplotlib 并列柱状图
```

### 点位逆向倒推（VNPY适配）
```
1. 回测图表中点击任意K线上的买卖标记
2. 系统自动定位到策略代码中该信号对应的 on_bar() 行号
3. 显示该笔交易完整上下文：
   - 触发时间、K线OHLC
   - 形态识别中间变量（左肩价/头部价/右肩价/颈线值）
   - 入场价/止损价/止盈价计算过程
4. 用户可在定位处直接修改代码，修改后重新回测对比
```

### 规则反向翻译（Code→NL）
```
从 VNPY 策略代码提取结构化规则：

入场条件：
- 头肩底形态确认（左肩低点 < 头部低点 < 右肩低点，且右肩 > 左肩）
- 收盘价突破颈线（突破幅度 ≥ 0.3%）

出场条件：
- 止损：价格回落至右肩最低价下方
- 止盈：价格到达入场价 + 2×(颈线 - 头部最低价)
- 移动止损：盈利超过1R后启动，回撤30%平仓

仓位管理：
- 固定风险 2% / 笔
- 仓位 = 账户净值 × 2% / (入场价 - 止损价)
```
