# Codex + 飞书 CLI 自动化技能手册

> **版本**：v1.0
> **更新日期**：2026-06-11
> **来源**：微信公众号「我姚学AI」—— 如何通过 Codex 对话接入飞书完整版
> **适用对象**：AI 分身技能库（Hermes / OpenClaw / 豆包 Agent）

---

## 一、核心理念

通过 Codex CLI 将飞书开放平台能力以**对话式**方式接入 AI 工作流，使 AI 不仅能"写代码"，更能直接操作飞书的文档、Base、日历、消息、任务等真实业务场景，实现从"回答者"到"执行者"的跨越。

**价值主张**：

> AI 不只是回答你，它开始替你完成任务。

## 二、环境准备

### 2.1 前置条件

| 条件项 | 要求 | 说明 |
|--------|------|------|
| Codex CLI | 已安装且可正常使用 | 作为对话式 AI 交互入口 |
| 飞书账号 | 企业版或团队版 | 需具备应用创建权限 |
| 飞书开放平台访问 | 浏览器可打开 `open.feishu.cn` | 用于创建和配置应用 |
| 网络环境 | 可访问飞书 API 端点 | `https://open.feishu.cn` |

### 2.2 操作系统兼容性

| 系统 | 状态 | 备注 |
|------|------|------|
| macOS | 完全支持 | 推荐 |
| Linux | 完全支持 | — |
| Windows | 支持（需 WSL 或 PowerShell） | 建议使用 WSL2 |

## 三、安装与配置（4 步 SOP）

### 第 1 步：安装飞书 CLI

**目标**：通过 Codex 对话式安装飞书命令行工具。

**操作方式**：直接在 Codex 对话中输入安装指令，让 Codex 自动执行。

**对话指令示例**：

```
帮我安装飞书 CLI 工具
```

**Codex 将自动执行**：

```bash
# Codex 实际执行（用户无需手动操作）
npm install -g @lark-base-open/feishu-cli
# 或 pip install lark-cli（视具体 CLI 工具而定）
```

> **预计耗时**：4～5 分钟

**验证安装**：

```bash
feishu --version
# 或
lark --help
```

**常见问题**：

| 问题 | 原因 | 解决方案 |
|------|------|----------|
| `command not found` | Node.js 未安装或 PATH 未配置 | 先安装 Node.js ≥ 16，确保 npm 全局 bin 在 PATH 中 |
| 安装超时 | 网络问题导致 npm 下载慢 | 切换国内镜像源：`npm config set registry https://registry.npmmirror.com` |
| 权限不足 | macOS/Linux 权限问题 | 使用 `sudo npm install -g` 或配置 npm 全局目录 |
| Windows 报错 | 部分 CLI 依赖 Unix 环境 | 在 WSL2 中执行 |

### 第 2 步：配置飞书应用

#### 2.2.1 初始化配置

在 Codex 中执行初始化，获取飞书开放平台配置链接：

**对话指令**：

```
帮我初始化飞书 CLI 配置，输出浏览器可访问的配置链接
```

**等价 CLI 命令**：

```bash
feishu config init
```

#### 2.2.2 创建飞书应用

1. 将 Codex 输出的配置链接复制到浏览器
2. 登录飞书开放平台（`open.feishu.cn`）
3. 按页面提示创建新应用，或绑定已有应用
4. **关键配置项**：
   - 应用名称：自定义（如 "Codex-AI助手"）
   - 应用描述：用于 AI 自动化工作流
   - 可用性状态：选择"所有员工"或指定范围

#### 2.2.3 获取并配置凭证

创建应用后，从飞书开放平台「应用凭证」页获取：

- **App ID**：应用唯一标识
- **App Secret**：应用密钥

在 Codex 中完成凭证配置：

```bash
# 设置 App ID
feishu config set app_id <你的App ID>

# 设置 App Secret
feishu config set app_secret <你的App Secret>
```

#### 2.2.4 权限配置（必读）

需要为应用开启以下**权限范围**，否则 API 调用会返回 403：

| 权限项 | scope | 用途 | 优先级 |
|--------|-------|------|--------|
| 日历读写 | `calendar:calendar` | 创建/查询/修改日历事件 | 🔴 必须 |
| 文档读写 | `docx:document` | 创建/编辑飞书文档 | 🔴 必须 |
| Base 读写 | `bitable:app` | 操作飞书多维表格 | 🔴 必须 |
| 消息发送 | `im:message` | 发送飞书消息 | 🟡 按需 |
| 通讯录读取 | `contact:contact` | 查询用户/部门信息 | 🟡 按需 |
| 知识库 | `wiki:wiki` | 操作飞书知识库 | 🟢 可选 |
| 会议纪要 | `vc:meeting` | 读取会议记录 | 🟢 可选 |
| 邮箱 | `mail:mail` | 发送/读取邮件 | 🟢 可选 |
| 审批 | `approval:approval` | 发起/查询审批 | 🟢 可选 |

> **最佳实践**：先开启最小必要权限，待验证通过后再逐步添加。避免一次性申请过多权限导致审批延迟。

---

### 第 3 步：用户授权

应用配置完成后，需完成 OAuth 用户授权以获取访问令牌。

**对话指令**：

```
帮我执行飞书用户授权，输出浏览器可访问的授权链接
```

**等价 CLI 命令**：

```bash
feishu auth login
```

**操作流程**：

1. Codex 输出授权链接
2. 浏览器打开链接
3. 在飞书授权页面点击「确认授权」
4. 授权成功后在 Codex 中验证：

```bash
feishu auth status
```

> **注意**：Access Token 有过期时间（通常 2 小时），Codex CLI 会自动刷新。如遇到 token 过期错误，重新执行授权即可。

---

### 第 4 步：验证接入

执行一个低风险操作验证链路通畅。

**对话指令**：

```
创建一个下周一早上 8 点的飞书日历事件
```

**等价 CLI 命令**：

```bash
feishu calendar create \
  --summary "Codex 接入测试" \
  --start-time "下周一 08:00" \
  --end-time "下周一 09:00"
```

**验证结果**：在飞书日历中查看是否已创建对应事件。如能看到，说明权限和链路基本通畅。

## 四、多场景自动化操作

### 4.1 飞书日历

```bash
# 创建日历事件
feishu calendar create \
  --summary "团队周会" \
  --start-time "2026-06-15 10:00" \
  --end-time "2026-06-15 11:00" \
  --description "本周工作复盘与下周计划"

# 查询指定日期的日程
feishu calendar list --date "2026-06-15"

# 删除日历事件
feishu calendar delete <event_id>
```

### 4.2 飞书文档

```bash
# 创建飞书文档
feishu doc create \
  --title "项目周报" \
  --folder_token "<文件夹token>"

# 追加内容到文档
feishu doc append \
  --doc_token "<文档token>" \
  --content "## 本周进展\n..."

# 读取文档内容
feishu doc read --doc_token "<文档token>"
```

### 4.3 飞书 Base（多维表格）

```bash
# 创建 Base
feishu base create --name "客户管理表"

# 添加数据行
feishu base record add \
  --app_token "<Base token>" \
  --table_id "<表ID>" \
  --fields '{"姓名":"张三","状态":"跟进中"}'

# 查询记录
feishu base record list \
  --app_token "<Base token>" \
  --table_id "<表ID>" \
  --filter "状态='跟进中'"
```

### 4.4 飞书消息

```bash
# 发送文本消息
feishu message send \
  --receive_id "<用户ID或群ID>" \
  --content "这是一条来自 Codex 的自动化消息"

# 发送富文本/卡片消息
feishu message send \
  --receive_id "<群ID>" \
  --msg_type "interactive" \
  --card '{"header":{"title":"每日提醒"},"elements":[{"tag":"div","text":"今日待办事项..."}]}'
```

### 4.5 飞书知识库

```bash
# 创建知识库页面
feishu wiki create \
  --space_id "<空间ID>" \
  --title "AI 自动化手册"
```

### 4.6 飞书会议/视频会议

```bash
# 创建会议
feishu vc create \
  --topic "项目评审会" \
  --start_time "2026-06-16 14:00" \
  --end_time "2026-06-16 15:00"
```

## 五、错误处理与调试

### 5.1 常见错误码

| 错误码 | 含义 | 解决方案 |
|--------|------|----------|
| `99991600` | Token 过期 | 执行 `feishu auth login` 重新授权 |
| `99991663` | 权限不足 | 在飞书开放平台添加对应权限 scope |
| `230001` | 参数校验失败 | 检查参数完整性，参考飞书 API 文档 |
| `99991400` | App ID/Secret 错误 | 核对飞书开放平台的凭证信息 |
| `500` | 飞书服务端错误 | 等待重试，检查飞书服务状态 |

### 5.2 调试技巧

```bash
# 开启调试模式查看详细请求/响应
feishu --debug calendar list --date "2026-06-15"

# 查看当前配置
feishu config show

# 查看 token 状态
feishu auth status

# 测试网络连通性
curl -I https://open.feishu.cn
```

## 六、最佳实践

### 6.1 安全实践

| 实践 | 说明 |
|------|------|
| **凭证隔离** | App Secret 不要硬编码在脚本中，使用环境变量或 CLI 配置文件 |
| **最小权限原则** | 仅开启业务所需的最小权限 scope |
| **定期轮换凭证** | 建议每 90 天轮换一次 App Secret |
| **审计日志** | 定期检查飞书开放平台的操作日志，关注异常调用 |
| **IP 白名单** | 在飞书开放平台为应用配置 IP 白名单，限制调用来源 |

### 6.2 运维实践

| 实践 | 说明 |
|------|------|
| **批量操作限流** | 飞书 API 有频率限制（通常 100次/秒），批量操作需添加 sleep 间隔 |
| **幂等性设计** | 创建类操作加入去重判断，避免重复创建 |
| **错误重试** | 网络抖动导致的失败使用指数退避重试（1s → 2s → 4s） |
| **干跑模式** | 执行批量操作前先用 `--dry-run` 确认影响范围 |

### 6.3 Codex 对话式最佳实践

1. **明确上下文**：在对话开头说明当前工作环境（项目名/飞书空间等）
2. **逐步确认**：高风险操作（如批量删除）让 Codex 先列出影响范围再确认执行
3. **利用记忆**：让 Codex 记住常用的 Base Token、文件夹 ID 等参数，避免重复输入
4. **组合指令**：一次对话完成多步骤串联（如"创建周报文档，然后发消息通知团队"）

## 七、企业级应用场景

| 场景 | 描述 | 涉及飞书能力 |
|------|------|-------------|
| **自动化日报/周报** | AI 自动汇总工作进展生成飞书文档 | 文档 + 消息 |
| **智能日程管理** | AI 自动协调团队成员空闲时间排会 | 日历 + 通讯录 |
| **客户数据管理** | AI 将微信/邮件客户信息自动录入飞书 Base | Base |
| **会议纪要自动化** | AI 读取会议录音生成纪要到知识库 | 会议 + 知识库 |
| **审批流程自动化** | AI 识别审批内容并自动提交/批转 | 审批 + 消息 |
| **知识库自动更新** | AI 定期整理项目文档推送到知识库 | 知识库 + 文档 |
