# 零积分任务执行技能 v1.0

> 核心原则：**先算账，再动手；能本地不联网，能批量不单调，能复用不重建。**

---

## 一、触发条件

以下关键词触发本技能：
- 省积分、零成本、低成本、性价比、成本控制
- 积分预算、省钱、别瞎调工具
- 成本优先、零积分把活干了

---

## 二、核心功能概览

1. **成本预算**：任务执行前声明预计积分消耗和最低成本路径。
2. **工具最小化**：减少不必要的工具调用，优先读取本地缓存/已有文件。
3. **批量合并**：把多个小操作合并成一次工具调用。
4. **零成本替代**：用本地脚本、已有技能、文件系统操作替代API调用。
5. **成本复盘**：任务结束后输出实际消耗 vs 预算，沉淀优化点。

---

## 三、执行流程

### Step 0: 任务接收 → 先问预算
- 用户下达任务后，先判断：**这件事值多少积分？**
- 如果任务简单/可本地完成 → 走零成本路径
- 如果任务复杂/必须多步 → 先做成本预算，经用户确认或默认采用最低成本路径

### Step 1: 信息复用 → 先看记忆和本地文件
- 读取 `~/.workbuddy/MEMORY.md` 和 workspace memory
- 检查当前目录是否已有相关文件/脚本/配置
- 检查是否已有 skill 可以复用

### Step 2: 路径选择 → 性价比排序
| 路径 | 成本 | 优先级 |
|------|------|--------|
| 纯本地文件操作 | 0 | ⭐ 首选 |
| 调用已安装的本地 skill | 0-低 | ⭐⭐ 次选 |
| 单次 Bash/脚本执行 | 0-低 | ⭐⭐⭐ |
| 多次文件读取/编辑 | 中 | 尽量批量合并 |
| 外部API/联网搜索 | 高 | 必须时再用 |
| 生成大量中间文件 | 中-高 | 精简输出 |

### Step 3: 执行中 → 三不原则
1. **不重复读取**：同一文件只读一次，结果缓存到 working memory
2. **不空转工具**：没有明确目的不调用工具
3. **不小步快跑**：能用一次 Edit 完成的不用 Read+Edit 分两次

### Step 4: 执行后 → 成本复盘
- 输出实际消耗估算（按工具调用次数×大致成本）
- 对比预算，标注超支/节省原因
- 把省积分经验沉淀回本 skill 或 workspace memory

## 四、零成本/低成本具体技巧

### 4.1 文件操作
- 用 `Read` 读一次长文件，不要用 Bash `cat/head/tail`
- 需要修改时尽量用 `Edit`，避免重写整个文件
- 批量读取多个文件时用并行 tool call

### 4.2 代码执行
- 优先复用项目已有 Python/Node 脚本
- 新建脚本尽量小，执行完把产物复制到工作区，中间日志扔 temp
- 避免反复调用同一脚本做不同参数

### 4.3 搜索与调研
- 先用本地文件/Grep/Glob，再考虑 WebSearch
- WebSearch 尽量用 `query_keyword_groups` 一次性覆盖多角度
- 能用 WebFetch 直接抓的不要用浏览器自动化

### 4.4 多智能体协作
- 不把完整上下文塞给 subagent，只给最小必要信息
- 优先用 Read 自己看，不轻易派 Explore agent
- agent 结果要缓存，避免重复派遣

### 4.5 技能/模板/MCP
- 优先加载已安装 skill，不要新建
- 新建 skill 前确认没有可复用的同类 skill
- MCP 调用前确认 connector 已连接，避免无效调用

```

- 下次优化：...
```

## 六、使用示例

### 示例1：用户让"整理一下这个目录"
- ❌ 高成本：递归列出所有文件 → 复制 → 分类 → 写报告
- ✅ 低成本：Glob 一次拿到文件列表 → Bash 按扩展名统计 → 直接给出建议

### 示例2：用户让"修复这个bug"
- ❌ 高成本：先 Explore agent 全仓库扫描 → 再 Read 十几个文件 → 再改
- ✅ 低成本：用户给日志/错误信息 → Grep 定位 → Read 关键2-3个文件 → Edit 修复

### 示例3：用户让"写个新功能"
- ❌ 高成本：直接开写，写到一半反复验证
- ✅ 低成本：先问清楚需求/范围 → 复用现有代码结构 → 先写最小可用版本 → 再迭代

## 八、错误处理

| 错误场景 | 处理 |
|----------|------|
| 用户要求大量工具调用 | 先输出预算和替代方案，让用户确认 |
| 发现已有skill可复用 | 立即停止新建，改用现有skill |
| 任务执行中超支 | 暂停并报告，给出低成本收尾方案 |
| 无法零成本完成 | 明确说明最低成本路径和必要性 |
