# Skill生态系统管家 V1.0

> 定位：手动触发的技能矩阵治理工具，不自动执行，由用户显式调用

## 触发条件

以下关键词或场景触发本技能：
- "技能矩阵"、"技能看板"、"技能治理"
- "skill steward"、"skill audit"、"技能健康度"
- "技能诊断"、"联动链路"、"技能依赖"
- 用户要求查看全技能状态概览

## 核心功能

### 一、矩阵健康度全景看板

输出一张完整的技能矩阵状态看板：

| 技能名称 | 版本 | 健康度 | 状态 | 更新日期 | 联动数 | 层级 |
|---------|------|--------|------|---------|--------|------|
| ... | ... | 🟢/🟡/🟠/🔴 | 存活/缺失 | YYYY-MM-DD | N | 数据/信号/分析/决策/沉淀/管理 |

健康度评分规则（4维度×25分=100分制）：
- **时效性(25分)**：7天内更新=25, 14天=20, 21天=15, 30天=10, 45天=5, >60天=0
- **完整性(25分)**：YAML frontmatter完整=25, 缺1字段=20, 缺2=15, 缺3=10, 无frontmatter=0
- **联动度(25分)**：3+双向联动=25, 2=20, 1=15, 单向引用=10, 无联动=5, 孤岛=0
- **内容质量(25分)**：结构清晰+步骤完整+参数明确=25, 缺一=20, 缺二=15, 粗略=10, 残缺=0

状态等级：
- 🟢优秀(85-100)：健康良好，无需干预
- 🟡良好(70-84)：可正常使用，注意时效
- 🟠关注(55-69)：需关注，建议近期迭代
- 🔴危险(<55)：需紧急修复或重建

### 二、老化预警与降级建议

预警机制：
- **时效预警**：>30天未更新 → 黄色预警；>60天 → 红色预警
- **健康度衰减**：每次审计间无更新时，时效维度按自然天数衰减（每7天扣5分）
- **降级建议机制**：
  - 连续3次🟠 → 建议降级（降低层级优先级）
  - 连续5次🟡 → 建议合并（与相关技能合并）
  - 60天无引用 → 建议归档（移入archived目录）

### 三、联动链路诊断与修复

诊断5维度协同健康：
1. **双向引用**：技能A引用B时，B是否也引用A？（缺失=单向引用Bug）
2. **参数标准化**：联动接口的参数名/格式是否一致？
3. **数据流闭环**：从数据→信号→分析→决策→沉淀，是否有断裂？
4. **版本兼容**：联动技能版本号是否匹配？
5. **功能冗余**：是否有两个技能覆盖相同场景？

修复规则：
- 发现单向引用 → 自动补写被引用技能的联动章节
- 参数不一致 → 统一为标准命名（market, timeframe, position_pct）
- 数据流断裂 → 标注断点，建议补建桥接技能
- 版本不兼容 → 标注兼容最低版本要求
- 功能冗余 → 建议合并或明确分工边界

### 四、版本升级决策矩阵

| 触发条件 | 升级类型 | 优先级 |
|---------|---------|--------|
| 连续2次🟠 | 紧急迭代 | P0 |
| 新场景覆盖需求 | 功能扩展 | P1 |
| 30天时效衰减 | 维护更新 | P2 |
| 联动链路断裂 | 修复补丁 | P1 |
| 用户显式请求 | 按需迭代 | P1 |

## 执行流程

> **V1.1 升级**：注入 V2.3 成本控制感知模式，默认 `cost_mode=strict`，工具调用预算 ≤4 次（单场景标准动作链）。
> 详细说明见「附录：V2.3 成本控制感知矩阵」。

### Step 1：扫描存活技能
```
ls ~/.workbuddy/skills/ → 列出所有技能目录
对每个技能：读取SKILL.md → 解析YAML frontmatter → 提取版本/更新日期/联动列表
```

### Step 2：计算健康度评分
按4维度×25分规则计算每个技能的健康度，输出看板表格

### Step 3：诊断联动链路
对每个有联动的技能，检查5维度协同健康：
- 双向引用完整性
- 参数标准化一致性
- 数据流闭环完整性
- 版本兼容性
- 功能冗余检测

### Step 4：生成治理建议
基于健康度评分和联动诊断结果：
- 🔴技能：紧急修复/重建建议
- 🟠技能：近期迭代建议
- 🟡技能：时效更新建议
- 🟢技能：维持现状

### Step 5：输出完整看板
生成Markdown格式的完整看板，包含：
- 矩阵健康度全景表
- 联动链路诊断结果
- 治理建议清单
- 依赖拓扑图
- 下次审计建议时间

## 附录：V2.3 成本控制感知矩阵（V1.1+ 必填）

### 三档 cost_mode

| cost_mode | 工具调用预算 | 适用场景 | 输出形态 |
|-----------|--------------|----------|----------|
| **strict（默认）** | ≤4 次 | 单场景看板/单维度诊断 | 抽样摘要 + 重点提示 |
| **normal** | ≤10 次 | 多维度扫描 + 治理建议 | 全量摘要 + 建议清单 |
| **full** | ≤25 次 | 大规模初始化/全矩阵深度审计 | 完整报告 + 健康度重算 |

### 禁止动作清单（任何模式）

- ❌ 重复 ls/cat 同一目录
- ❌ 每次都重新 Read 完整 SKILL.md（仅读 frontmatter + 联动表）
- ❌ 无目的 WebSearch / mimo-bridge / conversation_search
- ❌ 全量审计所有 32+ 技能（必须抽样，默认 30%）
- ❌ 单步小步快跑（连发工具调用而非批量聚合）
- ❌ 写报告时手算健康度（用四维公式自动算）

### 零积分动作优先（P0-P3 降级链）

- P0：本地缓存 / 复用上次结果 / 复用历史 patrol 报告
- P1：本地 stat/grep 替代 WebSearch
- P2：MiMO 远程推理（仅当 P0/P1 不可用时）
- P3：HY3 / WorkBuddy / 其他高成本路径（最后考虑）

### 联动扩展

- `zero-cost-task-execution V1.0` → 共享 cost_mode 定义与 P0-P3 优先级
- `zero-workday-skill-maintainer V1.1` → 零工作日联动：审计建议回流单动作执行
- `auto-skill-generator V2.3` → 自动调度 + 手动治理双闭环
- `skill-template-generator V1.1` → 新技能 frontmatter 标准化

### 切换话术

- "走 strict 模式看个摘要就行"
- "切 full 模式跑全量深度审计"
- "零积分治理：先 local scan → 仅识别 1 个最高价值动作"
