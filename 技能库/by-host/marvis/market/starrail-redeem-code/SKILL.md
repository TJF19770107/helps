# 崩坏星穹铁道兑换码一键领取

自动爬取最新兑换码 → 通过模拟器逐个兑换 → 文字返回结果。用户全程在 Marvis 对话中交互，**零模拟器交互**（所有交互都是文字对话，不需要用户操作模拟器）。

## 整体流程

```
用户触发
  │
  ├─ 1. 爬取兑换码（Python脚本，爬B站Wiki + 游民星空）
  │
  ├─ 2. 展示码列表 + 提示耗时约20~30分钟，**等待用户确认**
  │     └─ 用户回复「继续」→ 进入下一步
  │
  ├─ 3. 通过 androws MCP 启动模拟器中的星穹铁道
  │
  ├─ 4. 按固化路径进入兑换码界面
  │     │
  │     └─ ⚠️ 任何环节遇到异常（登录/闪退等）→ 暂停 + 文字提示用户
  │          └─ 用户回复「继续」→ 从暂停点恢复
  │
  ├─ 5. 全量逐个兑换（不过滤，全部尝试）
  │
  ├─ 6. 收集每个码的结果
  │
  └─ 7. 在对话中输出汇总结果
```

## 第1步：爬取兑换码

运行爬虫脚本获取最新兑换码列表：

```bash
python {SKILL_DIR}/scripts/crawl_starrail_codes.py
```

脚本输出 JSON 到 stdout，格式：

```json
{
  "total": 5,
  "long_term_count": 4,
  "preview_count": 1,
  "codes": [
    {"code": "SR8888", "type": "long_term", "reward": "星琼×50..."},
    {"code": "ABCD1234EFGH", "type": "preview", "reward": "星琼×100", "expire_at": "2026-05-01T23:59:59"}
  ]
}
```

**依赖**：需要 `requests` 和 `beautifulsoup4`。如果报 `ModuleNotFoundError`，先执行 `pip install -r {SKILL_DIR}/scripts/requirements.txt`。

**爬取失败处理**：如果脚本报错或返回 0 个码，告知用户"爬虫暂时无法访问数据源，请稍后重试"，不要编造兑换码。

### 爬取后展示与确认

爬到码后，先在对话中**逐条展示所有兑换码**，然后**暂停等待用户确认**是否继续自动领取：

```
📋 已获取 {total} 个兑换码（长期码 {long_term_count} 个 + 前瞻码 {preview_count} 个）：

| # | 兑换码 | 类型 | 奖励 |
|---|--------|------|------|
| 1 | SR8888 | 长期码 | 星琼×50... |
| 2 | ABCD1234EFGH | 前瞻码 | 星琼×100 |
| ... | ... | ... | ... |

⏱️ 自动领取预计耗时约 **20~30 分钟**（含游戏启动/资源加载/逐个兑换），期间需确保模拟器保持前台运行。
是否继续自动领取？回复「继续」即可开始。
```

> 🔴 **必须逐条列出所有兑换码**，不能只显示数量！遍历 JSON 中 `codes` 数组的每个元素，将 `code`、`type`（long_term→长期码，preview→前瞻码）、`reward` 填入表格。如有 `expire_at` 且未过期，在奖励列末尾标注「⏰ {expire_at} 前有效」。

> 🔴🔴 **【强制确认门禁】展示码列表后，必须暂停并等待用户明确回复「继续」才能进入 §2 模拟器兑换阶段！禁止跳过此确认直接启动游戏！**
>
> 用户可能的回复：「继续」「开始」「领取」「OK」「好」等表示同意的意图 → 进入第2步
> 用户可能拒绝或未回复 → 保持暂停状态，不执行任何操作

## 第2步：模拟器兑换

### 坐标定位强制规则

> 🔴🔴 **【坐标唯一合法来源】崩坏星穹铁道是游戏引擎渲染（Unity），所有 UI 元素的点击坐标必须且只能来自 `gui_grounder` 返回值！**
>
> **`gui_grounder` 的作用**：输入截图 + 目标元素描述 → **返回该元素的坐标 (x, y)**。它是一个纯粹的定位工具，不执行任何点击/输入操作。
>
> **每步操作的标准链路**：
> 1. `capture_screen` 截取当前画面，记录返回的 `image_size`
> 2. 调用 `gui_grounder`(截图 + 元素描述)，获取坐标
> 3. **直接用返回的坐标执行操作**（focus_at / android_tap），传入 `source="screenshot"` + `image_size`
>
> ⚠️ **gui_grounder 返回坐标后立即使用，禁止在中间插入多余的 capture_screen 或对同一目标重复调用 gui_grounder！**
> 如果需要定位**不同元素**，才需要重新调 gui_grounder。
>
> **正确示例**：`focus_at(x=gui_grounder返回的x, y=gui_grounder返回的y, source="screenshot", image_size=[1280,719], observe_mode="capture_screen")`
>
> **禁止**：
> - 自行猜测坐标、硬编码坐标、凭肉眼估算截图中的像素位置
> - 用 `android_tap` 替代 `focus_at`（focus_at 内置自动截图观察，减少工具调用次数）
> - 传 `source` 或 `image_size` 缺失
> - 混用 dump_ui 的 `physical` 坐标和截图方案的坐标

> 🔴🔴 **【主界面门禁】必须通过截图确认已到达游戏主界面（3D场景 + 左上角手机图标），才能进入 §2.2 兑换码入口路径。未确认到达主界面前，禁止执行任何点击操作！**

> 🔴🔴 **【反等待惯性规则】每次截图后，禁止只做"是不是主界面"的二元判断。必须识别当前页面属于哪种类型，并做出对应操作。"不是主界面"≠"还在加载"，很可能是需要用户交互才能继续的页面。**

### 2.2 兑换码入口固化路径

> 🔴 每步操作的完整流程：`capture_screen` 截图 → `gui_grounder`(传入截图+元素描述) 获取坐标 → **用 `focus_at` 执行点击（内置自动截图观察，无需手动 capture_screen）**。
>
> ⚠️ **禁止在 gui_grounder 返回坐标后重新截图或重新调用 gui_grounder！** 坐标已到手就直接用 focus_at。如果点击无响应，才需要重新截图+重新定位。

| 步骤 | 操作描述 | 工具 | 说明 |
|------|---------|------|------|
| 1 | 点击左上角「手机」图标 | focus_at | 打开手机菜单，自动截图确认 |
| 2 | 点击「…」更多按钮 | focus_at | 展开更多选项，自动截图确认 |
| 3 | 点击「兑换码」选项 | focus_at | 进入兑换码输入界面，自动截图确认 |

> ⚠️ **禁止在操作间调用 `wait`！** `focus_at` 本身已内置等待机制（focus_delay_ms），不需要额外 wait。唯一允许使用 `wait` 的场景是游戏启动后等待加载完成。

### 2.3 逐个兑换流程

> 🔴 对每个兑换码，按以下流程执行。**所有点击目标（输入框、清除按钮、确认按钮等）均需通过 `gui_grounder` 从截图中定位获取坐标。**
>
> ⚠️ **gui_grounder 返回坐标后直接用于操作（统一用 `focus_at`），禁止用 `android_tap`！focus_at 内置自动截图观察，无需手动 capture_screen。**

````
兑换码输入界面（首次进入）
  │
  ├─ 【一次性定位】capture_screen → gui_grounder 定位可见控件坐标：
  │     ├─ 输入框坐标 → 记录为 (input_x, input_y)
  │     └─ 「确认」按钮坐标 → 记录为 (confirm_x, confirm_y)
  │     （⚠️ 此时清除按钮不可见，不定位）
  │
  │  ⚠️ 后续所有兑换码直接复用这些坐标！不需要每次重新定位。
  │     只有界面发生明显变化才需要重新定位。
  │
  ├─ 1. focus_at(input_x, input_y) 点击输入框获取焦点
  │
  ├─ 2. 如有残留文字 → gui_grounder 定位清除按钮(✕) → 记录为 (clear_x, clear_y)
  │     → focus_at(clear_x, clear_y) 点击清除（⚠️ 清除按钮只在有文字时出现，首次无文字则跳过此步）
  │     → 后续清除操作直接复用 (clear_x, clear_y)，无需重新定位
  │
  ├─ 3. input_text 向已聚焦的输入框输入当前兑换码（区分大小写！）
  │     ⚠️ input_text 不带坐标，仅通过 IME commitText 向当前焦点控件发送文字，
  │        必须先通过 focus_at 确保输入框已获得焦点才能使用
  │
  ├─ 4. focus_at(confirm_x, confirm_y) 点击提交兑换（自动截图查看结果）
  │     │
  │     ├─ 🟢 成功弹窗 → 记录 ✅ 成功 + 奖励内容
  │     │    └─ focus_at 点击弹窗中的「确认」→ 回到手机主页 → 需重新走入口路径
  │     │       （⚠️ 回到主页后之前的坐标失效，重新进入兑换码界面需重新定位！）
  │     │
  │     └─ 🔴 红色横幅「无效的兑换码」→ 记录 ❌ 无效
  │          └─ focus_at(clear_x, clear_y) 点击清空 → focus_at(input_x, input_y) 重新激活 → input_text 输入下一个码
  │
  └─ 6. 重复步骤 1-5（复用已记录坐标），直到所有码处理完毕
````

**关键行为差异：**

| 结果 | 表现 | 界面行为 |
|------|------|---------|
| 🔴 失败（无效/过期/已使用） | 红色横幅「无效的兑换码」（统一提示） | 界面不关闭，可直接清空继续 |
| 🟢 成功 | 弹出成功弹窗，显示奖励 | 点确认后回到「手机」主页，需重走入口 |

> ⚠️ 失败时无法区分是"无效"、"过期"还是"已使用"，统一显示「无效的兑换码」。

### 2.4 弹窗关闭策略

> 🔴 优先用 tap_back（系统返回键）关闭弹窗！tap_back 不需要坐标。

````
关闭弹窗：
  ├─ 1.【首选】tap_back
  ├─ 2.【备选】gui_grounder 定位「确认」按钮 → focus_at 点击
  └─ 3.【最后】focus_at 点击弹窗外暗色遮罩
```

```
所有码处理完毕
  │
  ├─ tap_back 返回手机菜单
  ├─ tap_back 返回主界面

|--------|------|------|

### 中途停止

如果用户中途喊停（"停"、"暂停"、"先别兑了"等），立即停止兑换操作，输出已完成部分的结果，未处理的码标记为 ⏸️ 未兑换。

### 暂停恢复

遇到异常暂停后，Skill 应记住当前兑换进度（已完成的码和对应结果），用户回复继续时：

1. 重新 `capture_screen` 感知当前位置
2. 根据识别结果决定从哪里继续：
   - 在主界面 → 从头走路径（手机图标 → … → 兑换码）
   - 在路径某一步（如手机菜单界面）→ 从该步继续
   - 仍无法识别 → 再次触发暂停
3. 从**下一个未处理的码**开始兑换，不需要重头来

### 重试逻辑

```
在当前页面尝试寻找目标元素
  │
  ├─ 找到 → 执行操作，计数清零
  │
  └─ 找不到 → 失败计数+1
        │
        ├─ 计数 < 3 → 等待2秒 → 重新截图 → 再次尝试
        │
        └─ 计数 = 3 → 触发暂停，等待用户处理
```

> 3次重试都是在同一个画面上找目标元素，每次重试前会重新 capture_screen。

### 走错路径的处理

```
点击后进入非预期页面
  │
  ├─→ 【能识别当前页面】
  │       │
  │       ▼
  │   知道走错了 → tap_back 尝试返回
  │       │
  │       ├─ 返回成功 → 重新找目标元素
  │       └─ 返回失败3次 → 触发暂停
  │
  └─→ 【无法识别当前页面】
          │
          ▼
      在当前页面找下一步目标 → 找不到
          │
          ▼
      重试3次都找不到 → 触发暂停
```

## 异常处理

> 🔴 核心原则：所有需要用户介入的场景，都通过 **Marvis 文字对话** 提示用户，**暂停兑换等待用户回复后继续**。

| 场景 | 处理方式 | 用户交互 |
|------|---------|---------|
| 登录弹窗 | 暂停兑换，提示"检测到需要登录，请在模拟器中登录" | 用户登录后回复「继续」恢复 |
| 资源下载/更新（带百分比进度条） | **立即暂停**，禁止使用 wait！提示用户"检测到游戏正在下载/更新资源，请下载完成后通知我继续" | 用户下载完成后回复「继续」恢复 |
| 服务器维护 | 告知用户"服务器维护中，建议稍后再试"，任务终止 | 用户可稍后重新触发 |
| 连续3次找不到目标元素 | 暂停，提示"界面状态异常，请检查模拟器当前画面" | 用户处理后回复「继续」恢复 |
| 游戏闪退/不在前台 | 尝试重新启动，如再次失败则暂停提示用户 | 用户处理后回复「继续」恢复 |

> 用户回复的关键词识别：「继续」「恢复」「好了」「登录了」「OK」等表示已处理完毕、可以继续的意图。

## 注意事项

- 🔴 **全量兑换**：不做"是否已兑换过"的过滤，所有爬到的码全部尝试。已兑换过的码会返回"无效"，不影响流程。
- 🔴 **禁止 dump_ui**：游戏引擎渲染，dump_ui 无法获取游戏内 UI，统一使用 `capture_screen` + `gui_grounder` 方案。
- 🔴🔴 **坐标必须来自 gui_grounder**：所有点击操作的坐标必须且只能通过 `gui_grounder` 从截图中识别获取，禁止自行猜测或硬编码坐标。
- 🔴 **弹窗优先 tap_back**：游戏内 X 按钮点击区域小，tap_back 更可靠。
- 🔴 **兑换码区分大小写**：必须与原始码完全一致。
- 🔴🔴 **操作范围红线**：整个兑换码任务的完整流程是：进入游戏 → 打开手机菜单 → 点击「…」更多 → 点击「兑换码」 → 逐个输入兑换码 → 确认兑换结果 → 输出结论 → 任务结束。
  - 🚫 **兑换完毕后禁止再去探索游戏内其他功能/菜单**
  - 🚫 **禁止点击与兑换码无关的任何游戏内按钮**（如抽卡、商城、活动等）
