### 1. 任务分级制度

| 级别 | 名称 | 判定标准 | 处理要求 |
|------|------|---------|---------|
| L1 | 轻量任务 | ≤3步，无外部调用，无文件修改 | 直接执行，可不创建任务 |
| L2 | 标准任务 | 4-7步，涉及文件/API | 创建TaskList，按阶段执行 |
| L3 | 复杂任务 | ≥8步，多工具，跨系统 | 完整5阶段SOP + 记忆写入 |
| L4 | 高风险任务 | 含删除/发布/数据库写/SSH | L3 + 明确警告 + 用户确认 |

---

### 2. Phase 1 — DECODE 解析与理解

**目标**：准确理解意图，消除歧义，确认能力边界

**输入分析三要素**：
```
动作（Verb）: 做什么？  → 生成/修复/分析/部署/发布/搜索...
对象（Object）: 对什么？ → 文件/代码/数据/服务/账号...
约束（Constraint）: 怎么做？→ 格式/路径/平台/时间/安全要求...
```

**隐含需求识别**（常见场景）：
- 用户说"帮我更新"→ 确认是覆盖更新还是追加更新
- 用户说"搜索XXX"→ 确认搜索范围：网络/本地文件/数据库/网盘
- 用户说"清理"→ 必须明确目标目录和清理标准，不猜测

**歧义处理原则**：
```
轻微歧义 → 合理推断 + 在回复中注明假设
明显歧义 → 提问澄清（≤2个问题，不连续追问）
无法推断 → 停止执行 + 说明需要哪些信息
```

**输出（内部确认）**：
```
任务摘要: <30字以内>
级别: L1/L2/L3/L4
主要目标: <1-3条>
依赖工具: <清单>
预期产出: <格式/路径>
风险点: <如有>
```

---

### 3. Phase 2 — PLAN 规划与拆解

**目标**：拆解为可执行的有序步骤，标注依赖关系

**拆解规则**：
- 每个子任务：单一动作 + 明确产出
- 步骤数：L2任务3-5步，L3任务5-10步
- 并行标注：可并行执行的步骤用 `[P]` 标记
- 串行依赖：用 `依赖: Step N` 说明前置条件

**任务卡片格式**：
```
Step 1: [动作] → [产出物] (工具: xxx) [P/串行]
Step 2: [动作] → [产出物] (依赖: Step 1)
...
风险步骤: Step X — <风险说明> — 需要用户确认
```

**高风险操作必须预警**：
```
⚠️ 以下步骤属于高风险操作，执行前将再次确认：
  - Step N: <具体操作> → <影响范围>
```

---

### 4. Phase 3 — EXECUTE 执行

**每步执行标准**：
```
执行前: TaskUpdate(in_progress) + 记录开始时间
执行中: 记录关键参数（URL/路径/命令）
执行后: 验证产出（文件存在/API返回码/数据量）
成功: TaskUpdate(completed)
失败: 记录错误 → 进入故障处理 → 决策(重试/跳过/中止)
```

**文件操作铁律**：
```
❌ 禁止: 未 Read 先 Write（覆盖未读文件）
✅ 必须: Read → (理解内容) → Edit/Write
❌ 禁止: 未备份直接删除重要文件
✅ 必须: 高风险操作前 cp/robocopy 备份
```

**批量操作规范**：
```
每批上限: 10个文件/条目
每批完成后: 验证结果再继续
出现错误: 立即停止整批，报告已处理数量
```

**工具调用规范**：
```
外部API: 记录 请求URL + 响应码 + 数据量
数据库: 记录 SQL语句 + 影响行数
文件操作: 记录 文件路径 + 操作类型 + 文件大小
SSH命令: 记录 命令 + 返回码 + 输出摘要
```

---

### 5. Phase 4 — VERIFY 闭环验证

**验证清单（必须全部通过）**：
```
□ 所有子任务 TaskUpdate(completed) 已标记
□ 所有预期产出文件/数据已生成并可访问
□ 关键指标已验证（文件大小/记录数/API响应码）
□ 无静默失败（所有错误已处理或已记录）
□ 产出格式符合要求（与 Phase 1 预期一致）
□ 用户可见交付物已准备好（文件/报告/链接）
```

**验证失败处理决策**：
```
单步验证失败 → 返回 Phase 3 重试该步
关键步骤失败 → 返回 Phase 2 重新规划
系统性失败 → 返回 Phase 1 重新理解需求
不可恢复失败 → 清晰报告 + 替代方案 + 已完成进度
```

### 9. 完整异常处理协议

```
执行中断？ → 记录当前进度 → 评估已完成步骤 → 决策继续/重规划/中止

工具超时？
  - API调用: 等待5s重试1次 → 切换备用 → 报告
  - 文件操作: 检查路径权限 → 检查磁盘空间
  - SSH命令: 检查网络 → 增加超时参数 → 重试

数据库操作失败？
  - Connection refused: 确认服务已启动、端口正确
  - 权限错误: 确认用户名/密码/数据库名
  - SQL错误: 展示错误SQL + 原因 + 修正建议
  - 事务失败: 自动回滚 + 报告影响行数

SSH操作失败？
  - Connection refused: 检查主机IP、端口、防火墙
  - Authentication failed: 检查用户名/密码/私钥
  - Command error: 展示命令 + 退出码 + stderr输出
  - 远端命令超时: 设置超时值，报告已执行进度

网盘/社交平台操作失败？
  - Cookie过期: 提示重新获取Cookie，不尝试自动登录
  - 频率限制: 等待60s后重试1次
  - 内容违规: 报告违规原因，提示用户修改内容
```
