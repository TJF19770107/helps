> 触发：用户核心质询 + cc-switch 404 链路故障反复返工专项
> 结论先行：**不是单点失误，而是"迭代生产者缺失 + 多Agent链路断层 + 规则自相矛盾"三重漏洞叠加。**

## 一、核心质问逐条拆解

### Q1. 是否存在上下文断片、长记忆丢失？
**诱因判定：部分成立（断片型）**
- `memory/` 工作日志、`~/.workbuddy/MEMORY.md` 机制存在，但**跨会话的"技能沉淀"不在这个通道里**——
  它依赖 `state/issues_tracker.json` + `skill_knowledge/`，而该通道自 2026-07-13 起停更。
- 证据：`issues_tracker.json.archived` 最后一次写入是 `skill_20260713_001050_*`，
  7-18/7-19 的 cc-switch 多次修复**完全没进入 tracker**。
- 结论：不是记忆丢了，是"修完问题→写记忆"的**最后一跳没接上**。

### Q2. 是否缺少「问题解决后自动沉淀」的触发检测技能？
**诱因判定：成立（技能缺失型·主因）**
- 龙虾五步法 V2.6 的 Step5「迭代沉淀」只是一段**描述性文字**，没有任何可执行触发器。
- 已有的固化消费端 `lobster_skill_solidify.py`（每日00:10）**一直在跑**，但它是"空转"——
  因为 `resolved` 数组长期为空，无料可吃。
- **根因定位**：系统有"消费者"无"生产者"。`record_iteration.py`（本次新建）正是补齐的生产者。

### Q3. 是否软连接联动规则配置缺失？
**诱因判定：成立（链路断层型）**
- 五步法、全域模板、技能库三者**没有程序化软连接**。索引靠人工偶尔追加，
  导致"同一条规则"在三处可能不一致（本次就发现 V2.6 写"不使用15721代理/直连MiMO"，
  与实际生效的"15721→4567→MiMO"**直接矛盾**）。
- 本次修复：新增 `lobster_auto_iterate` 定义软连接绑定规则（索引追加而非复制，防漂移）。

### Q4. 迭代逻辑本身是否错误（仅临时修复未固化）？
**诱因判定：成立（逻辑错误型·V1.0-V1.2 方向做反）**
- cc-switch 修复在 V1.0-V1.2 阶段**反复推翻自己**：先删 /v1 后缀，实测 404 又加回，
  来回拉扯 5+ 轮。本质是**没固化成可复用技能**，每次从零试错。
- 本次 V1.3 已明确：`baseURL` 必须带 `/v1`（cc-switch 拼 `baseURL+"/responses"`）。
  此结论已写入 `cc_switch_4567_autofix` 技能包，不再依赖人脑记忆。

### Q5. 多Agent调度链路断层？
**诱因判定：成立（调度断层型）**
- Codex / Claude Code / Hermes 处理完问题后，**没有回传案例至五步法库与全域模板库的通道**。
- 各 Agent 各自维护 AGENTS.md/SOUL.md，版本不一致，旧规则可能仍在生效。
- 本次修复：Step5 多Agent同步规则，要求统一引用最新技能版本。

### Q6. 是否未识别重复故障判定规则？
**诱因判定：成立（重复返工型·最直接代价）**
- **无相似度检索前置**：任务启动不检索历史案例，直接上手排查。
- 代价量化：cc-switch 404 在 7-18~7-19 被处理 ≥5 次，每次都"重新发现"同一根因
  （baseURL 缺 /v1），且本次 `precheck.py` 还揪出**第3个漏网 provider** `d240abd2-...`
  同样缺 /v1 —— 证明人工修复永远只修"看见的那一个"。

## 二、造成循环的底层漏洞（定位）

```
        ┌─────────────────────────────────────────┐
        │  故障修复完成（如cc-switch 404）          │
        └───────────────────┬─────────────────────┘
                            │  ❌ 此处断链：无人调用 record_iteration
                            ▼
        ┌─────────────────────────────────────────┐
        │  state/issues_tracker.json.resolved 长期空 │  ← 生产者缺失
        └───────────────────┬─────────────────────┘
                            │  (固化引擎每日00:10空转)
                            ▼
        ┌─────────────────────────────────────────┐
        │  技能库/五步法/模板 不更新                  │  ← 消费者无料
        └───────────────────┬─────────────────────┘
                            │
                            ▼
        ┌─────────────────────────────────────────┐
        │  下次同类故障：从头排查、推翻旧方案         │  ← 重复返工循环
        └─────────────────────────────────────────┘
```

**三大底层漏洞：**
1. **生产者缺失**（主漏洞）：修复完成 → 无动作写入 tracker。
2. **规则自相矛盾**：V2.6 文档说"不用15721代理"，实际链路强依赖15721。
3. **无重复拦截**：任务启动不检索历史，每次从零。
